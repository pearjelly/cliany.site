# v0.16.372 发布草案

**目标版本：** `0.16.372`
**提交范围：** `v0.16.371..HEAD`（以最终 master 为准）
**状态：** 候选；最终 master 门禁和上海时间线上发布配额通过后才能推送 tag。

## 用户价值与边界

- 结果行缺失链接或摘要时，结构化提取保留空值，不再从整行或相邻结果借用数据。现有质量门禁会报告缺失字段和行号，避免错误结果被当作成功返回。
- 本版不包含 draft PR #47 的 AXTree 选择器门禁与模型可靠性实验。该分支最近的严格固定 30 次样本为 22/30，低于 27/30 控制目标；Issue #33 所需的独立首次用户验证也未完成。

## 证据与兼容性

- PR #48 的真实 Chromium 回归先在主线复现第二行 URL 错误借用第一行链接，再在修复后通过；完整离线、具身、Python 3.11-3.13、Windows、Ruff 和 Mypy 检查通过。
- 先前依赖缺失字段自动回退的调用方现在会收到空字段和 `partial` 质量诊断；这是防止错误数据传播的有意改变。已有 `fields_map` 格式和非缺失字段的读取保持不变。
- 案例库状态不变；修复局部提取错误不等于第三方网站在线流程或生成工作流通过验收。

## 案例库映射

`cases/manifest.json` 和 `cases/README.md` 本版不改变案例状态：四个只读案例保持 active，PyPI、npm、crates.io 搜索保持 candidate，`search-extraction-gap` 保持 known-gap。候选站点只有在真实 `doctor --llm-live --require-capability generate_adapters --json` 通过后才能探索；若返回 `llm_live_preflight_not_ready`，停止而不伪造结果。

## 风险与兼容性

已有 adapter 若依赖缺失字段自动借用整行或邻近链接，升级后会收到空字段及质量诊断，需要改成针对实际子节点的字段映射。对于完整结果行，读取逻辑不变。本次测试仅证明局部字段读取和回放门禁行为，不证明第三方网站当前可达。

## 发版前验证

1. 在最终 master SHA 运行完整离线测试、具身 Chromium 测试、Ruff、Mypy、`uv lock --check`、官网脚本和案例严格校验；构建 wheel/sdist 并运行 Twine 检查。
2. 确认最终 master 的普通 CI 与 Embodied CI 都通过，运行 `uv run python scripts/check_github_release_cap.py --strict --json`。线上计数未知或上海时间当天达到 3 个 GitHub Releases 时停止。
3. 运行 `uv run python scripts/release_readiness.py --strict --target-version 0.16.372 --remote --remote-name origin`；通过后创建本地 tag `v0.16.372`，再以 `--release-tag v0.16.372` 严格验证后推送。

## 发版步骤

1. 最终 master 门禁通过后推送 `v0.16.372` tag，等待 GitHub Release 和 PyPI 精确版本公开。
2. 在 `site/` 使用 `vercel link --yes --project cliany.site` 和 `vercel --prod --yes`，核查 `www.cliany.site` 首页、文档页和生产别名。
3. 从干净的 master 运行 `scripts/check_release_publication.py --strict --remote --distribution --json`；使用正式 PyPI 包和隔离 HOME 复测字段缺失的只读提取，不将维护者 smoke 当作独立用户验证。
