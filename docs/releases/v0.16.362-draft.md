# v0.16.362 发布草案

**目标版本：** `0.16.362`
**提交范围：** `v0.16.361..HEAD`

状态：2026-09-28 第二个发布候选；今日最多 3 个标签，以最终提交、CI 和公开分发为准。

## 用户价值

- 真实浏览器导航超时不再被报为泛用 `E_UNKNOWN` 或错误地引向模型配置，而是返回 `E_PAGE_NOT_READY`、`navigation_timeout` 和站点可达性提示。
- crates.io 候选案例记录当前网络的 HTTP 403 与浏览器超时，维护者先检查页面可达性，再决定是否重试模型探索。

## 当前证据

- 隔离 HOME 的真实 `doctor --llm-live --require-capability generate_adapters --json` 通过；随后 crates.io 浏览器导航两次超时，未生成 adapter。直接请求该搜索页从维护者网络返回 HTTP 403。
- 修复后同一路径返回 `E_PAGE_NOT_READY`，不是成功探索；细节见 [crates.io navigation evidence](../user-evidence/2026-09-28-crates-navigation.md)。
- 定向回归保护超时分类与无关 RuntimeError 的原有分类；最终全量测试、静态检查和 CI 仍以最终提交为准。

## 案例库映射

- `cases/manifest.json` 中 `crates-io-crate-search` 保持 candidate，`adapter_package` 仍 pending，新增当前网络阻断证据和安全的下一步；`cases/README.md` 的候选流程不变。
- `pypi-project-search` 仍待正常页面上的只读在线 smoke；`search-extraction-gap` 继续记录抽取质量边界。

## 风险与兼容性

- 页面超时诊断依赖当前浏览器库明确的 `Page.navigate() timed out` 错误文本；不匹配的运行时错误仍保留原有 `E_UNKNOWN` 分类，不扩大推断。
- 站点返回 403 或验证页时不绕过限制，也不声称 crates.io 在所有网络不可用。
- 真实模型探索仍须逐次运行 preflight；若出现 `llm_live_preflight_not_ready`，停止探索并记录错误。Jev 的实时 TypeSafe 准确率仍未测量。

## 发版前验证

- 严格 target readiness、最终 SHA 的普通 CI 与真实浏览器 CI；tag 前严格 tagged readiness。
