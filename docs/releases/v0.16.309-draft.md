# v0.16.309 发布草案

**目标版本：** `0.16.309`
**提交范围：** `v0.16.308..HEAD`
**提交范围：** `v0.16.309..HEAD`
**发布主题：** 将本地配置就绪与真实 provider 连通性分离为明确的机器可读门禁。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.309..HEAD`；该锚点不改变实际 release diff。

## 用户价值

默认 `doctor --json` 不会真实调用 provider，因此原有 `ready_for_explore` 只能说明本地配置、CDP 与目录等前提已满足。自动化若把它误作 provider 成功，可能在长时间 `explore` 或 candidate promotion 前才发现上游不可用。

本版新增 `summary.ready_for_live_explore` 与 `capabilities.generate_adapters.ready_for_live_explore`。它们仅在 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 成功后为 `true`；未运行或失败的 live preflight 都明确阻断真实 explore。既有 `ready_for_explore` 保留为兼容的本地配置信号。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 保持四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不改变案例、adapter package 或浏览器运行时行为。
- 2026-08-08 的真实严格预检返回 retryable `E_LLM_UNAVAILABLE` / connection error；candidate 的 adapter package、metadata validation 与 online smoke 仍为 pending。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、第三方工作流或 live LLM 成功。

## 风险与兼容性

- 读取旧 `ready_for_explore` 的调用方保持原有本地配置语义；需要真实 provider 证据的自动化应改读新的 `ready_for_live_explore`。
- 静态可用与 live 可用仍是不同证据：新字段不证明 Chrome session、action replay、第三方网站、GitHub Release、PyPI、Vercel 或 candidate package 已就绪。

## 发版步骤

1. 仅在 v0.16.308 已完整发布且版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.309`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.309 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.309`。
5. 运行 `gh release edit v0.16.309 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.309-github-release.md`，再用 `gh release view v0.16.309 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。
