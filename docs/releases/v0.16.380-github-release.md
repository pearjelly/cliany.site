# v0.16.380

## Semantic Extract Replay

Newly generated browser extracts retain targets grounded in the actual AX snapshot and observed DOM mapping. Replay resolves the current semantic region before reading and verifies a unique live root, including a recheck after loading. A renamed result region need not become a successful empty result. Missing, unresolved or unsupported native collection targets fail closed; legitimate zero matches remain valid only when the intended container exists and the command permits them.

Existing generated adapters are not rewritten. New semantic adapters and atoms require a supporting runtime; the public v0.16.379 runtime rejects a new compatibility fixture before browser or model work instead of silently ignoring its target. Native list/table support, identity ambiguity, field-quality rules and the 100-row cap remain explicit boundaries. See [semantic targets and compatibility](https://github.com/pearjelly/cliany.site/blob/v0.16.380/docs/semantic-extract-targets.md).

## Verification and Limits

The source passed 3,332 offline tests, static checks and ordinary/Chromium CI. Three fresh live filter explorations passed 3/3, with all six changed-layout positive/zero-match returned-value and independent-browser checks passing and actual Search refs changing. The first 0/3 reference-validation study is retained, not rescored; its fixture preparation was corrected without changing product code or the per-row-v2 output oracle.

Explore times of 121.23 and 130.42 seconds and a visible retry remain. This one-task controlled maintainer study does not establish a general success rate, improved latency, complete collection, candidate promotion, independent first use or alpha readiness. Final-master, published-package and production acceptance are separate gates.
