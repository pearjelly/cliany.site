# v0.16.371 发布草案

**目标版本：** `0.16.371`
**提交范围：** `v0.16.370..HEAD`（以最终 master 为准）
**状态：** 候选；最终 master 门禁通过且上海时间 GitHub Release 当日名额充足后才能推送 tag。

## 用户价值与边界

- `market` 命令的 JSON 响应增加与 `success` 同值的 `ok`；保留原有 `success`、`data`、`error` 和 `error.fix`，使新旧脚本都能判断结果。
- 自动启动 Chrome 的 CDP 就绪超时现在报告耗时、进程状态、TCP 端口状态和临时 profile 是否存在。这是排查 Issue #36 的有限观测，不改变 20 秒等待或清理流程，也不宣称修复冷启动失败。
- 本版不包含 draft PR #34 的浏览器生成可靠性实验；严格 30 次样本 25/30 仍低于 27/30 目标。Issue #33 的两名独立首次用户验证也未完成。

## 案例库映射

`cases/manifest.json` 与 `cases/README.md` 本版不调整案例状态：四个只读案例保持 active，PyPI、npm 和 crates.io 搜索保持 candidate，`search-extraction-gap` 保持 known-gap。包安装与静态验证不等于在线浏览器探索成功。候选案例仍须先通过真实 `doctor --llm-live --require-capability generate_adapters --json`；出现 `llm_live_preflight_not_ready` 时停止探索，不伪造结果。

## 风险与兼容性

`ok` 是 market JSON 的新增字段，不替换 `success`。调用方若严格拒绝未知字段，应按版本升级其解析约束。Chrome 诊断只在超时错误中增加布尔与进程状态，不包含页面数据；当前采样不能证明偶发超时已消失。

## 发版前验证

1. 在最终 master SHA 运行完整离线测试、具身 Chromium 测试、Ruff、Mypy、`uv lock --check`、官网脚本和案例严格校验；构建 wheel/sdist 并运行 Twine 检查。
2. 确认最终 master 的普通 CI 与 Embodied CI 都通过，并运行 `uv run python scripts/check_github_release_cap.py --strict --json`。若在线计数不可用或当日达到 3 个 GitHub Releases，则停止。

## 发版步骤

1. 运行 `uv run python scripts/release_readiness.py --strict --target-version 0.16.371 --remote --remote-name origin`；通过后创建本地 tag `v0.16.371`，再以 `--release-tag v0.16.371` 严格验证后推送。
2. 等待 GitHub Release 和 PyPI 精确版本公开；在 `site/` 使用 `vercel link --yes --project cliany.site` 与 `vercel --prod --yes`，核查 `www.cliany.site` 首页、文档页和生产别名。
3. 从全新 master 克隆运行 `scripts/check_release_publication.py --strict --remote --distribution --json`；用正式 PyPI 包复测 market JSON 契约，不把维护者 smoke 当作独立用户验证。
