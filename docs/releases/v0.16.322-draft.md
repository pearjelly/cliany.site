# v0.16.322 发布草案

**目标版本：** `0.16.322`
**计划日期：** `2026-08-14`
**提交范围：** `v0.16.321..HEAD`

完成 version bump 后，target-mode readiness 使用 **提交范围：** `v0.16.322..HEAD` 作为占位锚点；创建本地 tag 后，release-tag mode 检查实际发布起点 `v0.16.321..HEAD`。实际 release diff 将是 `v0.16.321..v0.16.322`。

## 用户价值

本版把 GitHub Actions 的 Dependabot 更新提案合并为一个可审阅组，并删除配置中会随 workflow major 更新而过期的版本注释。近期真实维护状态显示 checkout、Node、Python、uv 与 artifact action 更新曾形成多个独立 Dependabot 分支；新的分组让维护者可以一次审阅完整的 CI/runtime 兼容变更，减少只更新半套 action 的风险。该变化不改变 CI job、发布顺序或运行时行为。

## 案例库映射

- `cases/README.md` 与 `cases/manifest.json` 的 8 个案例状态保持不变；本版不生成、下载、安装或晋级 adapter。
- `pypi-project-search`、`npm-package-search` 和 `crates-io-crate-search` 仍是 candidate；本轮真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回 retryable `E_LLM_UNAVAILABLE`，不得宣称 candidate package、metadata validation、online smoke 或 live LLM 成功。
- `search-extraction-gap` 仍是 known-gap；`llm_live_preflight_not_ready` 仍是 candidate 晋级门禁，不能由 Dependabot 配置变更推断为已就绪。

## 风险与兼容性

- 仅扩展 `.github/dependabot.yml` 的 GitHub Actions 更新分组，并修正维护注释；不改变现有 workflow action 版本、job 名称、测试命令或发行逻辑。
- 该配置影响未来 Dependabot 提案的组织方式，不回溯合并现有历史分支；最终 master SHA 的 fresh GitHub CI、Embodied CI 和 tag Release workflow 仍是发布依据。

## 发版步骤

1. 按实际日期完成版本、CHANGELOG、官网和 GitHub Release Notes finalization，并保持工作树干净。
2. 推送最终 master，等待该 HEAD 的 GitHub CI 与 Embodied CI 均成功。
3. 仅在双 CI 成功后运行 `git tag v0.16.322` 创建本地 tag，并运行 `python scripts/release_readiness.py --strict --release-tag v0.16.322 --remote --remote-name origin`。
4. 推送 tag，等待 Release workflow 成功，逐版本核验 GitHub Release 和 PyPI。
5. 将 `site/` 部署到明确链接的 `cliany.site` Vercel production 项目，inspect 后进行浏览器检查。
6. 运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`；任一证据失败都不宣称发布完成。
