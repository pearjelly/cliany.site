# v0.16.321 发布草案

**目标版本：** `0.16.321`
**计划日期：** `2026-08-14`
**提交范围：** `v0.16.320..HEAD`
**发布后范围：** `v0.16.321..HEAD`

完成 version bump 后，target-mode readiness 使用 **提交范围：** `v0.16.321..HEAD` 作为占位锚点；创建本地 tag 后，release-tag mode 检查实际发布起点 **提交范围：** `v0.16.320..HEAD`。实际 release diff 将是 `v0.16.320..v0.16.321`。

## 用户价值

本版将 CI、Embodied CI、依赖升级验证、自动复现和 tag Release workflow 统一到已审阅的 GitHub Actions major 更新：`checkout@v7`、`setup-python@v6`、`setup-uv@v7`、`upload-artifact@v7` 和 `download-artifact@v8`。这回应近期真实 CI 中反复出现的 Node.js 20 deprecation annotation，并让后续 fresh CI 成为 action 兼容性的实际证据。

## 案例库映射

- `cases/README.md` 与 `cases/manifest.json` 的案例入口和 8 个案例状态保持不变；本版不生成、安装或晋级 adapter。
- `pypi-project-search`、`npm-package-search` 和 `crates-io-crate-search` 仍是 candidate；最近真实 live preflight 仍为 retryable `E_LLM_UNAVAILABLE`，不得宣称 candidate package、metadata validation、online smoke 或 live LLM 成功。
- `search-extraction-gap` 仍是 known-gap；`llm_live_preflight_not_ready` 仍是 candidate 晋级的真实门禁状态，不能由本次 workflow action 更新推断为已就绪。

## 风险与兼容性

- 变更只更新 workflow action major 版本，不改变 CI job 名称、测试命令、发布顺序或 PyPI/GitHub 发行逻辑。
- 旧 Dependabot 分支的历史检查不作为发布依据；最终 master SHA 的 fresh GitHub CI、Embodied CI 和 tag Release workflow 才是门禁证据。

## 发版步骤

1. 按实际日期完成版本、CHANGELOG、官网和 GitHub Release Notes finalization，并保持工作树干净。
2. 推送最终 master，等待该 HEAD 的 GitHub CI 与 Embodied CI 均成功。
3. 仅在双 CI 成功后运行 `git tag v0.16.321` 创建本地 tag，并运行 `python scripts/release_readiness.py --strict --release-tag v0.16.321 --remote --remote-name origin`。
4. 推送 tag，等待 Release workflow 成功，逐版本核验 GitHub Release 和 PyPI。
5. 将 `site/` 部署到明确链接的 `cliany.site` Vercel production 项目，inspect 后进行浏览器检查。
6. 运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`；任一证据失败都不宣称发布完成。
