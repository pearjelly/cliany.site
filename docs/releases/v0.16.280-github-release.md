# v0.16.280

Public candidate issue audits now catch renamed or orphaned `case-proposal` handoffs instead of leaving them outside the report.

## What Changed

- `scripts/audit_candidate_issues.py` reports `unexpected` issues when an open `case-proposal` title is absent from the current candidate manifest.
- Each unexpected entry includes its issue number, actual title, URL, and SHA-256 of its current body.
- The JSON summary now provides `unexpected_issue_count` and `unexpected_issue_numbers` for automation.
- `--apply --confirm-rewrite` refuses to rewrite stale issue bodies until `missing`, `duplicate`, and `unexpected` states are resolved.
- Scoped `--case-id` audits still recognize other manifest candidate titles, preventing false unexpected reports.

## Compatibility

The command remains a repository maintainer tool requiring an authenticated GitHub CLI. Its default mode stays read-only; it does not create, close, relabel, rename, or promote issues.

## Trust Boundaries

This release does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result. The real 2026-07-27 preflight observed `E_LLM_UNAVAILABLE`, so candidate cases remain pending.

## Verification

Focused audit-tool tests, case validation, the full offline suite, package build, Twine metadata validation, required CI workflows, GitHub Release, PyPI, Vercel production deployment, browser inspection, and strict publication audit are required before this release is complete.
