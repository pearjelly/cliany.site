# v0.16.308

Direct root CLI adapter commands now run the generated-module source-safety scan before importing adapter code.

## What Changed

- Root CLI adapter dispatch now rejects `commands.py` with banned patterns or invalid UTF-8 before import.
- Static failures return `E_VERIFY_STATIC` with `security_issue`; adapter code is not imported.
- Manifest integrity checks and SDK/API pre-browser contracts remain unchanged.

## Compatibility

Normal local adapters, including adapters without a marketplace manifest, retain their existing execution behavior. Reinstall or regenerate a failed adapter, then run `cliany-site verify <domain> --strict --json`.

## Trust Boundaries

This is a local installed-file check. It does not establish Chrome/CDP, session, action replay, third-party website, GitHub Release, PyPI, Vercel, candidate adapter package, metadata validation, online smoke, or live LLM provider readiness. Candidate promotion remains pending on real evidence.

## Verification

Focused root CLI, loader, verify, SDK, and HTTP regressions; full offline tests; package build and Twine validation; required CI; GitHub Release; PyPI; Vercel production deployment; website browser inspection; and strict publication audit are required before release completion.
