# v0.16.377

## Network Timeouts With Visible Exploration Retries

OpenAI-compatible clients now use a 120-second network-operation timeout with SDK-internal retries disabled. The existing exploration retry loop retains its attempt and backoff events; doctor retains one explicit preflight attempt. Real sync/async SDK configuration and mock-transport timeout recovery/exhaustion tests verify one HTTP request per visible attempt, without private text in progress events. Anthropic configuration, CLI arguments, JSON and adapter formats are unchanged.

This is not a hard end-to-end deadline: connect/read/write/pool waits, response chunks, retries and workflow stages can extend elapsed time. Retries may incur additional model cost. Opt-in benchmark reports retain only provider and endpoint categories, not configured URLs, keys, prompts or page content.

The retained full controlled study scored 29/30 with one timeout and all 38 checked replays passing. A fresh integration smoke passed 9/9 and all 12 changed-input returned-value plus independent DOM checks, including recovery after one 121.35-second attempt. Two earlier preflight-only failures are recorded separately. A fresh Python documentation browser workflow passed exploration and strict verification; changed pathlib replay returned 100 capped rows with the independently observed first title/link, while a zero-match query failed closed.

These are maintainer-only, same-provider samples, not a causal or population latency improvement. The Python docs case remains candidate. Long waits, intermittent live preflight availability, the 100-row cap and independent first-user acceptance remain open.
