# v0.16.396

Session teardown now always cleans up Chrome owned by that connection, even
when disconnect is cancelled or raises. Release the process and clear session
ownership so a later attempt can reuse the port. Existing external browsers
are not terminated. Keep existing handled OSError/RuntimeError behavior and
propagate other original errors/cancellation. No timeout or model-budget increase.

## Evidence And Limits

[The actual395 controlled failure and staged correction](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-28-chrome-disconnect-cleanup.md)
retain initial incorrect TimeoutError expectations separately from the actual
native task-cancellation leak. Native regressions cover owned-browser cleanup,
immediate same-port retry and external-browser survival. Cleanup remains
bounded: terminate/wait5 seconds, then kill/wait5 seconds; an uncooperative OS
can still prevent cleanup. This is not an end-to-end cancellation deadline or
a diagnosis of Issue116's historical timeouts.

Independent first-use acceptance remains pending on fixed387. First failures,
assistance, retries and maintainer tests remain separate. No candidate promotion
or alpha claim follows from this release.
