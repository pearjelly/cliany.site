# v0.16.381

## Safe Model Failure Handling

Model HTTP rejections no longer repeat because a response body contains gateway keywords. CLI and live doctor keep `E_LLM_AUTH_FAILED` for 401/403; other rejected HTTP requests report `retryable=false`. Typed timeouts and network errors retain bounded recovery.

Retry warnings and HTTP failure messages use fixed summaries without copying upstream titles, private endpoints or response text. An optional `explore_llm_attempt_error` progress event adds a safe category, status and retryability, while existing attempt callbacks remain compatible. The controlled benchmark retains these whitelisted fields with attempt timings.

Real SDK mock transports verify one request for authentication/request rejection and exact visible request counts for timeout recovery. A real provider preflight failed with `E_LLM_UNAVAILABLE` before any controlled trial started; that record is retained, not reported as successful model exploration. The existing OpenAI network timeout, retryable status set, semantic extraction, result-quality gates and old adapters are unchanged.

This release does not establish better general latency, continuing provider availability, complete collection, independent first use or alpha readiness. The new failure diagnostics do not make the entire pre-existing progress stream private or establish SDK/HTTP exploration-envelope parity. See [retry diagnostics](https://github.com/pearjelly/cliany.site/blob/master/docs/llm-retry-diagnostics.md) and the [dated review](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-10-safe-llm-retries.md). Issues 33, 38, 53 and 55 remain separate acceptance work.
