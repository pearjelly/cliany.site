# v0.16.386

## First Failures Stay Inspectable

The public-package first-result path now retains the failing install, verify or query stage when a child cannot start, exceeds the existing 90-second wait, or emits invalid UTF-8, JSON or a non-object envelope. Fixed local diagnostics provide a reason and available exit code without echoing child output, arguments or exception text. Python child streams and the parent reader explicitly use UTF-8; no shell settings are changed.

The [pinned first-use guide](https://github.com/pearjelly/cliany.site/blob/master/docs/first-use-trial.md) and failure-first issue form separate Jira API and browser-candidate results, independent people from maintainers, and original failures from assisted retries. Report failure before troubleshooting to eventual success.

## Evidence And Limits

Maintainer-controlled real subprocesses on official PyPI 0.16.385 lost the malformed-output reason or raised a decoding exception before phase handling. Ten new regressions failed before correction; the added controls cover valid upstream error preservation and inherited non-UTF-8 settings. These are controlled fault injections, not reports from independent people or proof that a public service failed. See the [evidence review](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-14-demo-step-failures.md).

Top-level stage error codes, valid upstream error forwarding, timeouts, no-overwrite, strict adapter verification and stop-before-query remain unchanged. The new local diagnostics do not extend a privacy guarantee to every historical upstream error. No model discovery or case promotion is claimed. Independent first-use acceptance is still open; full final-master, GitHub/PyPI, production and installed-package publication acceptance are audited separately.
