## 发版前验证

- 运行 `pytest tests/test_audit_candidate_issues.py -q --no-cov` 与 `CLIANY_QA_OFFLINE=1` 全量测试。
- 运行 `node --check site/script.js`、Ruff、Mypy、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check dist/*`。
- 运行 `python scripts/release_readiness.py --strict --target-version 0.16.329 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 创建 `v0.16.329`，运行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag并修复，不继续发布。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 `vercel inspect www.cliany.site`、`vercel inspect cliany.site` 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
