# v0.16.355

Installing an adapter package, including a dry run, now validates v3 metadata before replacing an existing installation. A correct archive checksum no longer hides missing required fields, invalid types, or a metadata domain that differs from the manifest. Invalid JSON and unsupported metadata versions also fail early. Legacy packages remain installable for migration.

The failure identifies the metadata problem and explains that force cannot bypass validation. JSON Schema validation is now an explicit runtime dependency.

A real audit found that the historical Apache Jenkins v0.14.1 package lacks required metadata fields. That demo is now degraded and excluded from active quickstart recommendations. The audit also records five live Jira issues and an empty Confluence response; neither is claimed as LLM exploration or browser replay evidence.
