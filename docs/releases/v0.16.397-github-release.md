# v0.16.397

When Chrome reaches a navigation error such as a closed or empty HTTP
connection, cliany-site now reports a page failure instead of telling you
that Chrome is unavailable. Check the target in a normal browser before
trying again. Replay stops before sending subsequent input.

The error is `E_PAGE_NOT_READY` with `phase=navigation`,
`reason=navigation_transport_failed` and a recognized Chromium error token.
The HTTP API returns 503 for the corresponding SDK failure. The new
structured details do not include the target URL or exception body.

[Failure evidence and browser controls](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-11-12-navigation-transport.md)
retain the original failures. The correction does not fix an upstream
connection or prove the cause of intermittent document readiness failures.
CDP discovery, timeouts, site verification and retry policy are unchanged.
No generated files are rewritten and no case is promoted. Independent first
use remains separate, on the fixed published 0.16.387 trial.
