# v0.16.310

`doctor --json` now gives capability-oriented automation a safe, concrete next step when local configuration is ready but the LLM provider has not been tested.

## What Changed

- Added `capabilities.generate_adapters.local_ready` and `live_blockers`.
- When live provider evidence is missing, `live_blockers` reports `llm_live_preflight` and `next_step` gives the strict preflight command.
- A successful live preflight clears `live_blockers`; existing `ready` and `ready_for_explore` local compatibility semantics remain unchanged.

## Trust Boundaries

This is local readiness guidance only. It does not prove an LLM provider, browser session, replay, candidate adapter package, metadata validation, online smoke, or third-party workflow succeeded.
