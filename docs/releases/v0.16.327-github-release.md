# v0.16.327

## Fixed

- `doctor --llm-live --require-capability generate_adapters --json` now returns `E_LLM_DISABLED` when no LLM key is configured, while an upstream provider outage remains `E_LLM_UNAVAILABLE`.
- Both failure paths preserve the complete checks, summary, and capability blockers in `error.details`, so automation can choose configuration repair or provider retry without treating either as a successful live capability.

## Compatibility

- Successful doctor checks, adapter commands, SDK, HTTP API, case statuses, and release ordering are unchanged.

## Trust Boundaries

- A doctor error envelope is local readiness evidence only. It does not prove live LLM success, candidate adapter packaging, online smoke, or third-party availability.
