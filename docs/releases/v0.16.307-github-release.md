# v0.16.307

Direct root CLI adapter commands now validate installed manifest integrity before importing adapter code.

## What Changed

- Root CLI adapter dispatch now checks every declared manifest file hash before it imports `commands.py`.
- A manifest-declared symbolic link or hash mismatch returns `E_VERIFY_STATIC` with `manifest_error`; adapter code is not imported.
- SDK `execute` and HTTP `POST /execute` retain the same pre-browser manifest contract.

## Compatibility

Adapters without a manifest keep their existing local execution behavior. When an installed adapter has a manifest, its declared files must be ordinary files whose hashes match. Reinstall a failed adapter from a trusted package, then run `cliany-site verify <domain> --strict --json`.

## Trust Boundaries

This is a local installed-file check. It does not establish Chrome/CDP, session, action replay, third-party website, GitHub Release, PyPI, Vercel, candidate adapter package, metadata validation, online smoke, or live LLM provider readiness. Candidate promotion remains pending on real evidence.

## Verification

Focused root CLI, loader, verify, SDK, and HTTP regressions; full offline tests; package build and Twine validation; required CI; GitHub Release; PyPI; Vercel production deployment; website browser inspection; and strict publication audit are required before release completion.
