# v0.16.284

Marketplace dry-runs now show the currently installed adapter version before an explicit replacement decision.

## What Changed

- `cliany-site market install <package> --dry-run --json` now returns `installed_version` next to the incoming package `version`.
- When `would_replace=true`, local packages and fixed-SHA-256 remote packages report the installed version without writing an adapter or backup.
- An unreadable, missing, or empty installed version is reported as `installed_version=null`; use `would_replace` to determine whether an adapter exists.

## Compatibility

This is an additive JSON field. Strict response schemas must accept `installed_version`; no version ordering, automatic upgrade/downgrade choice, or automatic overwrite is introduced.

`requires_force=true` remains the signal that a later real replacement needs explicit `--force`. A dry-run success only validates the package and computes a plan. Real duplicate installs without `--force` still return nonzero `INSTALL_FAILED` before changing `commands.py`, `metadata.json`, or backups.

## Trust Boundaries

This release does not install, overwrite, or delete an adapter during dry-run. It does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result. Candidate cases remain pending until their required evidence is attached.

## Verification

Focused marketplace, documentation, and release-doc tests, the full offline suite, package build, Twine metadata validation, required CI workflows, GitHub Release, PyPI, Vercel production deployment, browser inspection, and strict publication audit are required before this release is complete.
