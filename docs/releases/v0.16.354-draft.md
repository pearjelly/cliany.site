# v0.16.354 发布草案

**目标版本：** `0.16.354`

**提交范围：** `v0.16.354..HEAD`（target-mode readiness）
**提交范围：** `v0.16.353..HEAD`（release-tag readiness）

## 用户价值

修复 `doctor --llm-live` 的提示与 OpenAI JSON 模式不兼容的问题。预检现在明确要求 JSON 对象，避免严格 provider 因纯文本提示返回 400，导致正常服务被误判不可用。

## 案例库映射

`cases/README.md` 和 `cases/manifest.json` 仍记录 4 active、3 candidate、1 known-gap。`search-extraction-gap` 未关闭。2026-09-22 实测配置中的 provider 返回连接错误，独立 curl 检查确认 TLS 连接失败；`llm_live_preflight_not_ready` 仍阻断 candidate 生成。本次修复不证明真实 provider、adapter package 或 online smoke 成功。

## 风险与兼容性

所有 provider 共用简短 JSON 提示，保留原有单次预检、错误信封与重试分类。没有更改凭据、服务地址、生成格式或案例状态。

## 发版前验证

- 新增真实 ChatOpenAI 客户端加 HTTP MockTransport 的回归测试，验证发送的 JSON response_format 与提示兼容；旧代码失败、修复后通过。
- 执行离线完整测试、Ruff、Mypy、官网 JavaScript 语法、case catalog、构建和 twine 校验。
- 执行 `python scripts/release_readiness.py --strict --target-version 0.16.354 --remote`。

## 发版步骤

1. 推送 master，等待最终 SHA 的 CI 与 Embodied CI success。
2. `git tag v0.16.354`，执行 `python scripts/release_readiness.py --strict --release-tag v0.16.354 --remote --remote-name origin` 后推送 tag。
3. 等待 Release workflow，核验 GitHub Release 与 PyPI 精确版本。
4. 从 `site/` 链接 `cliany.site` 项目并部署 production，核验 alias 与浏览器页面。
5. 执行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
