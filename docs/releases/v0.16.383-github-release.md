# v0.16.383

## Generated Command Input Integrity

Candidate, not published: SDK and HTTP generated-command execution reject undeclared parameter names before browser work. Misspellings no longer silently use recorded defaults and return data for a different input. Errors use the existing `E_INVALID_PARAM` envelope with unknown/accepted names only; HTTP returns JSON 400. Correct declared inputs, defaults and auto-detected value placeholders retain their existing behavior, including strict adapter and output-quality gates.

Published v0.16.382 reproduced success/HTTP 200 for `qurey=asyncio` while the browser searched recorded `typing`. The source correction retains 36 failing baseline regressions and 12 passing controls; scoped source and real Chromium checks cover rejection, correct changed-input results and unchanged page/adapter state. See [the review](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-10-sdk-parameter-integrity.md) and [Issue 87](https://github.com/pearjelly/cliany.site/issues/87).

Legacy `command_defs` and value-type conversion are not changed. Generated modules are not rewritten; case status and independent-user/alpha acceptance remain unchanged. Exact final source, full offline and ordinary/Chromium CI, version/site metadata, online publication-time capacity, tagged readiness and fresh official-public-package acceptance remain required before publication and closure.
