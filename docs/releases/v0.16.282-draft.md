# v0.16.282 发布草案

**目标版本：** `0.16.282`
**提交范围：** `v0.16.281..HEAD`
**发布主题：** 让显式 adapter 验证在缺失状态下返回可操作的失败，而不是空的假成功。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.282..HEAD`；该锚点不改变实际 release diff。

## 用户价值

`market install --dry-run` 明确只校验分发包和安装计划，不会写入 adapter。此前用户随后运行 `cliany-site verify <domain> --json` 时，如果该 adapter 并未安装，CLI 却返回 `ok=true` 和空 `results`。这会让首次使用路径在真正执行已安装 adapter 前给出错误的成功信号。

本版让显式 domain 的 `verify` 返回非零 `ADAPTER_NOT_FOUND` envelope，并带上 `error.details.domain` 和下一步提示：若刚完成 dry-run 预检，应移除 `--dry-run` 执行同一安装命令；也可以选择先 `explore` 生成 adapter。未带 domain 的批量 `cliany-site verify --json` 保持原语义，仍可在空 adapter 目录中返回成功的空列表。

本版不放宽 `market install` 的覆盖保护，不将预检视为安装，也不执行或声称第三方 adapter 命令、live LLM、候选 adapter package、metadata validation 或 online smoke 成功。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 继续定义四个 active case、三个 candidate package-search case，以及已知缺口 `search-extraction-gap`。
- active demo 的安全路径仍要求先完成安装，再静态 `verify`，最后由用户自行运行声明的只读命令；本版只让安装前的缺失状态更早、更准确地暴露。
- `llm_live_preflight_not_ready` 仍然约束 candidate 晋级：没有真实 live preflight、adapter package、metadata validation 和 online smoke 证据时，candidate 保持 pending/blocked。

## 变更分组

### 显式验证契约

- `verify <domain>` 在 adapter 目录不存在时输出 `ADAPTER_NOT_FOUND`、domain 详情和安装/生成提示，并以非零退出。
- `verify --json` 的无 domain 批量扫描保持成功空列表语义，不把“没有任何 adapter”误报为错误。
- README 和官网 marketplace 文档明确 dry-run 只预检包，必须实际安装后才能验证指定 domain。

## 风险与兼容性

- 依赖“显式不存在 domain 返回空成功”的脚本会收到有意的非零结果；这是修正后的 CLI 契约，自动化可以稳定使用 `ADAPTER_NOT_FOUND` 和 `error.details.domain` 判断下一步。
- 已安装 adapter 的 schema、安全扫描和 manifest 检查路径不变。
- 本版不创建、安装、覆盖或删除任何 adapter，不改变 candidate 状态，也不构成 live LLM 或第三方在线成功证据。

## 发版步骤

1. 完成版本、CHANGELOG、官网基线、reviewed GitHub Release Notes 和本草案，在干净 HEAD 运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.282`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.282 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.282`。
5. 运行 `gh release edit v0.16.282 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.282-github-release.md`，再用 `gh release view v0.16.282 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.282` makes explicit adapter verification fail early and explain the install step when the requested adapter is absent, while preserving batch verification and marketplace write protections.
