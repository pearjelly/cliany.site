# v0.16.346

## What Changed

- `POST /explore`, `POST /execute`, and `POST /login` now reject unknown JSON fields with `BAD_REQUEST` / HTTP `400` before calling the SDK.
- Each endpoint accepts only its documented fields, while `workflow_description` remains supported for `POST /explore` when `workflow` is absent.

## Compatibility

Valid documented request fields keep their existing behavior. This change turns misspelled or unsupported write fields into deterministic client errors instead of silently discarding them.

## Trust Boundaries

This is a local HTTP API validation change. It does not establish Chrome availability, live LLM success, candidate adapter package availability, metadata validation, online smoke, or third-party workflow success.
