# v0.16.319

Candidate issue handoffs now distinguish attached doctor preflight evidence from the still-pending adapter package evidence.

## Changed

- Human and machine-readable candidate issue templates show the package evidence state separately from the saved doctor preflight values hash and gate state.
- A blocked preflight now tells maintainers to wait for provider recovery and rerun the strict live preflight; attached blocker evidence never makes candidate `explore` runnable.
- Existing candidate status, package acceptance, and explicit issue rewrite gates remain unchanged.

## Trust Boundaries

This release does not create, close, or promote GitHub issues. It does not create a candidate adapter package, validate metadata, run an online smoke, replay a browser workflow, or prove a live LLM provider is available. The real 2026-08-13 live preflight remained blocked by retryable `E_LLM_UNAVAILABLE`.
