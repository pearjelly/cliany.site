# v0.16.317

Candidate issue audits can now render their expected bodies from a saved strict doctor preflight with `--doctor-json`, so maintainers can detect when a public blocker handoff no longer matches the evidence that produced it.

## Added

- `scripts/audit_candidate_issues.py --doctor-json <path>` reuses the established doctor evidence extractor before building candidate issue templates.
- JSON reports identify the saved evidence with its source path, values SHA-256, gate status, and adapter-package runnable state.
- Existing audit behavior remains read-only. A stale public body still requires explicit `--apply --confirm-rewrite` after missing, duplicate, and unexpected issues are resolved.

## Compatibility

Calls without `--doctor-json` retain the existing template and report shape. Invalid or unreadable evidence fails before GitHub issue access or any rewrite.

## Trust Boundaries

This release does not create, close, or promote GitHub issues; it only makes the expected body evidence-specific when a maintainer supplies a saved file. It does not create a candidate adapter package, validate metadata, run an online smoke, replay a browser workflow, or prove a live LLM provider is available. The known `E_LLM_UNAVAILABLE` preflight blocker remains a blocker until a real preflight succeeds.
