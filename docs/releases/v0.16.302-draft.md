# v0.16.302 发布草案

**目标版本：** `0.16.302`
**提交范围：** `v0.16.301..HEAD`
**提交范围：** `v0.16.302..HEAD`
**发布主题：** 把 active case 的首次运行路径变成安装前可审阅、严格验证优先且不会自动执行的交接。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.302..HEAD`；该锚点不改变实际 release diff。

## 用户价值

公开案例的历史安装与 replay 命令本身不足以表达安全顺序。首次运行时，用户需要确认安装包使用固定 SHA-256、先通过严格 adapter 验证、仅在案例声明时登录，并且最后才运行已声明的只读命令。

本版让 `cliany-site cases --status active` 的 human output 按该顺序输出每个 active case 的首跑路径。它会拒绝含 shell control token、非 HTTPS 或缺少唯一 SHA-256 的安装命令，不把不完整案例伪装为可复制的安全路径。README、中文 README、案例索引和 10 分钟路径同步把 `verify --strict` 放在安装与登录/replay 之间。

这只是指导：`cases` 不会安装 package、登录、执行 adapter 命令或覆盖已有目录。已存在同名 adapter 时，使用严格验证重新建立健康证据，而不是把目录占用当作 adapter 正常。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不新增 adapter、package 或第三方在线验证。
- candidate 的九项 promotion evidence 仍为 pending。2026-08-04 最近一次真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回可重试 `E_LLM_UNAVAILABLE`，并记录 `llm_live_preflight_not_ready` blocker。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、第三方工作流或 live LLM 成功。

## 风险与兼容性

- JSON case catalog 与已声明 commands 保持兼容；本版只调整 human-first output 和对 active install 指令的严格校验。
- 固定 SHA-256 校验接受大小写十六进制值和 `--sha256=<value>` 形式，但拒绝附加 shell control token 的复合命令。
- strict verify 失败会阻断用户的顺序脚本；该行为是明确的安全门禁，不是第三方站点在线可用性证明。
- 本版不代表 live LLM、candidate workflow、candidate adapter package 或第三方站点操作成功。

## 发版步骤

1. 仅在 v0.16.301 已完整发布且版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.302`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.302 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.302`。
5. 运行 `gh release edit v0.16.302 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.302-github-release.md`，再用 `gh release view v0.16.302 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.302` makes active case guidance a safe, copyable human-first handoff: fixed-SHA install, strict verification, declared login only when needed, and a final read-only command without claiming an online workflow succeeded.
