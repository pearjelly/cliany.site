# v0.16.300 发布草案

**目标版本：** `0.16.300`
**提交范围：** `v0.16.299..HEAD`
**提交范围：** `v0.16.300..HEAD`
**发布主题：** 让每日 release cap 在恰好用尽时给维护者和自动化一个无歧义的停止信号。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.300..HEAD`；该锚点不改变实际 release diff。

## 用户价值

此前 `daily_release_limit_ok=true` 只说明当前 tag 数没有超过上限；当当天恰好为 `3/3` 时，它仍为 true，脚本必须额外推断是否还能创建下一个 tag。

本版让 `scripts/check_release_cadence.py --json` 和文本报告显式输出 `daily_release_capacity_remaining`。当值为 `0`，next action 会直接要求暂停新的 release tag 至下一日；当当前 tag 已超过上限时，既有超额动作保持不变。维护自动化可区分“当前状态合规”和“还有多少新 tag 容量”，从而避免把等于上限误解为继续发布许可。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不改变案例、adapter 或运行时浏览器行为。
- candidate 的九项 promotion evidence 仍为 pending。2026-08-03 最近一次真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 在 Chrome/CDP 可用时仍因 provider connection error 返回可重试 `E_LLM_UNAVAILABLE`；`summary.ready_for_explore=false`、`generate_adapters.ready=false`，并记录 `llm_live_preflight_not_ready` blocker。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、third-party workflow 或 live LLM 成功。

## 风险与兼容性

- `daily_release_limit_ok` 保持原语义：当前 release tag 数没有超过 cap。新字段不改变 readiness 或 tag gate。
- `daily_release_capacity_remaining` 仅由 cadence report 输出，范围为 `0..max_daily_releases`；它是当前日期与 tag 历史的报告，不是对 CI、PyPI 或 GitHub Release 成功的证明。
- 当 count 等于 `3/3`，本版新增停止动作；当 count 为 `4/3` 或更多，保留既有超额提示。
- 本版不代表 live LLM、candidate workflow、candidate adapter package 或第三方站点操作成功。

## 发版步骤

1. 只在版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.300`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.300 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.300`。
5. 运行 `gh release edit v0.16.300 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.300-github-release.md`，再用 `gh release view v0.16.300 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.300` makes daily release capacity explicit at the exact cap, while preserving the established release limit and never treating cadence data as publication or live-workflow evidence.
