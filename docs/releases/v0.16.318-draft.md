**目标版本：** `0.16.318`
**计划日期：** 2026-08-13
**提交范围：** `v0.16.317..HEAD`
**发布后范围：** `v0.16.318..HEAD`

完成 version bump 后，target-mode readiness 使用 **提交范围：** `v0.16.318..HEAD` 作为占位锚点；创建本地 tag 后，release-tag mode 检查实际发布起点 **提交范围：** `v0.16.317..HEAD`。实际 release diff 将是 `v0.16.317..v0.16.318`。

## 用户价值

维护者可以把真实 `doctor --llm-live` 阻断证据复制到公开 candidate issue，而不会把本机的 doctor JSON 绝对路径一并公开。`cliany-site cases --issue-template --doctor-json`、`scripts/audit_candidate_issues.py --doctor-json` 和 planner `--issues-dir` 生成的 public body 都改为渲染 `values_sha256`、gate state 与已抽取字段。

本地 JSON audit 和已审阅的 `issue-metadata.json` 仍保留 `source_path`，因此维护者可以复现并追溯同一份证据。公开 body 中需要复跑证据命令时使用显式 `<saved-doctor-json>` 占位符，而不是复制创建 artifacts 的绝对路径。

## 案例库映射

- `cases/README.md` 与 `cases/manifest.json` 的 8 个案例状态不变；本版不生成、安装或晋级 candidate adapter。
- `search-extraction-gap` 仍是已知抽取缺口，本版不修改 browser、提取、adapter runtime 或在线 smoke。
- 2026-08-13 的真实 strict live preflight 仍为 retryable `E_LLM_UNAVAILABLE` / `llm_live_preflight_not_ready`；`local_ready=true`、`local_blockers=[]`，但 `live_blockers=["llm_live"]`，因此 candidate adapter promotion 仍被阻断。
- 不声称 candidate package、metadata validation、online smoke、浏览器 replay 或 live LLM 成功。

## 风险与兼容性

- 本地机器可读 audit、evidence bundle 和 planner metadata 保留 source path 契约；只有可公开 Markdown body 被脱敏。
- 不带 `--doctor-json` 的 issue template、审计和 planner 输出保持兼容。
- `<saved-doctor-json>` 是需要维护者替换的公开占位符，不是一个可访问的证据文件或自动执行命令。

## 发版步骤

1. 按实际日期完成版本、CHANGELOG、官网和 GitHub Release Notes finalization，并保持工作树干净。
2. 推送最终 master，等待该 HEAD 的 GitHub CI 与 Embodied CI 均成功。
3. 仅在双 CI 成功后运行 `git tag v0.16.318` 创建本地 tag，并运行 `python scripts/release_readiness.py --strict --release-tag v0.16.318 --remote --remote-name origin`。
4. 推送 tag，等待 Release workflow 成功，逐版本核验 GitHub Release 和 PyPI。
5. 将 `site/` 部署到明确链接的 `cliany.site` Vercel production 项目，inspect 后进行浏览器检查。
6. 运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`；任一证据失败都不宣称发布完成。
