# v0.16.300

Daily release capacity is now explicit for maintainers and release automation.

## What Changed

- `scripts/check_release_cadence.py --json` now reports `daily_release_capacity_remaining`.
- The field is `0` at an exact daily cap such as `3/3`, even though `daily_release_limit_ok` correctly remains true for the existing tag count.
- At that boundary, the cadence next action explicitly tells maintainers to defer new tags until the next day.

## Compatibility

`daily_release_limit_ok` keeps its established current-count meaning. `daily_release_capacity_remaining` is additive and belongs only to the cadence report; it does not change release readiness, tag validation, CI, or publication-audit contracts.

## Trust Boundaries

Capacity is a report of local release-tag history for the current date, not evidence that a commit has passed CI or that GitHub Release, PyPI, a candidate adapter package, metadata validation, online smoke, a live LLM provider, or a third-party browser workflow succeeded. Candidate promotion remains pending until its required evidence is collected and verified.

## Verification

Focused cadence and documentation regressions, full offline tests, package build and Twine validation, required CI, GitHub Release, PyPI, Vercel production deployment, website browser inspection, and strict publication audit are required before release completion.
