# v0.16.389 发布草案

**目标版本：** `0.16.389`
**提交范围：** `v0.16.388..HEAD`（最终 master 为准）
**状态：** 远程安装安全诊断候选，尚未发布。

## 用户价值

`market install` 的 `INSTALL_FAILED` 保留 `error.details.stage=download` 和固定原因：`http_error`、`timeout`、`tls_certificate_error`、`tls_error`、`network_error`、`incomplete_response`、`download_failed`；有效 HTTP 状态另附数字 `status_code`。缺失资产、权限、证书信任分别提示下一步，不再将下载失败统一归咎于包格式。`demo` 保留上游分类并在验证/查询前停止。

URL 登录凭据、query/fragment、异常正文、响应体、头及部分响应字节不进入新增诊断。证书错误也继承 ValueError，需与正常包校验分开。保留[真实失败、受控 HTTPS 与修复边界](../user-evidence/2026-10-17-remote-install-diagnostics.md)，不倒推旧传输根因。

## 案例库映射

`cases/README.md`、`cases/manifest.json` 与 `search-extraction-gap` 不变；`llm_live_preflight_not_ready` 时停止生成与晋级。本轮不做模型探索或案例晋级，独立试用仍固定在已发布 0.16.387，人次仍为 0/2。

## 风险与兼容性

成功信封、INSTALL_FAILED、非零退出、固定哈希、TLS 校验、大小/路径/metadata 校验、禁止覆盖和生成文件不变。`AdapterDownloadError` 仍是 ValueError 子类；错误字段为增量。未分类 I/O 失败不伪装为网络根因。下载超时和重试策略不变，不增加自动重试、总时限或持续可用性承诺；旧首次失败不改分。受控测试的本地 CA 仅在子进程使用，不修改系统信任或生产证书设置。

## 发版前验证

版本、锁文件、CHANGELOG、README、路线图、官网与发布说明一致；完整离线/静态/案例/公开分发包检查、构建/Twine、精确最终 SHA 普通与真实 Chromium CI 通过后才能合并。独立最终 master 重复全量与 CI；tag 创建和推送前分别执行新鲜在线上海实际 GitHub 发布时间门禁，每天最多三个正式发布，未知即停止。target/tagged readiness 不能替代在线额度。

## 发版步骤

标准 workflow 发布 GitHub/PyPI，核对精确版本和实际文件哈希；按项目指引部署正确 Vercel 生产并核对首页、文档与生产别名；全新正式安装包重复受控故障及公开只读工作流，最后执行严格远端分发审计。静态官网不要求 /console。所有失败保留，维护者测试不计作独立用户。
