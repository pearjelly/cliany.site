# v0.16.303 发布草案

**目标版本：** `0.16.303`
**提交范围：** `v0.16.302..HEAD`
**提交范围：** `v0.16.303..HEAD`
**发布主题：** 让 SDK 与 HTTP 调用方在启动浏览器前收到与 CLI 一致的 adapter 静态完整性诊断。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.303..HEAD`；该锚点不改变实际 release diff。

## 用户价值

自动化调用方此前在通过 SDK 或 `POST /execute` 执行已安装 adapter 时，可能直到浏览器会话开始后才知道 adapter 的 metadata 或 `commands.py` 不能满足 runtime loader 契约。这会把可在本地确定的安装问题混同为 Chrome/CDP 或动作执行问题。

本版让 `ClanySite.execute(domain, command)` 在启动浏览器前复用 loader 的静态前置条件：current-schema adapter 的 metadata 必须是 JSON object，`commands.py` 必须是普通文件，且模块必须导出 `click.Group` 类型的 `cli`。任何失败都返回 `E_VERIFY_STATIC`，包含稳定的 `domain`、`verdict` 与 `reason`；例如无法导入或未导出命令组时使用 `commands_unloadable`，并给出 `cliany-site verify <domain> --strict --json` 的修复入口；浏览器连接与 action replay 不会开始。

HTTP `POST /execute` 保持既有错误映射。adapter 已安装但静态校验不通过时返回 `422`，便于服务编排与不存在 adapter 的 `404`、请求参数错误的 `400` 分开处理；有效 adapter 的执行路径保持不变。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不改变案例、adapter package 或浏览器运行时行为。
- candidate 的九项 promotion evidence 仍为 pending。2026-08-04 最近一次真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回可重试 `E_LLM_UNAVAILABLE`，并记录 `llm_live_preflight_not_ready` blocker。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、第三方工作流或 live LLM 成功。

## 风险与兼容性

- 成功通过 loader 静态契约的 adapter 保持原有 SDK/API 执行语义；本版不改变 action runtime、CDP 或 session 行为。
- `E_VERIFY_STATIC` 仅适用于当前 schema 且已安装、却不能满足 loader 静态前提的 adapter；legacy metadata 与 `ADAPTER_NOT_FOUND` 的现有路径保持兼容。
- 非对象 metadata 会被安全地诊断或跳过，不应再使 adapter discovery 或 SDK 调用因 `.get()` 假设而崩溃。
- loader 为确定 `click.Group` 合约会加载已安装 adapter 的 `commands.py`；这只验证本地受信任 adapter 的模块契约，不证明浏览器、LLM 或第三方工作流成功。
- 本版不代表 live LLM、candidate workflow、candidate adapter package 或第三方站点操作成功。

## 发版步骤

1. 仅在 v0.16.302 已完整发布且版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.303`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.303 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.303`。
5. 运行 `gh release edit v0.16.303 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.303-github-release.md`，再用 `gh release view v0.16.303 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.303` makes SDK and HTTP execution reject unloadable installed adapters before browser startup, preserving HTTP and CLI error contracts while keeping static adapter diagnostics separate from browser, LLM, and publication evidence.
