# v0.16.356 发布草案

**目标版本：** `0.16.356`

**提交范围：** `v0.16.356..HEAD`（target-mode readiness）
**提交范围：** `v0.16.355..HEAD`（release-tag readiness）

## 用户价值

修复共享动作执行器跳过 browser 动作却报告成功、dry-run 实际修改页面的问题。API 失败后会执行浏览器回退；API 成功记入报告。continue-on-error 记录实际 handler 错误后继续下一步，不再将失败算成成功。

## 案例库映射

`cases/README.md` 与 `cases/manifest.json` 保持 3 active、3 candidate、1 degraded、1 known-gap。`search-extraction-gap` 和 Jenkins degraded 未关闭。live provider 的 `llm_live_preflight_not_ready` 未被本地浏览器测试替代，不执行 candidate explore、不声称获得新包或公网 smoke。

## 风险与兼容性

此前被错误跳过的非 dry-run click/type/select/submit 现在会真正执行。依赖这些假成功的调用方会观察到实际动作或真实错误；需要无副作用预检应使用 dry-run。修复不改变公共函数签名、动作结构或 AXTree 语义定位方式。原子 CLI click/type 仍需迁移 browser-use 接口，不宣称完整生成命令路径已修复。

- 新增单元回归在旧代码上 12 项失败，覆盖真实派发、六类 dry-run、API 回退与报告；新增错误传播测试在旧代码上将两步错报为两次成功。
- 本地真实 Chromium 表单：旧 v0.16.355 dry-run 将页面变成 Ada/Blue/Ada:Blue；修复后 dry-run 保持空姓名/Red/untouched，正式回放得到 Ada/Blue/Ada:Blue。未调用 LLM，测试运行时状态使用 tmp_home。

- `python scripts/release_readiness.py --strict --target-version 0.16.356 --remote`。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 CI 与 Embodied CI success。
2. `git tag v0.16.356`，执行 `python scripts/release_readiness.py --strict --release-tag v0.16.356 --remote --remote-name origin` 后推送 tag。
3. 等待 Release workflow，核验 GitHub Release 与 PyPI exact/latest。
4. 从 site 链接 cliany.site 后部署 production，核验 aliases 和浏览器 home/docs/console。
