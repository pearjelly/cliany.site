# v0.16.398

Named browser input now waits until document initialization before
deciding whether equally good matches are ambiguous. If initialization
removes a temporary duplicate textbox, cliany-site can type into the
remaining target. If a tie remains, the command returns `target_ambiguous`
without typing or submitting.

[Real Chromium controls](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-11-12-settled-input-target.md)
show one submission for a temporary pair and no input for a persistent
pair. The existing ten-second observation budget, explicit refs and
site-challenge checks are unchanged. There is no automatic retry or
generated-file rewrite.

Exploration now rejects consecutive clicks on the same observed
cross-page link before recording or executing the plan. The existing
bounded repair can request one click followed by a fresh observation.
[The original failed candidate](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-11-12-duplicate-navigation-plan.md)
remains recorded. Repeat actions on separate observations and existing
saved replay commands are not deduplicated.

This does not identify the cause of the historical document-readiness
failure in #124. Original failures remain recorded. Independent first
use stays separate, on published 0.16.387; no case is promoted.
