# v0.16.312 发布草案

**目标版本：** `0.16.312`
**提交范围：** `v0.16.311..HEAD`
**提交范围：** `v0.16.312..HEAD`
**发布主题：** 让 candidate blocker evidence 明确区分本地前提与 live provider 故障。

完成 version bump 后，target-mode readiness 会检查占位锚点 **提交范围：** `v0.16.312..HEAD`；该锚点不改变实际 release diff。

## 用户价值

v0.16.311 已让 `doctor --json` 输出 `generate_adapters.local_ready` 与 `local_blockers`，但 candidate evidence template、extractor、issue body 和 planner artifacts 尚未采集这两个字段。维护者贴出 `E_LLM_UNAVAILABLE` blocker 时，仍需要回看原始 doctor payload 才能确认本地前提是否健康。

本版把 `summary.capabilities.generate_adapters.local_ready` 和 `summary.capabilities.generate_adapters.local_blockers` 加入 doctor preflight evidence contract。`cases --doctor-json`、独立 extractor、case validation 和 next-iteration planner 会保留同一组 14 个字段及更新后的 template count/hash，让 issue handoff 可以同时证明本地就绪状态与 live blocker。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 中四个 active case、三个 candidate package-search case 和 `search-extraction-gap` known gap 均不变。
- 2026-08-11 的真实严格预检返回 retryable `E_LLM_UNAVAILABLE` / connection error，同时显示 `local_ready=true`、`local_blockers=[]`、整体 `ready=false` 与 `live_blockers=["llm_live"]`。
- candidate adapter package、metadata validation 与 online smoke 仍为 pending；本版不生成、安装或发布 candidate adapter package，也不声称 live LLM、第三方 workflow 或 online smoke 成功。

## 风险与兼容性

- Doctor preflight evidence template 从 12 个字段增至 14 个字段，template SHA-256 会相应变化；按 hash 检测漂移的维护工具应接受新契约。
- `local_ready=true` 只证明本地前提健康，不能替代 `summary.llm_live_preflight.ready=true`，也不会放行 candidate `explore`。
- 本版不改变 doctor 判定、preflight state 状态集合、案例状态或 adapter runtime。
