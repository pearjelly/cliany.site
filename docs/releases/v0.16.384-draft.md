# v0.16.384 发布草案

**目标版本：** `0.16.384`
**提交范围：** `v0.16.383..HEAD`（以最终 master 为准）
**状态：** 浏览器连接故障处理发布准备；完整门禁和严格在线每日额度检查通过前不授权 tag。

## 用户价值

修复 [Issue 89](https://github.com/pearjelly/cliany.site/issues/89) 在公开 v0.16.383 的实际复现：五个 SDK 操作抛出未捕获 CDP 异常，两条 HTTP 路径返回纯文本 500。候选保留旧 JSON 信封，以 `CDP_UNAVAILABLE`、`phase=browser_connect` 和 doctor 提示让调用方处理故障；HTTP 返回 JSON 503。见[证据与边界](../user-evidence/2026-10-12-sdk-browser-errors.md)。

## 案例库映射

保留 `cases/README.md`、`cases/manifest.json` 和 `search-extraction-gap` 的实际状态。未运行真实模型探索；`llm_live_preflight_not_ready` 必须先通过严格真实预检，不能据此晋级案例。

## 风险与兼容性

只处理会话获取时的具名 CDP、连接与超时异常；取消、未知异常、动作阶段处理及既有重试策略不变。保留语义定位、结果质量、固定哈希安装和严格验证，不修改用户或生成文件，不新增 HTTP 路由。PR CI 零真实 LLM key。

## 发版前验证

基线保留 26 个失败回归和 10 个通过控制；候选定向回归 297 项与两项真实 Chromium 检查通过。Chromium 恢复测试的探测转换为确定性模拟，真实连接/动作/加密保存不模拟；另有实际不可用 endpoint 的 SDK/HTTP 检查。版本化最终提交仍须完整离线回归、静态和案例包检查、最终 SHA 普通/Chromium CI、target/tagged readiness 和严格在线每日发布额度。

## 发版步骤

GitHub Release、PyPI、正确 Vercel 生产三端精确版本及公开包故障/正常路径验收通过后，再运行严格远端分发审计；Issue 89 仅在这些门禁完成后结案。
