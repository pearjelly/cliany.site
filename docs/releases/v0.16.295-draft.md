# v0.16.295 发布草案

**目标版本：** `0.16.295`
**提交范围：** `v0.16.294..HEAD`
**发布主题：** 让失败的 human live preflight 给出可复制的严格重试门禁。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.295..HEAD`；该锚点不改变实际 release diff。

## 用户价值

2026-08-03 的真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 显示 Chrome/CDP、key 和 OpenAI-compatible provider 配置都可用，但 provider connection error 返回可重试的 `E_LLM_UNAVAILABLE`，`generate_adapters` 未 ready。

此前普通 `cliany-site doctor --llm-live` 会解释连接问题并保留现有 adapter 的 verify/read-only 路径，却不会打印恢复后应执行的严格命令。用户需要重新查文档才能知道如何安全回到 `explore`。

本版在已经执行且失败的 live preflight 后，增加“修复后重新执行严格预检”与 `cliany-site doctor --llm-live --require-capability generate_adapters`。它不会自动重试、不会绕过 provider gate，也不会把失败的预检描述为生成 adapter 已就绪。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap`；candidate 的九项 promotion evidence 仍是 pending。
- 本次 live preflight 是 `E_LLM_UNAVAILABLE`，因此不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation 或 online smoke 成功。
- `llm_live_preflight_not_ready` 仍是 candidate 交接的 blocker；严格重试命令只有成功后才允许继续 adapter-package 路径。
- `scripts/audit_candidate_issues.py --repo pearjelly/cliany.site --json` 必须继续确认公开 candidate issues #14、#15、#16 为 current；本地 provider 错误不会写成外部成功证据。

## 风险与兼容性

- `doctor --json` 的 checks、summary、capabilities、error envelope 和 strict exit code 均不变。
- 默认 `doctor` 仍不调用 LLM provider；仅显式 `--llm-live` 且 `llm_live_preflight.ready=false` 的 human output 增加一条恢复命令。
- 已有 adapter 的 verify/read-only 引导保持可用；带 `--require-capability` 的严格路径继续使用既有的非零 gate。
- 本版不代表 live LLM、candidate workflow、candidate adapter package 或第三方站点操作成功。

## 发版步骤

1. 在干净 HEAD 完成版本、CHANGELOG、官网基线、路线图、reviewed GitHub Release Notes 和本草案，并运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.295`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.295 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.295`。
5. 运行 `gh release edit v0.16.295 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.295-github-release.md`，再用 `gh release view v0.16.295 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.295` makes an explicit failed live provider preflight show the exact strict retry gate, without changing provider calls, JSON contracts, or candidate promotion evidence.
