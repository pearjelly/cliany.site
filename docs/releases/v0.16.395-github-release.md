# v0.16.395

Chrome startup cancellation now cleans the process created by that operation.
Failed readiness or second discovery also stops and reaps the owned process.
Deliver pending asyncio cancellation at the synchronous-startup handoff before
reporting availability. Preserve the original error/cancellation, including
when ordinary OS cleanup fails. Reused external browsers are not stopped.

## Evidence And Limits

The [actual394 failure and staged repair record](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-28-chrome-startup-cancellation.md)
preserves the first prototype's native failures, not only the later passes.
A native signal regression checks process/port cleanup and same-port retry.
Polling iterations, model budgets, existing generated files and normal
successful ownership transfer are unchanged. Cleanup waits at most5 seconds
before killing, then waits5 more; an uncooperative OS may still fail cleanup.

This does not establish the cause of historical timeouts in Issue116.

tests, assistance and retries do not fill independent participant slots;
no candidate promotion or alpha claim follows.
