## 用户价值

[10月22日新失败证据](../user-evidence/2026-10-22-planning-observation-and-extraction.md)保留旧391 wheel真实研究2/3工作流成功、6/9计划检查通过及3项未运行。空AX观察不再直接交给模型，重新观察消耗原步骤额度；持续为空返回结构化页面未就绪。混合动作/提取计划也在执行前检查已观察的唯一语义目标，共享原单次规划修正。两项旧包单测及真实浏览器旧包失败、源码56项重点回归和3项原生受控通过分开记录，不能替代新完整门禁及真实模型验收。

SDK/HTTP 生成命令内部采用与 CLI 一致的原始参数名/规范化变量别名及覆盖顺序，避免 `search-term` 对应的 `search_term` 或保留名变量被原样输入浏览器却返回成功。公开请求仍使用元数据原始参数名，不扩展可接受键；默认值、0/false 和静态所有权检查不变。[Issue107 证据](../user-evidence/2026-10-17-generated-parameter-aliases.md)保留旧391 wheel 的4项错误成功；新提交须重跑全部适用门禁，不沿用58f41331的较窄通过结论。

修复浏览器工作流生成与重放中的错误成功：单个 query 绑定不再扩散到同名控件，固定基线不会被隐式参数替换；有意义的重复点击、提交、导航和输入不再在生成时被删除。同一参数确需多次输入时，使用显式 `action_indices`；默认值匹配多个动作时停止猜测。

每个声明参数必须在最终替换后影响真实执行字段，不允许无效导航 value、未绑定名称或后参数覆盖前参数。探测 `probe` 在执行前声明并保留完整历史，但不进入业务回放；用户明确要求的固定 `baseline` 仍返回。普通单次搜索不允许混入早期固定查询结果，不能事后改标、选最后一个数组或去重来通过。只向模型提供当前能语义落地且唯一解析的提取候选，保留完整动作 AX 引用和运行时平分拒绝。

版本化前9d0d0c0f通过3,902项完整离线回归及精确提交普通/Chromium CI，未加诊断包装的真实研究为3/3生成、9/9回放；另行声明的固定 asyncio 基线比较诊断为1/1生成、3/3回放，返回[100,100]、[100,100]及[100,0]行。源自不同任务的两组结果分别记录，均不代表完整收集或独立用户。[完整源码收据](https://github.com/pearjelly/cliany.site/issues/106#issuecomment-6226689026)保留七项受控错误成功、所有早期失败与观察器错误；新版本必须另做实际安装包验证。

## 风险与兼容性

本次没有人工检查候选官网外观，存在未被自动测试覆盖的视觉风险；发布说明明确此限制，不以人工反馈作为额外发布前置条件。

旧生成 CLI 已写死步骤和占位符，运行时升级不会自动修复它；需以明确工作流重新探索或正常合并，禁止手改生成代码。单索引只控制对应的 type/select；一个参数复用多个输入需明确声明属于本命令的非重复整数索引。SDK/merge 会重定位标量及多索引，保留原历史；无效或歧义的旧 SDK 参数绑定在浏览器工作前返回 `E_VERIFY_STATIC`，HTTP 使用既有 JSON422，不回显输入值或异常正文。

保留语义身份、100行上限、质量检查、只读边界、取消传播及既有重试/步骤预算。保留录制次数可能比旧错误清理输出更多动作，但不是自动重试。时间先后/静态参数效果不是用户意图或任意站点正确性的证明。受控 CLI/SDK/HTTP 对照、普通真实 CLI 研究、带只读观察的比较诊断、独立用户及正式包分别计分，不混为普遍可靠性。正式0.16.390研究的成功数为2/3工作流、6/9检查，整体验收仍失败，不倒推未捕获的缺失列表原因。
