# v0.16.295

Human `cliany-site doctor --llm-live` output now gives a strict retry command after a failed provider preflight.

## What Changed

- A failed live provider preflight now prints the exact `doctor --llm-live --require-capability generate_adapters` command to rerun after the provider issue is fixed.
- Existing adapter verification and read-only guidance remain available while adapter generation stays blocked.
- The quickstart, README, and website clarify that a failed preflight must be repaired and rerun before `explore`.

## Compatibility

The JSON checks, summaries, error envelopes, and strict exit semantics are unchanged. Default `doctor` still does not call an LLM provider, and explicit strict preflight behavior is preserved.

## Trust Boundaries

This release does not claim a live LLM provider, candidate adapter package, candidate explore, metadata validation, online smoke, or third-party browser workflow succeeded. Candidate promotion evidence remains pending until it is collected and verified.

## Verification

Doctor and documentation regressions, full offline tests, package build and Twine validation, required CI, GitHub Release, PyPI, Vercel production deployment, website browser inspection, and strict publication audit are required before release completion.
