# v0.16.292 发布草案

**目标版本：** `0.16.292`
**提交范围：** `v0.16.291..HEAD`
**发布主题：** 让首次运行的 `doctor` 直接给出可复制、可验证的 active demo 路径。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.292..HEAD`；该锚点不改变实际 release diff。

## 用户价值

`doctor --json` 一直会提供 `demo_adapter_quickstart.recommended_commands`，但普通 `cliany-site doctor` 只在安装目标已经存在时才打印具体命令。第一次使用且目标未安装的用户只能看到泛化的 `cliany-site cases`，还要自行从 JSON 或案例文档拼接三步路径。

本版让 human output 在 active demo 目标未安装时按顺序打印：

```bash
cliany-site market install <published HTTPS adapter> --sha256 <64-hex-sha256>
cliany-site verify <domain> --strict --json
cliany-site <domain> <read-only-command> --json
```

这些是来自已发布 active case catalog 的固定 SHA-256 可复制建议，不是自动化操作。已安装或占用的目标仍先执行 `verify --strict`；普通 doctor 不下载、安装、执行或覆盖 adapter。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 的四个 active case、三个 candidate package-search case 和 `search-extraction-gap` 状态不变。
- 本版不运行 live LLM preflight、explore、adapter package、metadata validation 或 online smoke，也不把 candidate 或第三方浏览器会话称为已验证。
- 后续 candidate 晋级若返回 `llm_live_preflight_not_ready`，仍必须保留 doctor blocker evidence，并让 adapter package、metadata validation 与 online smoke 维持 pending 或 blocked；本次 human 输出修复不替代任何 live 证明。
- 本版只读取打包的 active case catalog 生成建议；不创建、下载、安装、覆盖或声明任何 adapter asset。

## 风险与兼容性

- `demo_adapter_quickstart` 的 JSON schema、兼容 `commands` 列表和 `recommended_commands` 内容均不变。
- 已安装或占用的 active demo 仍从严格验证开始，避免把目标存在误认成健康，也不会自动覆盖。
- 缺少可用 active demo 的 fallback 仍输出 `cliany-site cases`；本版不把 candidate 路径呈现为 demo 成功路径。

## 发版步骤

1. 在干净 HEAD 完成版本、CHANGELOG、官网基线、路线图、reviewed GitHub Release Notes 和本草案，并运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.292`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.292 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.292`。
5. 运行 `gh release edit v0.16.292 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.292-github-release.md`，再用 `gh release view v0.16.292 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.292` makes the first human `doctor` run show the same safe active-demo commands already available in JSON, without taking those actions automatically.
