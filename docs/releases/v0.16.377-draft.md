# v0.16.377 发布草案

**提交范围：** `v0.16.376..HEAD`（以最终 master 为准）
**状态：** 2026-10-08 候选；最终 SHA 的完整回归、CI 和三处发布门禁待复核。

## 用户价值

- OpenAI 兼容客户端使用 120 秒网络操作超时，关闭 SDK 内部重试；探索由现有可见外层尝试与退避负责恢复，doctor 保留一次显式预检。
- 同步和异步客户端的配置、实际 SDK 超时异常、恢复与耗尽路径均有确定性回归；两次可见尝试只发出两次模拟 HTTP 请求，进度不带出私有文本。
- 实时测量报告只保留供应商与端点类别，不保留密钥、地址、提示词或页面内容。

## 验证证据与边界

[固定提交集成复核](../user-evidence/2026-10-08-request-budget-integration.md)通过 9/9 受控探索和 12/12 改参数返回值加独立 DOM 检查，含一次 121.35 秒尝试后的可见重试恢复。两次更早的预检失败未启动任何试验，记录仍保留。既有[完整样本](../user-evidence/2026-10-04-openai-request-budget.md)为 29/30，包含一次总超时，不用小样本替代该门禁。

公开 Python 文档页的新探索与严格验证通过；改搜 pathlib 返回 100 条截断结果，首条标题和链接匹配独立浏览器，零匹配输入明确失败。它仍是维护者的一站点检查，不代表所有行或完整匹配页均正确。网络操作超时不是端到端硬时限，重试也可能增加模型费用；长尾与间歇性预检可用性仍未解决。

## 案例库映射

`cases/README.md` 和 `cases/manifest.json` 状态不变：4 active、3 candidate、1 known-gap，`search-extraction-gap` 不晋级。Anthropic 配置、CLI 参数、JSON envelope、adapter 格式与提取门禁不变，不修改生成代码。#38、#33 与 #55 保持开放；没有独立首次用户或 Jev 准确率结论。

## 风险与兼容性

既有探索重试次数和退避规则不变，120 秒网络操作超时不能替代总时限；历史样本包含超过该阈值仍成功的请求，重试未必总能恢复。若后续探索返回 `llm_live_preflight_not_ready`，记录首个阻塞，先恢复严格 live preflight，不将失败预检算作已完成试验。CLI、JSON 与 adapter 格式不变，不自动覆盖既有 adapter；独立用户成功和第三方长期可用性仍待验证。

## 发版前验证

1. 最终 SHA 运行完整离线测试、Ruff、Mypy、锁文件与官网 JavaScript 检查、严格案例校验，以及 wheel/sdist 构建与 Twine 检查。
2. 等待最终 master 的普通 CI 和真实 Chromium CI 均通过。
3. 在线运行 `scripts/check_github_release_cap.py --strict --json`，再运行 `scripts/release_readiness.py --strict --target-version 0.16.377 --remote --remote-name origin`；创建本地 `git tag v0.16.377` 后，用 `--release-tag v0.16.377` 严格复核，通过才推送。

## 发版步骤

1. 核对 GitHub Release 审阅说明和 PyPI 精确版本、latest 版本及分发文件哈希。
2. 在 `site/` 运行 `vercel link --yes --project cliany.site` 和 `vercel --prod --yes`；检查生产别名、首页、文档页和新增超时说明。
3. 从新 PyPI 安装验证客户端配置和公开只读流程，再执行 `scripts/check_release_publication.py --strict --remote --distribution --json`。
