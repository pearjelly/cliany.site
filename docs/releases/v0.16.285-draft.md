# v0.16.285 发布草案

**目标版本：** `0.16.285`
**提交范围：** `v0.16.284..HEAD`
**发布主题：** 让 doctor 在已占用 active demo 安装目标时，不再建议会失败的重复安装。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.285..HEAD`；该锚点不改变实际 release diff。

## 用户价值

`doctor` 现在从 active demo 的安装目标生成实际可执行的 `recommended_commands`。目标未占用时，推荐仍是固定 HTTPS + SHA-256 安装、`verify`、只读案例；目标已占用时，推荐从 `verify` 开始，再运行只读案例。用户不会因为照着 doctor 的建议重复安装同名 demo 而先遇到重复安装失败。

`adapter_present=true` 仅表示安装目标已占用，不证明 adapter 健康、完整或可运行。`verify` 保持第一步，负责给出实际状态；本版不会调用浏览器、下载包、修改、覆盖、删除或自动修复任何 adapter，更不会自动覆盖该目标。

兼容字段 `commands` 和 `install_command` 仍保留静态安装路径。新的人类输出和自动化应消费 `recommended_commands`，使旧的宽松 JSON 消费者继续工作，而新入口获得安全的下一步。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 继续定义四个 active case、三个 candidate package-search case，以及已知缺口 `search-extraction-gap`。
- 本版不创建、下载、安装、覆盖或声明任何 candidate adapter asset；已发布 active demo 仍使用 release 固定 HTTPS、SHA-256、`verify` 和只读命令。
- `llm_live_preflight_not_ready` 仍然约束 candidate 晋级；没有真实 live preflight、adapter package、metadata validation 和 online smoke 证据时，candidate 保持 pending/blocked。

## 变更分组

### 已占用目标的安全引导

- `demo_adapter_quickstart` 新增 `adapter_present` 和 `recommended_commands`。
- 未占用目标继续推荐安装、`verify`、只读命令；占用目标只推荐 `verify`、只读命令。
- human `doctor` 输出和 `summary.recommended_next_step` 使用 `recommended_commands`，避免人和新自动化走回静态安装列表。
- 安装目标可以是损坏目录或普通文件；仍先跳过重复安装并运行 `verify`，不能把占用目标伪装为健康 adapter。

## 风险与兼容性

- 这是新增 JSON 字段。严格 key-set 校验的调用方应接受 `adapter_present` 和 `recommended_commands`。
- `commands`、`install_command`、`verify_command`、`read_only_command`、`available`、`deprecated` 和 `ready_for_demo_adapters` 的语义保持不变。
- `adapter_present=true` 不是安装成功、metadata 有效、浏览器可重放或第三方站点在线的证明；`verify` 的实际 envelope 才是诊断事实。
- 本版不伪造第三方 adapter、live LLM、candidate package、metadata validation 或 online smoke 成功。

## 发版步骤

1. 在下一个允许发布的日期完成版本、CHANGELOG、官网基线、reviewed GitHub Release Notes 和本草案，在干净 HEAD 运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.285`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.285 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.285`。
5. 运行 `gh release edit v0.16.285 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.285-github-release.md`，再用 `gh release view v0.16.285 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.285` makes the active demo path verify-first when its install target is already occupied, without treating occupancy as a healthy adapter or changing overwrite protection.
