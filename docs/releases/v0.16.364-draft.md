# v0.16.364 发布草案

**目标版本：** `0.16.364`
**提交范围：** `v0.16.363..HEAD`

状态：候选准备中。2026-09-28 已发布三个 tag，今天不得再发布；下一个发布日以最新远端状态和完整门禁结果为准。

## 用户价值

- 真实 PyPI adapter 重放显示事件总线导航超时现在能报 `E_PAGE_NOT_READY`，但普通 `browser navigate` 对另一种 `Page.navigate()` 超时仍会误报 CDP 故障。本版候选将两种明确的导航超时统一归为页面未就绪，并提供站点访问建议。
- Python SDK 的 `navigate()` 同样区分导航超时和普通浏览器断连，便于脚本按错误类型决定是否稍后重试。
- 生成的读取命令现在按提取模式判断非空文本，不再因为没有列表行而误报 `E_EMPTY_RESULT`。探索门禁会拦截会丢失前置输入/点击的拆分命令，要求模型输出可独立重放的完整命令；带端口的本地站点会返回可调用的 `command_group`。
- 生成命令的多个浏览器步骤现在共享一次自动启动的 Chrome，不再在导航后关闭浏览器、让后续步骤落到新空白页。仅关闭本命令启动的进程。若当前页面明确为 `Client Challenge` 且找不到动作目标，返回页面未就绪，而不是建议用户重新定位元素。
- 自动启动 Chrome 的冷启动就绪窗口延长到 20 秒；进程提前退出时立即报告退出状态，端口始终未就绪时会先清理浏览器再返回超时。
- Chrome `browser navigate` 现在会在返回成功前检查页面 AXTree；完整或部分加载的 Cloudflare 验证页返回 `E_PAGE_NOT_READY`。不支持 AXTree 的 provider 保留原导航路径。

## 当前证据

- 官方 PyPI 安装的 v0.16.363 与公开 SHA-256 adapter 包在独立 HOME 中安装、严格校验通过；只读搜索因导航事件超时失败。保留正常系统 HOME、仅隔离项目运行数据后，同一公开 adapter 的浏览器访问到 PyPI `Client Challenge`，搜索返回 `E_SELECTOR_NOT_FOUND`；在线结果仍未验证。先前超时不能归因于站点验证页。
- 同一公开 CLI 在另一个全新 HOME 中运行 Jira 首次结果 demo，自动安装、严格校验并返回 5 条 SPARK issue；第二次运行复用 adapter。它读取 Jira API，不作为浏览器重放证据。
- [真实模型本地页面实测](../user-evidence/2026-09-28-live-local-explore.md)：公开版在独立 CDP 浏览器上把操作与读取拆成两个命令，后者重导航后读到 `untouched` 并误报空结果。候选版生成一个完整参数化命令，两次独立重放分别返回 `Ada:Blue` 与 `Grace:Red`，提取质量均为 `ok`。
- [自动启动浏览器的完整重放](../user-evidence/2026-09-28-generated-browser-lifetime.md)：本地生成命令用两组参数独立返回 `Ada:Blue` 与 `Grace:Red`；未改动的公开 PyPI adapter 完成导航、输入和点击，提取时遇到 `Client Challenge`，准确报 `E_PAGE_NOT_READY`。这不构成 PyPI 在线搜索成功。
- [npm 验证页实测](../user-evidence/2026-09-28-npm-access.md)：修复前的部分加载树曾造成一次虚假导航成功；修复后五次隔离 headless 导航均返回 `E_PAGE_NOT_READY`，普通示例页仍成功。本地真实 Chromium 夹具也验证了验证页失败与普通表单成功；npm 案例未生成 adapter，继续保留 candidate。
- CLI 与 SDK 的定向回归覆盖两种超时及无关断连；新增真实 Chromium 具身回归覆盖自动启动、两组输入及浏览器退出。本地离线测试、Ruff、Mypy 和案例校验已通过。正式发版仍须在最终提交上重跑所有门禁。

## 案例库映射

- 案例状态以 `cases/manifest.json` 为准；`cases/README.md` 记录可复现步骤和只读边界。
- `pypi-project-search` 继续为 candidate：公开包和静态校验完成，只读 online smoke 未通过；不绕过站点验证页，也不把先前单次成功当作稳定结果。
- `npm-package-search` 和 `crates-io-crate-search` 仍为 candidate；[npm 访问检查](../user-evidence/2026-09-28-npm-access.md)只看到 Cloudflare 验证页，维护者网络的访问限制不构成探索成功证据。
- `search-extraction-gap` 仍为 known-gap，不能用本地文本抽取的成功替代第三方列表结果验收。候选晋级前须运行真实 `doctor --llm-live --require-capability generate_adapters --json`；若出现 `llm_live_preflight_not_ready`，停止探索并保留证据。

## 风险与兼容性

- 分类只识别 `TimeoutError` 和明确的 `Page.navigate()` 超时文本；其他 RuntimeError 继续沿用原错误码。
- 修复改善失败解释，不保证目标网站可达，也不改动 AXTree 匹配、站点权限或 Jev 的远程数据边界。
- 临时替换系统 HOME 的测试出现过导航超时；保留正常系统 HOME、仅隔离项目运行数据后，自动启动的 headless Chrome 两次成功访问本地页面。这不足以保证所有冷启动和第三方站点可用。远端具身 CI 曾在 10 秒启动窗口内失败，随后同一提交两次通过；20 秒窗口仍需在最终 SHA 上重新验证。成功的真实模型验证使用已打开页面的独立 CDP 浏览器。拆分命令的修正门禁宁可拒绝生成，也不静默重放可能有副作用的前置点击。
