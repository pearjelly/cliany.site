# v0.16.349

## What Changed

- Direct Python SDK `doctor()` now rejects a non-boolean `llm_live` value and a non-string capability with `E_INVALID_PARAM` before CDP or live-provider work begins.
- This prevents truthy Python values such as `"false"` from unexpectedly requesting a live LLM preflight.

## Compatibility

Valid `True` and `False` inputs retain their existing behavior. All other SDK methods are unchanged.

## Trust Boundaries

This is a local SDK input-validation change. It does not establish Chrome availability, live LLM success, candidate adapter package availability, metadata validation, online smoke, or third-party workflow success.
