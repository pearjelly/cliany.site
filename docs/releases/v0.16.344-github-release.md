# v0.16.344

## What Changed

- `GET /doctor` now rejects repeated `require_capability` query keys.
- `GET /verify` now rejects repeated `domain` query keys.
- Both paths return the existing `BAD_REQUEST` / HTTP `400` contract before the SDK receives an ambiguous request.

## Compatibility

Single-value `require_capability` and `domain` requests keep their existing behavior. Only repeated query keys now fail explicitly instead of letting query-string order choose a value.

## Trust Boundaries

This is a local HTTP API validation change. It does not establish Chrome availability, live LLM success, candidate adapter package availability, metadata validation, online smoke, or third-party workflow success.
