# v0.16.314 发布草案

**目标版本：** `0.16.314`  
**计划日期：** 2026-08-12  
**提交范围：** `v0.16.314..HEAD`
**发布后范围：** `v0.16.314..HEAD`

完成 version bump 后，target-mode readiness 使用 **提交范围：** `v0.16.314..HEAD` 作为占位锚点；创建本地 tag 后，release-tag mode 检查实际发布起点 **提交范围：** `v0.16.313..HEAD`。实际 release diff 是 `v0.16.313..v0.16.314`。

## 用户价值

v0.16.313 修复了真实 production 白屏：`site/script.js` 中英文翻译的撇号曾让整个脚本解析失败。v0.16.314 将 `node --check site/script.js` 从人工验证提升为 master CI 的独立 `Website JavaScript Syntax` job，并在 tag `Release Preflight` 重复执行。strict readiness 同时验证两处门禁仍然存在，使同类静态语法错误在 GitHub 与 PyPI 发布、Vercel production 部署之前失败。

## 案例库映射

- `cases/README.md` 与 `cases/manifest.json` 的 8 个案例状态不变。
- `search-extraction-gap` 仍是已知缺口，本版不改变 adapter、浏览器、提取或在线 smoke 能力。
- 2026-08-12 真实 `doctor --llm-live --require-capability generate_adapters --json` 仍返回 `E_LLM_UNAVAILABLE`；状态是 `llm_live_preflight_not_ready`、`local_ready=true`、`local_blockers=[]`、`live_blockers=["llm_live"]`。
- 因此本版不声称 candidate package、metadata validation、online smoke 或 live LLM 成功。

## 风险与兼容性

- CLI、SDK、HTTP API、adapter schema 与已安装 adapter 行为不变。
- 新 job 使用 `actions/setup-node@v4` 固定 Node 24，仅静态解析已提交的 `site/script.js`，不执行网站代码。
- Release Preflight 在 strict readiness 与 distribution build 前重复检查；失败时 tag workflow 停止，不创建 GitHub Release 或发布 PyPI。

## 发版步骤

1. 完成版本、CHANGELOG、官网与 release notes finalization，并保持工作树干净。
2. 推送最终 master，等待该 HEAD 的 GitHub CI 与 Embodied CI 均成功。
3. 仅在双 CI 成功后创建本地 `v0.16.314` tag，并运行 strict `--release-tag` readiness（含 remote）。
4. 推送 tag，等待 Release workflow 成功，逐版本核验 GitHub Release 与 PyPI。
5. 将 `site/` 部署到明确链接的 `cliany.site` Vercel production 项目，浏览器检查 `www.cliany.site`。
6. 运行 strict publication audit；任一证据失败都不宣称发布完成。
