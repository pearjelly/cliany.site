# v0.16.347

## What Changed

- `POST /explore` and `POST /login` now accept only whitespace-free `http` or `https` URLs with a host.
- Unsupported schemes, missing hosts, and malformed URLs return `BAD_REQUEST` / HTTP `400` before SDK or browser work begins.

## Compatibility

Documented HTTP(S) URLs, existing request fields, and `POST /execute` keep their existing behavior. This change turns an invalid browser target into a deterministic client error instead of passing it to SDK work.

## Trust Boundaries

This is a local HTTP API validation change. It does not establish Chrome availability, live LLM success, candidate adapter package availability, metadata validation, online smoke, or third-party workflow success.
