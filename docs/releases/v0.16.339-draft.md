## 用户价值

- 新生成 adapter 的根 `--sandbox` 现在会在任何 atom 子命令启动前预检初始 URL 和录制动作；跨域导航、危险 URL scheme、JavaScript 执行或下载得到结构化 `E_SANDBOX_VIOLATION`，不会先连接浏览器。
- Python 调用方可显式传入 `ClanySite.execute(domain, command, sandbox=True)`；HTTP `POST /execute` 接受同名布尔字段并把策略违反映射为 `422`。默认调用保持既有执行行为。

## 证据边界

- 这是参数替换后的本地动作策略检查，不是 Chrome、LLM、adapter package、在线 smoke 或第三方工作流成功证明。
- 最近真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 仍返回可重试的 `E_LLM_UNAVAILABLE`；不运行 candidate explore，不生成或宣称 candidate package、metadata validation、online smoke、live LLM 或第三方成功。

## 案例库映射

- `cases/README.md` 与 `cases/manifest.json` 保持案例目录为 8 total、4 active、3 candidate、1 known-gap；三个 candidate 的 adapter package、metadata validation、online smoke 仍 pending。
- `search-extraction-gap` 保持 known-gap；`llm_live_preflight_not_ready` 仍是 candidate 晋级前必须修复或重试的 live provider 边界。
- 本轮不修改案例目录，不创建、关闭或改写公网 issue；没有当前 doctor JSON 时也不执行 `--apply --confirm-rewrite`。

## 风险与兼容性

- 旧 adapter 文件不会被重写。仅在新生成 adapter 使用根 `--sandbox`，或 SDK/API 显式请求 `sandbox=true` 时执行新策略。
- SDK/API 继续返回既有 envelope；HTTP 对非布尔 `sandbox` 返回 `400`，策略违反返回 `422`。

## 发版前验证

- 运行 sandbox/SDK/API/codegen focused tests、发布说明与官网文档回归、`CLIANY_QA_OFFLINE=1` 全量测试、Ruff、Mypy、`node --check site/script.js`、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check`。
- 版本最终化后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --target-version 0.16.339 --remote`；创建本地 tag 后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.339 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 运行 `git tag v0.16.339`，再执行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 alias inspect 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
