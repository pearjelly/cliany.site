# v0.16.287

Strict verification now rejects a locally installed adapter when its required command module is missing or cannot be loaded as a regular file.

## What Changed

- `cliany-site verify <domain> --strict --json` now reports `commands_missing` when `commands.py` is absent or a directory.
- The strict result uses the existing nonzero `E_VERIFY_STATIC` envelope, with the full diagnostic result retained in `error.details.results`.
- Doctor-guided `recommended_commands` therefore stop before a read-only demo command tries to load an incomplete adapter.

## Compatibility

Default `verify` keeps its diagnostic, exit-zero behavior and reports the new verdict in `data.results`. Only `verify --strict` turns it into a nonzero process gate; the existing `verify_command`, `strict_verify_command`, and `recommended_commands` fields remain compatible.

## Trust Boundaries

This verifies local adapter structure only. It does not prove a third-party site is online, a session is valid, or a business command will return data. This release does not install, overwrite, delete, repair, download, or execute an adapter merely by running doctor or verify. It does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result.

## Verification

Focused verification, doctor, documentation, and release-doc tests, the full offline suite, package build, Twine metadata validation, required CI workflows, GitHub Release, PyPI, Vercel production deployment, browser inspection, and strict publication audit are required before this release is complete.
