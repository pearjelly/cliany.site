# v0.16.283

Duplicate marketplace dry-runs now report an actionable, read-only replacement plan.

## What Changed

- `cliany-site market install <package> --dry-run --json` now returns `success=true` and exit 0 when the target adapter is already installed.
- The returned plan exposes `would_replace=true`, `would_create_backup=false`, and `requires_force=true` so callers can distinguish a safe preflight from a permitted overwrite.
- Local packages and fixed-SHA-256 remote packages use the same no-write plan contract.

## Compatibility

Automation that treated a duplicate dry-run's nonzero exit as a blocker must now inspect `data.requires_force`. A successful dry-run only means package validation and plan calculation succeeded; it does not install an adapter or authorize a future install without `--force`.

Real duplicate installs without `--force` still return nonzero `INSTALL_FAILED` before changing `commands.py`, `metadata.json`, or backups. A `--dry-run --force` result with `requires_force=false` remains only a read-only plan.

## Trust Boundaries

This release does not install, overwrite, or delete an adapter during dry-run. It does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result. Candidate cases remain pending until their required evidence is attached.

## Verification

Focused marketplace, documentation, and release-doc tests, the full offline suite, package build, Twine metadata validation, required CI workflows, GitHub Release, PyPI, Vercel production deployment, browser inspection, and strict publication audit are required before this release is complete.
