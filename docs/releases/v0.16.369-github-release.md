# v0.16.369

## More Reliable Session Storage and Clean Installs

Fresh installations now declare `aiohttp` and `PyYAML` directly, matching the modules cliany-site imports at runtime. Session saves no longer fall back to plaintext cookies if encryption fails. Key and Session files are written atomically under process locks; a legacy plaintext Session is used only after successful encrypted migration.

`browser navigate --session` now stops before navigation when the requested Session is missing or unreadable. Generated commands for public pages remain usable without a saved Session; if a Session file exists but cannot be read, the error remains visible instead of quietly proceeding as logged out.

This release does not promote the PyPI, npm, or crates.io search candidates. The published PyPI adapter installs and verifies, but the latest online attempt reached PyPI's `Client Challenge` rather than independently verified search rows.

The previously published no-login demos were independently rechecked with the PyPI v0.16.368 CLI: [Jira](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-02-jira-pypi-demo-audit.md) returned five read-only issues, and [Confluence](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-02-confluence-pypi-demo-audit.md) returned six pages. Those are point-in-time third-party results, not a guarantee of future availability or proof of live LLM discovery.
