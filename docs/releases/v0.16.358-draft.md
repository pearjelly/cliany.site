# v0.16.358 发布草案

**目标版本：** `0.16.358`
**提交范围：** `v0.16.357..HEAD`
**提交范围：** `v0.16.358..HEAD`（升版后 target-mode readiness）

状态：发布候选；完成最终提交的测试、CI 和 tagged readiness 后发布。

## 用户价值

- `doctor --llm-live --json` 在检查项和摘要中返回按 TLS、DNS、拒绝连接、超时或 HTTP 状态区分的安全修复建议，仍不输出底层异常原文。
- 官网文档提供 Jev 只读意图查找命令、显式外发授权和限制；明确保存会话只恢复适用于目标主机的 Cookie，不恢复 LocalStorage。
- 发布门禁拒绝仍写着未发布状态的 GitHub Release notes；0.16.357 的公开说明已更正。

## 案例库映射

`cases/README.md` 与 `cases/manifest.json` 仍为 2 active、3 candidate、2 degraded、1 known-gap；`search-extraction-gap` 未关闭。2026-09-23 Jira active adapter 通过严格验证，独立只读命令返回 5 条 issue。Confluence 与 Jenkins 不因此晋级；候选 package 仍缺真实模型生成证据，`llm_live_preflight_not_ready` 不被离线替身消除。

## 风险与兼容性

- 诊断建议是分类，不会修复上游连接，也不证明密钥有效。当前配置的模型服务在 TLS 阶段断开，未得到 HTTP 响应。
- Jev 仍需 `TYPESAFE_API_KEY` 和 `--allow-remote`；当前没有真实 TypeSafe 评测，不宣称准确率、成本或速度收益。页面元素名称可能含敏感信息。
- 旧 Cookie 会话不自动清理；LocalStorage 恢复仍不支持。官网没有 `/console` 静态路由。

## 发版前验证

- 定向 doctor、官网与 release-readiness 测试已经通过；最终版本提交还须跑完整离线测试、Ruff、Mypy、Node 检查、案例校验、构建与 Twine。
- 最终 SHA 的 CI 和 Embodied CI 必须通过；严格 target/tag readiness、GitHub Release、PyPI 精确版本和官网生产别名必须逐项核对。

## 发版步骤

1. 确认工作树、版本、CHANGELOG、官网、路线图和已审阅发布说明一致。
2. 运行完整本地检查和 `python scripts/release_readiness.py --strict --target-version 0.16.358 --remote`，再推送最终 master。
3. 等待最终 SHA 的 CI 与 Embodied CI 成功，创建 `v0.16.358`，运行 tagged readiness 后推送 tag。
4. 等待 Release workflow，核对 GitHub Release 和 PyPI；从 `site/` 运行 `vercel link --yes --project cliany.site` 与 `vercel --prod --yes`。
5. 检查 `www.cliany.site` 首页与文档页，运行严格远端分发审计。
