## 用户价值

- Python SDK 新增同步 `save_session(domain, cdp_url=..., headless=...)`，让非 async 调用方可保存当前浏览器 session，无需自行管理事件循环或重写浏览器配置。
- 同步入口复用 `ClanySite.save_session()`：host、host:port 和 bracketed IPv6 继续可用，路径、凭据、空白和无效端口仍会在打开 Chrome 或写 session 前返回 `E_INVALID_PARAM`。

## 证据边界

## 风险与兼容性

- 新函数是现有异步 SDK 方法的便利包装，不改变 CLI、HTTP API、adapter、session 持久化格式或 release workflow。
- 该变更不启动 Chrome、不调用 LLM，也不表示 adapter 或第三方站点已可用。

## 发版前验证

- 运行 SDK、发布说明与官网文档 focused tests、`CLIANY_QA_OFFLINE=1` 全量测试、Ruff、Mypy、`node --check site/script.js`、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check`。
- 版本最终化后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --target-version 0.16.353 --remote`；创建本地 tag 后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.353 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 运行 `git tag v0.16.353`，再执行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 alias inspect 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
