# v0.16.339

## Fixed

- Newly generated adapters now honor root `--sandbox` before any atom command starts. Recorded action `type` values are checked alongside the initial URL, so cross-domain or dangerous actions return `E_SANDBOX_VIOLATION` without first opening Chrome.
- `ClanySite.execute(..., sandbox=True)` and HTTP `POST /execute` provide the same parameter-resolved preflight. HTTP validates the boolean field and maps a sandbox violation to `422`.

## Compatibility

- Existing adapter files and default SDK/API execution behavior are unchanged. The new boundary applies only to newly generated adapters using root `--sandbox`, or to SDK/API callers that explicitly enable `sandbox`.

## Trust Boundaries

- A local sandbox pass is not proof of Chrome availability, live LLM success, adapter-package validation, online smoke, or third-party workflow success.
- Candidate adapter promotion remains gated on a real successful live-provider doctor preflight.
