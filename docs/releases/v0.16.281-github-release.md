# v0.16.281

Candidate issue audits now make an unknown public handoff actionable directly from the default terminal output.

## What Changed

- `scripts/audit_candidate_issues.py` now includes an `unexpected` issue's actual title and URL in its human-readable report.
- Maintainers can identify the public blocker without parsing the JSON report or issuing a separate GitHub lookup.
- JSON output, body hashes, and the explicit `--apply --confirm-rewrite` gate remain unchanged.

## Compatibility

This remains a repository maintainer tool requiring an authenticated GitHub CLI. The default audit remains read-only and does not create, close, relabel, rename, rewrite, or promote an issue. Automation should continue to consume the existing JSON contract.

## Trust Boundaries

This release does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result. The real 2026-07-27 preflight observed `E_LLM_UNAVAILABLE`, so candidate cases remain pending.

## Verification

Focused audit-report tests, documentation checks, the full offline suite, package build, Twine metadata validation, required CI workflows, GitHub Release, PyPI, Vercel production deployment, browser inspection, and strict publication audit are required before this release is complete.
