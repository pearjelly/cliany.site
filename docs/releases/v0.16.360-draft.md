# v0.16.360 发布草案

**目标版本：** `0.16.360`
**提交范围：** `v0.16.359..HEAD`

状态：下一自然日发布候选；2026-09-23 已达到每日 3 个标签上限，不在当天创建或推送标签。

## 用户价值

- 新用户可运行 `cliany-site demo --case-id apache-jira-issues --json`，一次完成固定哈希安装、严格验证、只读查询和至少一条 issue 的结果验收；无需先配置 LLM key。
- 本地已有同名 adapter 时跳过安装但仍严格验证；安装、验证、查询和空结果均以非零状态停止，不覆盖已有目录，也不执行 candidate 或登录案例。
- 普通终端输出直接显示结果条数和 issue 摘要，失败按阶段给出下一步；机器可读 JSON 契约保持不变。
- Jev 意图定位在拒绝选择时保留前三个已验证候选及概率，帮助人工检查页面；它仍不点击或修复页面。

## 当前证据

- Python 3.13 全套离线测试 3025 项通过、1 项跳过；新命令保护性测试另增加 2 项，最终发布前需重跑全套。
- 干净临时用户目录中首次运行返回 5 条公开 SPARK issue，第二次运行跳过安装、再次返回 5 条；这只证明该时点的 Jira 首跑路径，不证明其他站点或真实 LLM 生成能力。
- 独立 Python 3.11 环境从本地构建 wheel 安装后，在空 HOME、仓库外目录及 `CLIANY_QA_OFFLINE=1` 下仍返回 5 条 issue。正式 PyPI 版本发布后必须再从 PyPI 重测，不能把本地 wheel 当作公开分发证据。
- 案例索引严格校验、Mypy 125 个源文件、Ruff 运行时代码、网站 JavaScript 和网站转换检查通过；wheel/sdist 构建与 Twine 元数据检查通过。
- 桌面 1440px 与手机 390px 的本地网站预览确认新命令完整可见，无页面横向溢出。

## 风险与兼容性

- 首跑案例依赖 GitHub 发布资产和公开 Jira 服务，网络或服务故障会返回失败；该 Jira adapter 使用公开只读 API，不需要 Chrome/CDP。当前仅 Jira active 案例具有可执行的行数 oracle。
- 新 `demo` 输出采用统一 `ok` envelope，内部保留旧 adapter 的原始 `success` 结果；旧 adapter 文件未修改。
- 没有 TypeSafe 密钥，Jev 的真实准确率、拒绝率、延迟和费用仍未测量。当前只是更透明地呈现决策证据。
