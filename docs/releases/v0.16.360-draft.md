# v0.16.360 发布草案

**目标版本：** `0.16.360`
**提交范围：** `v0.16.359..HEAD`

状态：下一自然日发布候选；2026-09-23 已达到每日 3 个标签上限，不在当天创建或推送标签。

## 用户价值

- 新用户可运行 `cliany-site demo --case-id apache-jira-issues --json`，一次完成固定哈希安装、严格验证、只读查询和至少一条 issue 的结果验收；无需先配置 LLM key。
- 本地已有同名 adapter 时跳过安装但仍严格验证；安装、验证、查询和空结果均以非零状态停止，不覆盖已有目录，也不执行 candidate 或登录案例。
- 普通终端输出直接显示结果条数和 issue 摘要，失败按阶段给出下一步；机器可读 JSON 契约保持不变。
- Jev 意图定位在拒绝选择时保留前三个已验证候选及概率，帮助人工检查页面；它仍不点击或修复页面。
- 新配置的 OpenAI 兼容模型已通过真实连通性检查，并成功生成可运行的 PyPI 搜索命令；探索提示现在明确给出 0-based 动作编号和本轮起始编号，减少最后一轮遗漏动作的概率。
- PyPI 候选案例现采用真实生成的 `search-packages --query` 命令与对应样例；`validate_cases.py --case-id` 可单独严格校验目标候选包，不再因其他候选包缺失而给出假失败。晋级清单与 issue 交接也输出同一条聚焦校验命令。

## 案例库映射

- `cases/README.md` 和 `cases/manifest.json` 中，`apache-jira-issues` 继续是已发布的 active 首跑案例；`pypi-project-search` 仍是 candidate，公开资产验证后才考虑晋级。
- `search-extraction-gap` 继续记录列表字段与空结果的已知边界。新有界重试只处理页面交互后的短暂空列表，不把持续空结果或部分字段缺失伪装成成功。
- 真实模型已通过一次 live preflight，但自动化仍须逐次检查 `generate_adapters.ready`；若返回 `llm_live_preflight_not_ready`，停止探索并保留诊断证据。

## 风险与兼容性

- 首跑案例依赖 GitHub 发布资产和公开 Jira 服务，网络或服务故障会返回失败；该 Jira adapter 使用公开只读 API，不需要 Chrome/CDP。当前仅 Jira active 案例具有可执行的行数 oracle。
- 新 `demo` 输出采用统一 `ok` envelope，内部保留旧 adapter 的原始 `success` 结果；旧 adapter 文件未修改。
- 没有 TypeSafe 密钥，Jev 的真实准确率、拒绝率、延迟和费用仍未测量。当前只是更透明地呈现决策证据；新配置的模型是另一家 OpenAI 兼容服务，不能充当 Jev 测试证据。
- 全量 candidate 包校验仍会因 npm/crates.io 缺包而失败；PyPI 聚焦校验已通过。该案例继续保持 candidate，直到候选包作为公开 GitHub Release 资产上传并完成带 SHA-256 的独立安装验证，不宣称已发布或已晋级。
