# v0.16.307 发布草案

**目标版本：** `0.16.307`
**提交范围：** `v0.16.306..HEAD`
**提交范围：** `v0.16.307..HEAD`
**发布主题：** 让根 CLI 直接执行 adapter 的导入路径，也在读取 `commands.py` 前执行已安装 manifest 的完整性检查。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.307..HEAD`；该锚点不改变实际 release diff。

## 用户价值

已安装 adapter 的 manifest 描述可信分发包中的普通文件和 SHA-256。此前 SDK `execute` 与 HTTP `POST /execute` 会在浏览器启动前验证这些哈希，但根 CLI 的直接 adapter 命令只会拦截 manifest 符号链接，仍可能导入已篡改的 `commands.py`。

本版让 root CLI 在导入前复用 manifest 验证：存在 manifest 时，声明文件的符号链接或哈希失配会返回 `manifest_error` / `E_VERIFY_STATIC`，不会导入 adapter 代码。没有 manifest 的本地 adapter 保持既有行为。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不改变案例、adapter package 或浏览器运行时行为。
- candidate 的九项 promotion evidence 仍为 pending。保留的最近真实 live preflight 是 retryable `E_LLM_UNAVAILABLE` / `llm_live_preflight_not_ready` blocker；本版不把它当作成功。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、第三方工作流或 live LLM 成功。

## 风险与兼容性

- 不含 `manifest.json` 的本地 adapter 保持原有可执行行为；存在 manifest 的 adapter 现在会在全部执行入口遵循普通文件和哈希契约。
- 哈希失配会在导入前停止 root CLI 命令；请用可信包重新安装，再运行 `cliany-site verify <domain> --strict --json`。
- `E_VERIFY_STATIC` 只表示本地静态边界未通过，不证明 Chrome、LLM、session、action replay、第三方网站、GitHub Release、PyPI、Vercel 或 candidate package 已就绪。

## 发版步骤

1. 仅在 v0.16.306 已完整发布且版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.307`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.307 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.307`。
5. 运行 `gh release edit v0.16.307 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.307-github-release.md`，再用 `gh release view v0.16.307 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。
