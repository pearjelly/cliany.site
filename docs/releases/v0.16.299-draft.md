# v0.16.299 发布草案

**目标版本：** `0.16.299`
**提交范围：** `v0.16.298..HEAD`
**发布主题：** 让结构化搜索和列表提取在字段缺失时能直接指出需要复核的结果行。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.299..HEAD`；该锚点不改变实际 release diff。

## 用户价值

结构化搜索或列表提取已经会把缺失字段报告为 `partial` 并返回 `E_EMPTY_RESULT`，但用户还需要在每一行中猜测哪个结果项的字段映射或页面内容失效。

本版为失败的对象行提取增加可选 `data.quality.field_blank_rows`。键是缺失或空白字段名，值是从 1 开始的结果行号列表。例如 `{"url":[2],"snippet":[3]}` 表示第二行缺少 URL、第三行缺少摘要。完整结果不会新增这个字段，已有 `issues`、`row_count`、`field_names`、状态和失败语义均保持不变。用户可以据此回到具体结果行，修正字段映射或判断页面内容，而不是把部分成功误当成可用数据。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap`。该 known-gap 的离线 fixture 现验证链接或摘要缺失时，质量报告会同时保留 `partial` 与按字段列出的行号。
- candidate 的九项 promotion evidence 仍为 pending。2026-08-03 最近一次真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 在 Chrome/CDP 可用时仍因 provider connection error 返回可重试 `E_LLM_UNAVAILABLE`；`summary.ready_for_explore=false`，`generate_adapters.ready=false`，并记录 `llm_live_preflight_not_ready` blocker。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、third-party workflow 或 live LLM 成功。

## 风险与兼容性

- `field_blank_rows` 只在失败的结构化对象行质量报告中出现；成功、文本、attribute、纯标量 list 和既有 failure envelope 均不因它改变 schema。
- 行号是结果数组的 1-based 位置，而不是页面 DOM index、CSS selector 或稳定业务 ID；页面重排后应重新运行提取。
- 该诊断不放宽 `expects_nonempty`、`E_EMPTY_RESULT` 或 partial quality gate，也不修复页面字段映射本身。
- 本版不代表 live LLM、candidate workflow、candidate adapter package 或第三方站点操作成功。

## 发版步骤

1. 只在版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.299`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.299 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.299`。
5. 运行 `gh release edit v0.16.299 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.299-github-release.md`，再用 `gh release view v0.16.299 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.299` makes structured extraction quality failures actionable by identifying the affected result rows, while preserving existing quality gates and without claiming a live provider or candidate workflow succeeded.
