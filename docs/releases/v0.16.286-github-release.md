# v0.16.286

Doctor-guided active demos now use strict static verification as a process gate before their read-only command.

## What Changed

- Added `cliany-site verify <domain> --strict --json`.
- Strict verification returns a nonzero error envelope when a schema, legacy-adapter, security, manifest, or requested smoke check fails.
- Failure diagnostics remain in `error.details.results`, with `failed_domains` for automation.
- Static failures use `E_VERIFY_STATIC`; a failure caused only by a requested CDP smoke check uses `E_VERIFY_SMOKE`.
- `doctor --json` adds `data.summary.demo_adapter_quickstart.strict_verify_command`, and `recommended_commands` now use it.

## Compatibility

Default `verify` keeps its existing diagnostic, exit-zero behavior. `verify_command` and `commands` remain compatible fields. Automation that follows doctor guidance should execute `recommended_commands`; the read-only command runs only after `verify --strict` succeeds.

## Trust Boundaries

Strict verification checks local adapter structure and an explicitly requested smoke check. It does not prove a third-party site is online, a session is valid, or a business command will return data. This release does not install, overwrite, delete, repair, download, or execute an adapter merely by running doctor or verify. It does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result.

## Verification

Focused verification, doctor, documentation, and release-doc tests, the full offline suite, package build, Twine metadata validation, required CI workflows, GitHub Release, PyPI, Vercel production deployment, browser inspection, and strict publication audit are required before this release is complete.
