# v0.16.294

Human `cliany-site doctor` guidance now separates local configuration from a live provider preflight.

## What Changed

- Ordinary human `cliany-site doctor` output now asks users to run `doctor --llm-live --require-capability generate_adapters` before it presents an `explore` command.
- Default `doctor` still does not call an LLM provider; it only checks local configuration and browser availability.
- A successful live preflight continues to show the direct `explore` next step, while the quickstart, README, and website now teach the same order.

## Compatibility

The `doctor --json` checks, summary, capabilities, and `llm_live_preflight` contracts are unchanged. Existing explicit `doctor --llm-live` behavior and strict exit semantics remain intact.

## Trust Boundaries

This release does not claim a live LLM provider, candidate adapter package, candidate explore, metadata validation, online smoke, or third-party browser workflow succeeded. Candidate promotion evidence remains pending until it is collected and verified.

## Verification

Doctor and documentation regressions, full offline tests, package build and Twine validation, required CI, GitHub Release, PyPI, Vercel production deployment, website browser inspection, and strict publication audit are required before release completion.
