# v0.16.279

Candidate promotion issues now have a safe way to stay aligned with the current executable handoff contract.

## What Changed

- Added `scripts/audit_candidate_issues.py` to compare each manifest candidate's open `case-proposal` issue against the current generated issue body.
- The audit reports `current`, `stale`, `missing`, and `duplicate` states with expected and actual SHA-256 evidence.
- Rewriting requires both `--apply` and `--confirm-rewrite`, and the tool rechecks GitHub after the rewrite instead of assuming success.
- Refreshed public candidate issues #14, #15, and #16 so their first executable command is the strict `doctor --llm-live --require-capability generate_adapters --json` gate.

## Compatibility

The command is a repository maintainer tool and needs an authenticated GitHub CLI. Its default mode is read-only; it does not create, close, relabel, or promote issues.

## Trust Boundaries

This release does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result. The real 2026-07-27 preflight observed `E_LLM_UNAVAILABLE`, so candidate cases remain pending.

## Verification

Focused audit-tool tests, case validation, the full offline suite, package build, Twine metadata validation, required CI workflows, GitHub Release, PyPI, Vercel production deployment, browser inspection, and strict publication audit are required before this release is complete.
