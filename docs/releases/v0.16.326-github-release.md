# v0.16.326

## Fixed

- `doctor --llm-live --require-capability` now returns a stable error for the first hard blocker while preserving the complete failed `checks` and `summary` in `error.details`.
- Missing Chrome/CDP is reported as `E_CDP_UNAVAILABLE`; a provider outage retains its `E_LLM_UNAVAILABLE` diagnostic. Automation can repair the right dependency and retry without treating `E_UNKNOWN` as a runnable capability result.

## Compatibility

- Successful doctor checks, adapter commands, SDK, HTTP API, case statuses, and release ordering are unchanged.

## Trust Boundaries

- A doctor error envelope is local readiness evidence only. It does not prove live LLM success, candidate adapter packaging, online smoke, or third-party availability.
