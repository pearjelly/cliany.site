# v0.16.308 发布草案

**目标版本：** `0.16.308`
**提交范围：** `v0.16.307..HEAD`
**提交范围：** `v0.16.308..HEAD`
**发布主题：** 让根 CLI 直接执行 adapter 的路径，也在导入前执行生成模块源码安全扫描。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.308..HEAD`；该锚点不改变实际 release diff。

## 用户价值

SDK `execute`、HTTP `POST /execute` 与 `verify --strict` 会在导入 adapter 前扫描禁用模式和非 UTF-8 `commands.py`，但根 CLI 直接执行 adapter 命令此前只检查路径与 manifest，仍可能导入同类本地不安全模块。

本版让 loader 在导入前复用生成模块扫描。包含 `eval(`、`exec(`、`__import__(`、`subprocess.`、`os.system(` 或无法按 UTF-8 读取的模块，会返回 `security_issue` / `E_VERIFY_STATIC`，不导入 adapter 代码。manifest 完整性检查和无 manifest adapter 的兼容行为保持不变。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 保持四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不改变案例、adapter package 或浏览器运行时行为。
- candidate 的九项 promotion evidence 仍为 pending。保留的最近真实 live preflight 是 retryable `E_LLM_UNAVAILABLE` / `llm_live_preflight_not_ready` blocker；本版不把它当作成功。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、第三方工作流或 live LLM 成功。

## 风险与兼容性

- 本次只阻止已有禁用模式或无法按 UTF-8 读取的 adapter 模块；正常本地 adapter 与无 manifest adapter 保持行为不变。
- 静态失败请重新安装可信 adapter 或重新生成，再运行 `cliany-site verify <domain> --strict --json`。
- `E_VERIFY_STATIC` 只表示本地静态边界未通过，不证明 Chrome、LLM、session、action replay、第三方网站、GitHub Release、PyPI、Vercel 或 candidate package 已就绪。

## 发版步骤

1. 仅在 v0.16.307 已完整发布且版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.308`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.308 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.308`。
5. 运行 `gh release edit v0.16.308 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.308-github-release.md`，再用 `gh release view v0.16.308 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。
