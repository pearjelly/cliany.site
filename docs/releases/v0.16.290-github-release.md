# v0.16.290

Newly generated adapters now make extract and replay failures actionable for shell automation.

## What Changed

- A generated adapter now rejects a missing, `None`, empty, or whitespace-only extract selector before it calls `browser extract`. The structured error is `E_PARSE_FAILED` with the selector and extract-mode context.
- When a generated command writes a failed `--json` envelope, it now exits nonzero. `E_SELECTOR_NOT_FOUND`, `E_EMPTY_RESULT`, CDP errors, and other runtime failures no longer look successful to shell scripts or CI.
- The empty generated `run-workflow` fallback follows the same nonzero JSON failure rule.
- An explicitly declared `expects_nonempty=false` empty result remains a successful `ok=true`, exit-0 outcome.

## Compatibility

The JSON envelope body and existing error codes remain unchanged. This affects newly generated or regenerated adapters; existing generated files keep their current behavior until regeneration. Direct `browser extract` usage retains its separate full-page extraction option.

## Trust Boundaries

This release improves local generated-command failure signaling only. It does not prove a third-party page is online, a browser session is valid, a selector will match after a page change, or any candidate case has live evidence. It does not claim live LLM success, generate or install an adapter archive, run metadata validation, or perform an online smoke test.

## Verification

Focused codegen/runtime-helper, generated Click command, documentation, and site tests; the full offline suite; package build; Twine metadata validation; required CI workflows; GitHub Release; PyPI; Vercel production deployment; browser inspection; and strict publication audit are required before this release is complete.
