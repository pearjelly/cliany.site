# v0.16.360

## First Result From A Clean Install

`cliany-site demo --case-id apache-jira-issues --json` now takes a new user from an empty runtime directory to a real, read-only result. It installs the pinned public Jira adapter only when absent, verifies it strictly, runs the declared query, and requires at least one issue row. It does not need an LLM key or Chrome. An occupied adapter directory is verified rather than overwritten, and any failed stage exits nonzero. Human output shows the row count and issue summaries; the JSON envelope remains machine-readable.

## Generated Adapter Reliability

The configured OpenAI-compatible provider has passed a live preflight and generated a working PyPI search adapter. JSON-mode prompts now include the lowercase `json` token required by some providers, and exploration explicitly numbers recorded actions from zero so a final action is less likely to be omitted. Generated list and table adapters briefly retry an otherwise successful empty extraction after a page interaction; persistent empty results and partial field quality still fail.

The PyPI `search-packages --query` candidate was installed, strictly verified, and queried from a fresh temporary HOME. It remains a **candidate**, not an advertised active demo: the local archive still needs to be attached as a public GitHub Release asset and verified by digest-backed HTTPS installation. The candidate catalog and issue handoffs now use the generated command and can validate one package with `validate_cases.py --case-id` without requiring unrelated candidate packages.

Jev intent lookup now exposes up to three validated ranked candidates and abstention probability for human review. It remains opt-in and read-only; provider accuracy, latency, and cost have not been measured in a live TypeSafe evaluation.

## Verification And Limits

The local package smoke, including one transient PyPI empty-result observation and subsequent repeat passes, is recorded in `docs/user-evidence/2026-09-23-pypi-package-smoke.md`. The release tag, PyPI distribution, public adapter asset, and production website must each be checked after publication; local tests and CI alone do not prove those channels are live. The public Jira service and PyPI search page are third-party dependencies and can change independently of this package.
