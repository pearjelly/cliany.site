# v0.16.360

## First Result From A Clean Install

`cliany-site demo --case-id apache-jira-issues --json` now takes a new user from an empty runtime directory to a real, read-only result. It installs the pinned public Jira adapter only when absent, verifies it strictly, runs the declared query, and requires at least one issue row. It does not need an LLM key or Chrome. An occupied adapter directory is verified rather than overwritten, and any failed stage exits nonzero. Human output shows the row count and issue summaries; the JSON envelope remains machine-readable.

## Generated Adapter Reliability

The configured OpenAI-compatible provider has passed a live preflight and generated a working PyPI search adapter. JSON-mode prompts now include the lowercase `json` token required by some providers, and exploration explicitly numbers recorded actions from zero so a final action is less likely to be omitted. Generated list and table adapters briefly retry an otherwise successful empty extraction; persistent empty results and partial field quality still fail.

When a list/table extraction has no rows because the page is titled `Client Challenge`, the CLI now reports `E_PAGE_NOT_READY` with `reason=site_challenge` instead of a misleading empty search result. It does not bypass the challenge.

The explicitly enabled `browser eval --allow-eval` command now works with the installed browser-use API. It returns JSON-typed results for ordinary expressions and resolved Promises; eval remains disabled by default.

The PyPI `search-packages --query` candidate was installed, strictly verified, and queried from a fresh temporary HOME. Later replays encountered PyPI's `Client Challenge` page, so online reliability is not established. It remains a **candidate**, not an advertised active demo: the local archive still needs to be attached as a public GitHub Release asset and verified by digest-backed HTTPS installation and a successful independent read-only smoke. The candidate catalog and issue handoffs now use the generated command and can validate one package with `validate_cases.py --case-id` without requiring unrelated candidate packages.

Jev intent lookup now exposes up to three validated ranked candidates and abstention probability for human review. It remains opt-in and read-only; provider accuracy, latency, and cost have not been measured in a live TypeSafe evaluation.

## Verification And Limits

The local package smoke, including repeat passes and later challenge-page failures, is recorded in `docs/user-evidence/2026-09-23-pypi-package-smoke.md`. The release tag, PyPI distribution, public adapter asset, and production website must each be checked after publication; local tests and CI alone do not prove those channels are live. The public Jira service and PyPI search page are third-party dependencies and can change independently of this package.
