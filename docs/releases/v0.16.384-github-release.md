# v0.16.384

## Structured Browser Connection Failures

SDK execute/login/save-session/navigation/page-info calls return the existing `CDP_UNAVAILABLE` envelope for typed CDP, connection and timeout errors while acquiring a browser. `phase=browser_connect` and a doctor repair hint let callers handle the failure without exposing private endpoints or raw exception text. Existing HTTP execute/login handlers return JSON 503 instead of a plain-text server error.

Published v0.16.383 reproduced five uncaught SDK failures and two HTTP plain-text 500s against a real unavailable owned endpoint. The source correction retains 26 failing baseline regressions and 10 passing controls. Two real Chromium checks cover same-instance recovery, changed-input semantic replay, navigation/page observation and encrypted cookie persistence. Their probe transition is scripted, not automatic-reconnection evidence. See [the review](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-12-sdk-browser-errors.md) and [Issue 89](https://github.com/pearjelly/cliany.site/issues/89).

The correction changes only acquisition error handling. Cancellation and unknown errors remain distinct; action-phase handling, retry budgets, generated files and existing response shapes are unchanged. No live model was used for this study and no case is promoted. Final-master CI, versioned regression/build/package/readiness, online publication-time capacity, GitHub/PyPI/production checks and fresh official-public-package acceptance remain separate publication gates.
