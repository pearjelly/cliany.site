# v0.16.305

Static adapter verification and runtime preflight now reject symbolic links before they read or import adapter-owned files.

## What Changed

- `verify --strict` rejects a symbolic-link adapter directory, `metadata.json`, `commands.py`, or `manifest.json` as `security_issue` / `E_VERIFY_STATIC` before reading its contents.
- Manifest integrity checks also reject symbolic-link files declared by the manifest, so their digest cannot be read outside the installed adapter directory.
- Root CLI adapter registration, `ClanySite.verify(domain)`, `GET /verify`, `ClanySite.execute()`, and `POST /execute` preserve the same static boundary. HTTP keeps `422` for `E_VERIFY_STATIC` and does not start a browser first.

## Compatibility

Normal adapter directories with ordinary files retain their existing verification and execution behavior. An installation that deliberately uses a symbolic link must be reinstalled as ordinary files from a trusted package, then checked with `cliany-site verify <domain> --strict --json`.

## Trust Boundaries

This release validates a local installed-file boundary. It does not prove that Chrome/CDP, a session, an action replay, a third-party site, GitHub Release, PyPI, Vercel, a candidate adapter package, metadata validation, online smoke, or a live LLM provider is ready or successful. Candidate promotion remains pending on its required evidence.

## Verification

Focused CLI, loader, verify, SDK, and HTTP regressions; full offline tests; package build and Twine validation; required CI; GitHub Release; PyPI; Vercel production deployment; website browser inspection; and strict publication audit are required before release completion.
