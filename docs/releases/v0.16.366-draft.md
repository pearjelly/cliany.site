# v0.16.366 发布草案

**目标版本：** `0.16.366`
**提交范围：** `v0.16.365..HEAD`

## 用户价值

- ASF Confluence 页面搜索从 degraded 晋级 active。用户现在可以运行 `cliany-site demo --case-id apache-confluence-search --json`，由 CLI 按公开包固定 SHA-256 首次安装、严格校验，并执行只读查询；已有 adapter 只验证、不覆盖。
- `demo` 的错误提示和 human 摘要同时适用于 Jira issue 与 Confluence page，不再把 Wiki 故障误称为 Jira 故障。

## 证据与边界

- [公开包独立验收](../user-evidence/2026-10-01-confluence-public-package-audit.md)：PyPI v0.16.365 CLI 从 GitHub Release 下载固定哈希资产，dry-run、安装和严格校验通过，只读查询返回 5 行。
- 新隔离 HOME 中，当前源码的首次 `demo` 返回 `ok=true`、`installed_now=true`、`row_count=6`；重复执行返回 `installed_now=false`、`row_count=6`。离线案例样例已与维护版输出结构对齐。
- 第三方站点可达性和搜索相关度可能变化。历史 v0.14.1 精确标题 adapter 不因此恢复；Jenkins 仍为 degraded，PyPI/npm/crates.io 仍为 candidate。

## 案例库映射

- `cases/manifest.json` 将 Confluence 标为 active；`cases/README.md` 和官网展示新首跑路径。`search-extraction-gap` 保持 known-gap。
- candidate 仍必须先通过真实预检；出现 `llm_live_preflight_not_ready` 时不能推进 explore 或声称生成了可用包。

## 风险与兼容性

- 公开 Confluence 页面与搜索结果可能变化；在线失败时停止后续步骤，不伪造非空结果。已有 adapter 不自动覆盖。

## 发版前验证

- 合并前运行完整测试、Ruff、Mypy、案例严格校验、网站脚本检查、wheel/sdist 和 Twine 检查。
- 仅在最终 master SHA 的普通 CI 与真实浏览器 CI 通过后创建 tag；tag 前执行严格目标与 tagged readiness。
- tag workflow 发布 GitHub Release/PyPI 后，从公网核对精确版本；从 `site/` 部署 Vercel 生产并核对别名，最后运行严格远端分发审计。

## 发版步骤

1. 合并并验证最终 master SHA，确认普通 CI 与真实浏览器 CI 均成功。
2. 创建本地 `v0.16.366` tag，通过严格 tagged readiness 后再推送，由 workflow 发布 GitHub Release 和 PyPI。
3. 部署官网生产，核对 `www.cliany.site` 首页、文档与别名，再运行严格远端分发审计。
