## 用户价值

- 普通 `cliany-site doctor --json` 在 Chrome/CDP 等硬阻塞发生时返回稳定错误码，自动化可以直接选择正确的修复路径。
- `error.details` 继续保留完整 `checks`、`summary` 和 capability 诊断，不牺牲人工排查信息。

## 证据边界

- 本轮只改进本地 doctor 诊断，不代表 Chrome、LLM provider、candidate adapter 或第三方工作流已可用。
- 最近真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 仍返回可重试的 `E_LLM_UNAVAILABLE`；不运行 candidate `explore`，不生成或宣称 package、metadata validation、online smoke。

## 兼容性与风险

- 成功路径、warning 路径、`--require-capability` 门禁、CLI、adapter、SDK、HTTP API 和 release workflow 不变。
- 仅在已有 hard-fail 检查导致 doctor 失败时，将顶层错误码从通用 `E_UNKNOWN` 收敛到既有稳定码；检查明细保持原样。

## 发版前验证

- 运行 doctor focused tests、`CLIANY_QA_OFFLINE=1` 全量测试、Ruff、Mypy、`node --check site/script.js`、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 创建 `v0.16.336`，运行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 alias inspect 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
