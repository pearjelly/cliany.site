# v0.16.296

HTTP API clients now get actionable status codes without losing cliany-site's structured SDK envelope.

## What Changed

- Mutation endpoints reject non-object JSON and invalid `params`, `force`, and `dry_run` types with `400`.
- Missing adapters and commands return `404`; unavailable Chrome or LLM dependencies return `503`; valid but unprocessable workflow outcomes return `422`.
- The README and website SDK examples now include a complete `asyncio.run(main())` entrypoint and envelope-aware error handling.

## Compatibility

Successful responses and `{success, data, error}` fields are unchanged. Clients that previously sent malformed JSON shapes or string control values now receive an explicit `400` instead of relying on implicit conversion or a generic server error.

## Trust Boundaries

This release does not claim a live LLM provider, candidate adapter package, candidate explore, metadata validation, online smoke, or third-party browser workflow succeeded. Candidate promotion evidence remains pending until it is collected and verified.

## Verification

HTTP API and documentation regressions, full offline tests, package build and Twine validation, required CI, GitHub Release, PyPI, Vercel production deployment, website browser inspection, and strict publication audit are required before release completion.
