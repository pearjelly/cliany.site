# v0.16.302

Start active demo cases with a verified, human-readable order.

## What Changed

- `cliany-site cases --status active` now prints a first-run path for each active case: fixed-SHA install, `verify --strict`, declared login when required, then the read-only command.
- Active-case install instructions must be one HTTPS `market install` command with exactly one fixed SHA-256. Shell-control tokens and incomplete install commands are not presented as safe quickstarts.
- README, Chinese README, the case catalog, and the 10-minute guide place strict verification between installation and login or replay.
- The guidance is read-only: it never installs a package, logs in, executes an adapter command, overwrites an adapter, or treats an occupied directory as healthy.

## Compatibility

The JSON catalog and declared case commands remain compatible. The change affects human-first guidance and validation of active remote install instructions. Uppercase SHA-256 values and `--sha256=<value>` remain supported.

## Trust Boundaries

The guidance does not prove that a demo site, browser workflow, GitHub Release, PyPI publication, live LLM provider, or candidate adapter package is ready. It only gives an ordered local handoff for an already-declared active case. Candidate promotion remains pending until its required evidence is collected and verified.

## Verification

Focused case/validation/docs regressions, full offline tests, package build and Twine validation, required CI, GitHub Release, PyPI, Vercel production deployment, website browser inspection, and strict publication audit are required before release completion.
