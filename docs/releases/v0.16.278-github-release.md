# v0.16.278

Candidate adapter generation now has an explicit executable gate instead of relying on a diagnostic warning and a zero exit status.

## What Changed

- Added `cliany-site doctor --require-capability` for `manage_adapters`, `run_browser_workflows`, and `generate_adapters`.
- Candidate promotion now uses `cliany-site doctor --llm-live --require-capability generate_adapters --json` before `explore`.
- An unavailable live provider exits nonzero with its specific error code, including `E_LLM_UNAVAILABLE`, while retaining the complete doctor payload in `error.details`.
- Candidate evidence bundles, planner artifacts, and the standalone evidence extractor can read that strict error envelope and keep the promotion state blocked with the real diagnostic evidence attached.

## Compatibility

Existing `doctor` diagnostics remain non-blocking unless `--require-capability` is requested. The strict `generate_adapters` gate requires `--llm-live` so scripts cannot treat key/config checks as a successful provider preflight.

## Trust Boundaries

This release does not claim live LLM success, a candidate adapter archive, or a third-party online smoke result. A real 2026-07-26 preflight observed `E_LLM_UNAVAILABLE`; candidate cases remain pending until real evidence exists.

## Verification

Regression coverage exercises strict CLI exit behavior, error-code preservation, `error.details` evidence extraction, candidate bundles, planner artifacts, case validation, and release readiness. The full offline suite, package build, and publication workflow remain required before release.
