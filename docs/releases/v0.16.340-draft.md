完成 version bump 后，target-mode readiness 使用 `v0.16.340..HEAD` 作为占位锚点；创建本地 tag 后，release-tag mode 校验实际发布范围 `v0.16.339..HEAD`。

## 用户价值

- 严格 publication audit 现在会对短暂的远端 Git ref 或 GitHub/PyPI JSON 传输失败做两次有限重试，减少真实发布已完成时由短暂 EOF/TLS 中断造成的人工重复审计。
- 持续失败仍输出原有阻断审计证据；HTTP 响应不重试，绝不把无法读取的 GitHub Release、PyPI 或 remote ref 写成发布成功。

## 证据边界

- 本轮只改进本地发布审计的传输恢复，不改变 GitHub、PyPI、Vercel、浏览器或第三方服务的真实状态判断。
- 最近真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 仍返回可重试的 `E_LLM_UNAVAILABLE`；不运行 candidate `explore`，不生成或宣称 candidate package、metadata validation、online smoke、live LLM 或第三方成功。

## 案例库映射

- `cases/README.md` 与 `cases/manifest.json` 保持案例目录为 8 total、4 active、3 candidate、1 known-gap；三个 candidate 的 adapter package、metadata validation、online smoke 仍 pending。
- `search-extraction-gap` 保持 known-gap；`llm_live_preflight_not_ready` 仍是 candidate 晋级前必须修复或重试的 live provider 边界。
- 本轮不修改案例目录，不创建、关闭或改写公网 issue；没有当前 doctor JSON 时也不执行 `--apply --confirm-rewrite`。

## 风险与兼容性

- 重试仅包围远端 ref 与 JSON 读取的传输异常，最多三次尝试；持久 Git 失败仍回到原有 `Remote ref check failed` 审计路径。
- HTTP 错误、版本不匹配、空 release notes、dirty worktree 与任何其他 readiness blocker 保持原有失败语义，不能由重试绕过。

## 发版前验证

- 运行 publication-audit focused tests、发布说明与官网文档回归、`CLIANY_QA_OFFLINE=1` 全量测试、Ruff、Mypy、`node --check site/script.js`、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check`。
- 版本最终化后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --target-version 0.16.340 --remote`；创建本地 tag 后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.340 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 运行 `git tag v0.16.340`，再执行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 alias inspect 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
