# v0.16.374 发布草案

**目标版本：** `0.16.374`
**提交范围：** `v0.16.373..HEAD`（以最终 master 为准）
**状态：** 候选；最终 master 门禁和上海时间线上发布配额通过后才能推送 tag。

## 用户价值

- 浏览器列表提取和生成命令的质量输出标记 `row_limit=100` 与 `limit_reached`，避免把达到上限误读为已收集全部结果；字段质量仍独立报告。
- 快速入门和官网链接公开的 Python 文档站只读候选适配器试用流程，使用固定 SHA-256 安装、严格验证和改参回放，并收集独立用户反馈。

## 验证证据

- 固定公开包在隔离运行目录中安装、严格验证，并以 `pathlib` 改参回放；首条标题和链接与独立浏览器一致，100 行上限得到标记。
- 代码需通过离线、具身 Chromium、Python 3.11-3.13、Windows、Ruff、Mypy、官网脚本、构建与 Twine 检查；PR 和最终 master CI 必须均通过。

## 案例库映射

`cases/manifest.json` 和 `cases/README.md` 保留原有 active/candidate 状态，`search-extraction-gap` 不变。Python 文档站仍是浏览器生成的 candidate，不加入 active 或 `demo`；PyPI、npm 与 crates.io 的候选门禁也不因本版变化自动通过。若 live doctor 返回 `llm_live_preflight_not_ready`，停止真实探索并记录阻塞。

## 风险与兼容性

新增质量字段是加法式 JSON 变更；`limit_reached=true` 仅表示返回长度达到上限，并不证明页面有更多结果。公开 Python 文档适配器仍缺独立首次用户验收；一个 macOS 维护者环境的合成 OS `HOME` 会使 Chrome 外部导航超时，具体机制尚未确认。本版不改 Chrome 启动环境、不扩大列表上限、不宣称普遍可靠性。

## 发版前验证

1. 在最终 master SHA 运行完整离线测试、具身 Chromium、Ruff、Mypy、`uv lock --check`、官网脚本和案例严格校验；构建 wheel/sdist 并运行 Twine 检查。
2. 确认最终 master 的普通和 Embodied CI 均通过，运行 `uv run python scripts/check_github_release_cap.py --strict --json`，达到上海时间当日 3 次上限时停止。
3. 运行 `uv run python scripts/release_readiness.py --strict --target-version 0.16.374 --remote --remote-name origin`；通过后创建本地 tag `v0.16.374`，再以 `--release-tag v0.16.374` 严格验证后推送。

## 发版步骤

1. 推送 `v0.16.374`，等待 GitHub Release 和 PyPI 精确版本公开；核对 reviewed Release notes。
2. 在 `site/` 执行 `vercel link --yes --project cliany.site`、`vercel --prod --yes`，核查生产别名和版本。
3. 从干净 master 运行 `scripts/check_release_publication.py --strict --remote --distribution --json`。独立首次用户由 Issue #55 验收，维护者试验不代替。
