# v0.16.310 发布草案

**目标版本：** `0.16.310`
**提交范围：** `v0.16.309..HEAD`
**提交范围：** `v0.16.310..HEAD`
**发布主题：** 让 doctor 的嵌套生成能力在 provider 未预检时给出可执行的安全下一步。

完成 version bump 后，target-mode readiness 会检查占位锚点 **提交范围：** `v0.16.310..HEAD`；该锚点不改变实际 release diff。

## 用户价值

默认 `doctor --json` 不调用 provider。此前它已经提供 `ready_for_live_explore=false`，但本地配置就绪时，嵌套 `capabilities.generate_adapters.next_step` 仍写作可直接运行 `explore`。这会让只读取 capability 的调用方看到相互矛盾的引导。

本版保留既有 `generate_adapters.ready` 兼容的本地语义，并新增 `local_ready` 和 `live_blockers`。当本地前提已满足但尚未做 live preflight 时，`live_blockers=["llm_live_preflight"]`，`next_step` 给出精确的严格预检命令；预检成功后 `live_blockers=[]`。本版不把本地配置、Chrome 或 provider key 伪装为 live LLM 成功。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 中维护的四个 active case、三个 candidate package-search case 与 `search-extraction-gap` known gap 均不变。
- 最新真实严格预检仍为 retryable `E_LLM_UNAVAILABLE` / connection error；`doctor_preflight_state.reason_codes` 包含 `llm_live_preflight_not_ready`，candidate 的 adapter package、metadata validation 与 online smoke 仍是 pending。
- 本版不生成、安装或发布 candidate adapter package，也不声称 third-party workflow、metadata validation、online smoke 或 live LLM 成功。

## 风险与兼容性

- 既有 `ready_for_explore` 与 `generate_adapters.ready` 的本地语义保持不变；需要真实 provider 证据的调用方仍须读取 `ready_for_live_explore`。
- 新字段只改善本地诊断和引导，不建立浏览器会话、action replay、第三方站点、GitHub Release、PyPI 或 Vercel 就绪证据。

## 发版步骤

1. 仅在 v0.16.309 已完整发布且版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.310`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.310 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.310`。
5. 在 `site/` 运行 Vercel production 部署并浏览 `www.cliany.site`；严格 publication audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.310` makes the nested adapter-generation capability guide automation to a real provider preflight before `explore`, while preserving existing local readiness fields.
