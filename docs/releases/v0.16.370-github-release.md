# v0.16.370

## More Trustworthy Browser-Generated Search Commands

Generated list and table commands now wait for repeated identical results before returning. A client-rendered list that keeps changing reports `E_PAGE_NOT_READY` instead of succeeding with a partial snapshot. The existing 100-item list limit remains; this change does not claim full retrieval of larger result sets.

Exploration now lets a search or filter command allow zero matches when the requested workflow explicitly calls for that case. A malformed final command partition gets one non-executing correction request, with strict validation still rejecting newly proposed actions or a second invalid partition. The response reports whether that correction was attempted.

For a first-time user without an LLM key, `doctor` now explains that a missing `AGENT.md` does not affect installation or use of an existing adapter. Its suggestion to run `explore` is reserved for generating a new adapter after an LLM preflight.

An opt-in fresh-browser benchmark adds independent page-result checks. Three controlled tasks scored 8/9 on one clean, single-provider baseline. Separately, three fresh explorations of the public Python documentation produced reusable search commands; all six changed-query replays matched the browser's first 100 titles and links after search completion. These small samples are evidence for those specific tasks, not a general reliability rate.

A later fixed-commit follow-up ran 10 fresh trials per controlled task and passed 27/30 independent replays: form 10/10, filter 7/10, and semantic target 10/10. All 35 replays that returned success matched the page-DOM oracle, but filter exploration had a quality-gate failure and a 300-second timeout, and one positive-query replay failed explicitly. The filter path and latency outliers remain open work; this score is not a general reliability claim.

A separate filter-only diagnostic run scored 9/10 and reproduced a model-generated `url` field blank in every result, even though the task asked only for count and package names. One-time completion feedback now names such blank fields and asks for a real field or removal only when optional; it does not waive the quality gate. This feedback change has deterministic coverage, but its live impact is still unverified.

The repair path can now omit an extract action that the completion gate already proved failed, while requiring every other recorded action exactly once and a new successful extract. Deterministic tests cover a corrected extraction, a still-partial correction, and rejection of missing required actions. Live impact remains unverified because two post-change provider preflights timed out before any trials.

`python-docs-search` enters the case catalog as a **candidate**. Its generated adapter passed local packaging, strict verification, and a separate read-only replay, but a fixed-SHA public Release download and published-version smoke are still required before promotion. The maintained Jira, Confluence, Jenkins, and SuiteCRM active cases are unchanged.
