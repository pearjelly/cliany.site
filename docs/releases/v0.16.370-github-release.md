# v0.16.370

## More Trustworthy Browser-Generated Search Commands

Generated list and table commands now wait for repeated identical results before returning. A client-rendered list that keeps changing reports `E_PAGE_NOT_READY` instead of succeeding with a partial snapshot. The existing 100-item list limit remains; this change does not claim full retrieval of larger result sets.

Exploration now lets a search or filter command allow zero matches when the requested workflow explicitly calls for that case. A malformed final command partition gets one non-executing correction request, with strict validation still rejecting newly proposed actions or a second invalid partition. The response reports whether that correction was attempted.

An opt-in fresh-browser benchmark adds independent page-result checks. Three controlled tasks scored 8/9 on one clean, single-provider baseline. Separately, three fresh explorations of the public Python documentation produced reusable search commands; all six changed-query replays matched the browser's first 100 titles and links after search completion. These small samples are evidence for those specific tasks, not a general reliability rate.

`python-docs-search` enters the case catalog as a **candidate**. Its generated adapter passed local packaging, strict verification, and a separate read-only replay, but a fixed-SHA public Release download and published-version smoke are still required before promotion. The maintained Jira, Confluence, Jenkins, and SuiteCRM active cases are unchanged.
