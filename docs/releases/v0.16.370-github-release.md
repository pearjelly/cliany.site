# v0.16.370

## One Command from Doctor to a Read-Only Result

The human-readable `cliany-site doctor` output now offers one copyable `demo --case-id ... --json` command when a published, active, no-login example is available. The demo installs its verified public adapter only when the target is absent, runs strict verification, and returns a nonempty read-only result or fails nonzero. The machine-readable doctor fields and live LLM preflight contract are unchanged.

In a clean maintainer HOME, the suggested Jira command installed and verified the published adapter and returned five nonblank SPARK issue rows. This is an API-backed example, not evidence that a model generated a browser workflow. It also does not replace the independent first-time user trials still requested in [Issue #33](https://github.com/pearjelly/cliany.site/issues/33).

The public roadmap now links the [October value plan](https://github.com/pearjelly/cliany.site/blob/master/docs/plans/2026-10-02-october-value-plan.md). The controlled browser-generated command study remains draft: its 25/30 strict replay result is below the 27/30 target and is not part of this release. PyPI, npm, and crates.io search cases remain candidates where normal site access or online result verification is missing.
