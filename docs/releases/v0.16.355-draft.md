# v0.16.355 发布草案

**目标版本：** `0.16.355`

**提交范围：** `v0.16.355..HEAD`（target-mode readiness）
**提交范围：** `v0.16.354..HEAD`（release-tag readiness）

## 用户价值

修复真实 demo 审计发现的安装门禁缺口：包哈希正确但 v3 metadata 不合格时，market install 和 dry-run 都在替换现有安装前失败，返回具体字段错误。`--force` 不绕过校验，不创建无意义备份。旧版包仍可安装后迁移。

## 案例库映射

`cases/README.md` 与 `cases/manifest.json` 的 Jenkins 案例改为 degraded；当前为 3 active、3 candidate、1 degraded、1 known-gap。`search-extraction-gap` 未关闭。Jira 真实返回五条 issue，Confluence 返回空列表，Jenkins 的公开固定哈希 archive 缺少必填字段，详见 `docs/user-evidence/2026-09-22-active-demo-audit.md`。没有编辑历史生成 adapter。上轮 live provider TLS 故障仍保留为 `llm_live_preflight_not_ready`，本轮未执行 candidate explore。

## 风险与兼容性

以前能被安装但无法严格 verify 的 v3 包现在会在安装前拒绝；请维护者修复后重新发布。legacy 安装迁移行为保留。增加显式 jsonschema 运行时依赖。安装预检不执行包内 Python，也不证明浏览器或第三方服务可用。

## 发版前验证

- marketplace 回归覆盖缺失字段、domain 不符、错误字段类型、非对象 JSON、JSON 语法错误，以及 dry-run/force 下的原安装和备份保留。
- 完整离线测试、Ruff、Mypy、JS syntax、lock、strict cases、build/Twine。
- target readiness：`python scripts/release_readiness.py --strict --target-version 0.16.355 --remote`。

## 发版步骤

1. 推送 master，等待最终 SHA 的 CI 与 Embodied CI success。
2. `git tag v0.16.355`，执行 `python scripts/release_readiness.py --strict --release-tag v0.16.355 --remote --remote-name origin` 后推送 tag。
3. 等待 Release workflow，核验 GitHub Release 和 PyPI 精确版本/latest。
4. 从 site 链接 cliany.site，部署 production 并检查 aliases、真实浏览器 home/docs/console。
5. `python scripts/check_release_publication.py --strict --remote --distribution --json`。
