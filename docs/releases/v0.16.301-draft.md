# v0.16.301 发布草案

**目标版本：** `0.16.301`

**提交范围：** `v0.16.301..HEAD`
**发布主题：** 让已识别但无法注册的 adapter 在根 CLI 给出可执行的静态验证错误，而不是伪装成未知命令。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.301..HEAD`；该锚点不改变实际 release diff。

## 用户价值

已安装 adapter 的 metadata 可能仍符合当前 schema，但其 `commands.py` 缺失、不是普通文件、无法导入，或没有导出 `click.Group` 类型的 `cli`。此前用户执行 `cliany-site <domain> <command>` 时会收到模糊的未知命令结果，难以区分拼写错误、未安装 adapter 和损坏的 adapter。

本版保存 loader 的 `domain`、`verdict` 和 `reason` 诊断。根 CLI 遇到这类当前 schema adapter 时返回 `E_VERIFY_STATIC`，并给出 `cliany-site verify <domain> --strict --json` 的修复入口；JSON 信封可供自动化按 `schema_error`、`commands_missing` 或 `commands_unloadable` 分支处理。

无效的 metadata JSON 不再阻断 adapter discovery 或 CLI 启动：非对象 metadata 会作为可定位的 `schema_error` 返回，其他有效 adapter 仍可被注册并执行。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不改变案例、adapter package 或浏览器运行时行为。
- candidate 的九项 promotion evidence 仍为 pending。2026-08-04 最近一次真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回可重试 `E_LLM_UNAVAILABLE`，并记录 `llm_live_preflight_not_ready` blocker。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、第三方工作流或 live LLM 成功。

## 风险与兼容性

- 已成功注册的 adapter、内置命令和 legacy adapter migration 路径保持不变。
- 行为变化只覆盖已发现且无法加载的 current-schema adapter：此前的未知命令改为带 `E_VERIFY_STATIC` 的具体诊断和修复提示。
- loader 仍仅为注册 adapter 而加载其 `commands.py`；本版不把 adapter 模块加载解释为 browser、LLM 或第三方工作流成功。
- 本版不代表 live LLM、candidate workflow、candidate adapter package 或第三方站点操作成功。

## 发版步骤

1. 在实际可发布日期完成版本、CHANGELOG、官网基线和路线图 finalization；只有 finalization 后的 CI 可以作为 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.301`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.301 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.301`。
5. 运行 `gh release edit v0.16.301 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.301-github-release.md`，再用 `gh release view v0.16.301 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.301` makes an unloadable installed adapter actionable at the root CLI, preserving compatible working commands while giving people and automation a strict verification path before any browser or LLM work.
