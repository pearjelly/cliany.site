## 用户价值

- 真实保存的适配器可经 CLI、SDK、HTTP、workflow、串行 batch 返回改变输入后的结果；显式 CDP 路由不操作备用浏览器。
- 修复动作被跳过、重复派发、跨命令参数串用、跨页面同名目标误去重，以及提取结果或错误被组合入口丢失的问题。
- 录制语义优于旧编号，冲突名称/角色和最高分并列不再任意命中。模型修复与视觉候选也检查记录语义；这不是通用消歧保证。
- 导航前恢复保存的 Cookie，过期会话阻止导航。内置批量执行器串行运行完整命令，避免共享浏览器与 CLI 输出的线程竞争。
- 探索步数耗尽、损坏回答、缺失命令、错误动作分区不再伪装为完成。
- Jev 提供显式 opt-in 的只读意图定位，不生成操作、不自动点击。需要 TypeSafe 密钥与外发许可；未实测真实模型收益。

## 风险与兼容性

- 旧生成文件不会自动改写。依赖模板、参数归属与去重修复的适配器需要重新探索/生成，先保留旧包，再用变化输入验收。
- 内置 `workflow batch --concurrency N` 现在固定串行并警告；自定义执行器仍可并发。跨进程共享同一浏览器、并行浏览器隔离、明确目标 tab 不在当前保证范围。
- 过去的假成功现在可能返回非零退出或结构化失败；调用方必须检查状态，不应只检查是否有输出。
- 工作流和原子命令要求 stdout 为单个 JSON 对象；诊断放 stderr。显式 `ok` 优先于旧 `success`。
- 名称或角色改变可能要求重新探索。名称包含关系仍允许模糊匹配；仅编号记录仍按编号执行。
- 会话仅验证 Cookie 首次加载恢复，未实现完整 localStorage 恢复或第三方登录验收。
- Jev 会发送用户意图、元素名称和角色，名称仍可能包含敏感内容。禁止宣称其延迟、成本或准确率已经提升。

## 发版步骤

1. 9 月 23 日或之后，先检查是否已有未完成发布；在干净的发布检出拉取最新 master。保留其他任务的 `docs/reviews/`，不删除、不暂存为本版文件。
2. 运行 `python scripts/release_readiness.py --strict --target-version 0.16.357 --remote`，核对日上限和草案；若目标版本已被使用，重新规划，不重复标签。
3. 按现有发布工具升版，移动 Unreleased 到带实际日期的发布条目，同步路线图与官网内容；检查新增依赖 httpx 的锁文件和分发包。
4. 构建并验证包，推送最终 master，等待该精确 SHA 的 CI 与 Embodied CI success。此时才能将候选说明作为已发布说明使用。
5. 创建 `v0.16.357`，运行 `python scripts/release_readiness.py --strict --release-tag v0.16.357 --remote --remote-name origin` 后推送 tag；等待 Release workflow。
6. 核验 GitHub Release 资产与 PyPI 精确版本，再从 `site/` 执行 `vercel link --yes --project cliany.site` 和 `vercel --prod --yes`。
7. 核验生产域名及 home/docs/console，执行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。失败则保持发布未完成，不以标签存在代替三端验收。

下一阶段仍需真实模型探索、三个公开只读任务的独立结果验收，以及外部用户首次上手证据。
