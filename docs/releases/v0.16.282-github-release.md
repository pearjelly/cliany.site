# v0.16.282

Explicit adapter verification now fails early when the requested adapter has not been installed.

## What Changed

- `cliany-site verify <domain> --json` now returns a nonzero `ADAPTER_NOT_FOUND` envelope instead of a successful empty result when that adapter is absent.
- The envelope includes `error.details.domain` and explains that `market install --dry-run` only validates a package; remove `--dry-run` to install before verifying.
- Batch `cliany-site verify --json` keeps its existing empty-success behavior when no adapters are installed.

## Compatibility

Scripts that explicitly verify a missing adapter now receive the intended nonzero result. Use `error.code=ADAPTER_NOT_FOUND` and `error.details.domain` to guide the next action. Verification of installed adapters and marketplace overwrite protection are unchanged.

## Trust Boundaries

This release does not install, overwrite, or delete an adapter. It does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result. Candidate cases remain pending until their required evidence is attached.

## Verification

Focused verification and documentation tests, the full offline suite, package build, Twine metadata validation, required CI workflows, GitHub Release, PyPI, Vercel production deployment, browser inspection, and strict publication audit are required before this release is complete.
