# v0.16.338

## Changed

- Python SDK `doctor()` and HTTP `GET /doctor` now reuse the CLI structured checks, summary, stable hard-blocker errors, and repair diagnostics.
- SDK callers can opt into the existing live-provider preflight with `doctor(llm_live=True, require_capability="generate_adapters")`; HTTP supports the equivalent `llm_live=true` and `require_capability` query parameters.
- SDK custom CDP ports now reach the same doctor check path as the CLI.

## Compatibility

- Existing SDK success and error envelopes remain available. Full doctor diagnostics are additionally present in `data` and `error.details` for structured repair handling.
- Default SDK and HTTP doctor requests remain local-only. Invalid HTTP booleans return `400`; unavailable Chrome, provider, or required capability results preserve the envelope and use `503`.

## Trust Boundaries

- This release contains no candidate adapter package, metadata validation, online smoke, live LLM success, browser workflow result, or third-party workflow claim.
- A live provider preflight is explicit and remains gated; the latest real preflight was retryably unavailable.
