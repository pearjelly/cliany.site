# v0.16.342

## Fixed

- `GET /adapters?detail=` now shares the HTTP API's strict boolean parsing. Use `true`/`false`, `1`/`0`, or `yes`/`no` to request the compact or metadata-rich adapter list.
- Invalid `detail` values now return `BAD_REQUEST` with HTTP `400` instead of silently falling back to the compact response, so integrations can detect a response-shape mistake immediately.

## Compatibility

- Omitting `detail` still returns the compact list. Existing valid true and false spellings keep their behavior.
- This changes only the HTTP query-parameter boundary; CLI commands, adapters, SDK methods, and workflow execution are unchanged.

## Trust Boundaries

- A valid local API response does not establish Chrome, live LLM, candidate adapter, or third-party workflow readiness.
- This change does not create a candidate adapter package or validate candidate metadata or online smoke evidence.
- Candidate adapter package promotion remains gated on a real successful live LLM provider preflight.
