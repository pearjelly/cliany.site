# v0.16.293

Candidate case handoffs now state plainly when an adapter command is not runnable yet.

## What Changed

- Human `cliany-site cases` output labels a candidate's future adapter command as unavailable until the package is published and installed and `verify --strict` passes.
- Candidate preflight and promotion commands remain visible for maintainers, but the later adapter command is no longer presented like an active demo quick command.
- README, case-maintainer guidance, and the website FAQ explain the same boundary.

## Compatibility

The cases JSON schema, candidate promotion plan, issue template, and evidence bundle contracts are unchanged. Active demo commands remain runnable according to their published package and verification path.

## Trust Boundaries

This release does not claim a live LLM preflight, candidate explore, adapter package, metadata validation, online smoke, or third-party browser workflow succeeded. Candidate promotion evidence remains pending until it is collected and verified.

## Verification

Cases CLI and documentation regressions, full offline tests, package build and Twine validation, required CI, GitHub Release, PyPI, Vercel production deployment, website browser inspection, and strict publication audit are required before release completion.
