# v0.16.379

## First Generation Preserves Its Evidence

Fresh browser exploration no longer mistakes an extract/snapshot-only directory for an installed adapter. It retains the observed starting URL, including its path, and model provenance instead of losing them through an empty merge. Existing adapters and generated modules are not automatically rewritten; partial core artifacts retain their previous merge handling.

The opt-in controlled benchmark compares returned row counts, order and values, rejecting extra, duplicate or contradictory collections. New reports name the `per-row-v2` oracle. Historical summaries did not retain raw output and cannot be rescored under this stronger rule.

## Verification and Limits

The source fix passed eight focused first-install regressions, 3,291 offline tests, static checks and ordinary/Chromium CI. A fresh live source generation retained the original Python docs URL and model, passed strict verification and returned a changed-query prefix matching the independent page; its declared nonempty negative query failed closed.

A public-v0.16.378 controlled matrix passed 9/9 explorations and 12/12 output/DOM replays under the new oracle, but one generation took 264.62 seconds after two provider timeouts. Three public Python docs generations reproduced the fixed metadata bug; all six positive replays matched 100-row prefixes, not complete collection. One original negative probe assumed empty results must fail, although the third command explicitly allowed them; the failed probe record is retained and the declared contract is documented.

This is bounded maintainer evidence, not a general success rate, latency improvement, case promotion or alpha-readiness claim. Independent first-user acceptance remains open. Published-package and production acceptance are separate post-publication gates.
