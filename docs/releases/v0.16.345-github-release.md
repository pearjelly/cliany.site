# v0.16.345

## What Changed

- `POST /explore`, `POST /execute`, and `POST /login` now reject array, object, and blank values for required text fields with `BAD_REQUEST` / HTTP `400` before calling the SDK.
- `workflow_description` remains supported when `workflow` is absent; an explicitly supplied invalid `workflow` no longer falls through to that alias.

## Compatibility

Valid non-empty string requests keep their existing behavior. This change only makes malformed write requests deterministic and avoids accidental server errors.

## Trust Boundaries

This is a local HTTP API validation change. It does not establish Chrome availability, live LLM success, candidate adapter package availability, metadata validation, online smoke, or third-party workflow success.
