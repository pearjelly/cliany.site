# v0.16.373

## More Trustworthy Browser-Generated Commands

Generated read-only extraction now checks the current accessibility-tree evidence before accepting a selector. List extraction waits for results to settle in both direct action replay and generated browser commands; an unsettled page returns `E_PAGE_NOT_READY` instead of a valid-looking partial result. Blank scalar text no longer counts as a successful zero-match search.

Noninteractive exploration gets one bounded continuation when a model declares commands without recording actions, plus one constrained attempt to repair an invalid command-action partition. If the repair is invalid, generation stops without writing a misleading adapter. Extract output also stays inside the configured runtime home.

PR #47 passed full CI and a clean, fixed-head 30/30 controlled sample; all 40 changed-input replays matched returned values and independent DOM. The sample had a 186.4-second exploration p95 and no live partition-repair attempts, so it is not a general reliability estimate. Three maintainer-run Python documentation browser trials passed. The [adapter archive](https://github.com/pearjelly/cliany.site/releases/download/v0.16.373/docs.python.org-0.1.0.cliany-adapter.tar.gz) is public (SHA-256 `29f1ece48fd6749e53cf7384f5be0878c1617d1d8344641e284b6c37150f6592`); a maintainer installed it with the published PyPI package in an isolated runtime directory, strictly verified it, and replayed a changed query in Chromium. The adapter remains a candidate: extraction is capped at 100 rows, a wholly synthetic OS `HOME` hit first-navigation timeouts, and independent first-user feedback is still pending.
