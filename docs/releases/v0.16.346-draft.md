## 用户价值

- `POST /explore`、`POST /execute` 与 `POST /login` 现在会在调用 SDK 前拒绝未知 JSON 字段，稳定返回 `BAD_REQUEST` / HTTP `400`，不再悄悄丢弃客户端的拼写错误。
- 各端点只接受已记录的字段；`POST /explore` 仍兼容 `workflow_description`，但只在 `workflow` 缺席时使用。

## 证据边界

- 2026-08-31 的真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回可重试的 `E_LLM_UNAVAILABLE` / `llm_live_preflight_not_ready`；不运行 candidate `explore`，不生成或宣称 candidate package、metadata validation、online smoke、live LLM 或第三方成功。

## 案例库映射

- `cases/README.md` 与 `cases/manifest.json` 仍记录 8 total、4 active、3 candidate、1 known-gap。
- `search-extraction-gap` 仍是 known-gap；三个 candidate 的 adapter package、metadata validation 与 online smoke 仍 pending。

## 公开 issue

- 最近 candidate issue 只读审计因可重试的 `E_GITHUB_UNAVAILABLE` / GraphQL EOF 失败；它不是 `missing`，不会创建、关闭或改写公网 issue。
- 没有当前 doctor JSON 时，不执行 `--apply --confirm-rewrite` 覆盖含 Doctor Preflight Evidence 与 64 位 values hash 的公开 issue。

## 风险与兼容性

- 只有包含未知字段的写请求从此前可能被忽略的行为改为明确 `400`；各端点的已记录字段、合法值以及 `workflow_description` 兼容路径保持不变。
- 这是本地 HTTP API 边界修复，不表示 Chrome、LLM、candidate adapter 或第三方站点已可用。

## 发版前验证

- 运行 SDK/API、发布说明与官网文档 focused tests、`CLIANY_QA_OFFLINE=1` 全量测试、Ruff、Mypy、`node --check site/script.js`、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check`。
- 版本最终化后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --target-version 0.16.346 --remote`；创建本地 tag 后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.346 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 运行 `git tag v0.16.346`，再执行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 alias inspect 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
