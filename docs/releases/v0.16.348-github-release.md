# v0.16.348

## What Changed

- `ClanySite.explore()` and `ClanySite.login()` now share the strict HTTP(S) URL validation used by the HTTP API.
- Invalid schemes, missing hosts, malformed ports, whitespace-containing URLs, and non-string values return `INVALID_URL` before browser-facing SDK work begins.

## Compatibility

Valid HTTP(S) URLs and all other SDK methods retain their existing behavior. `POST /execute` is unchanged.

## Trust Boundaries

This is a local SDK input-validation change. It does not establish Chrome availability, live LLM success, candidate adapter package availability, metadata validation, online smoke, or third-party workflow success.
