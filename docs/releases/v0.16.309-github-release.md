# v0.16.309

`doctor --json` now distinguishes local setup from a successfully tested LLM provider before automation starts a real `explore`.

## What Changed

- Added `summary.ready_for_live_explore` and `capabilities.generate_adapters.ready_for_live_explore`.
- These fields are true only after `doctor --llm-live --require-capability generate_adapters --json` succeeds.
- `ready_for_explore` keeps its local configuration compatibility meaning, so existing consumers are not silently redefined.

## Compatibility

Existing `ready_for_explore` consumers continue to receive the local prerequisite result. Automation that requires live provider evidence should use `ready_for_live_explore` or the strict preflight command.

## Trust Boundaries

This is a provider-connectivity gate only. It does not establish a browser session, action replay, third-party website success, candidate adapter package, metadata validation, online smoke, GitHub Release, PyPI, or Vercel readiness.

## Verification

Focused doctor, CLI, documentation, and release-document regressions; full offline tests; package build and Twine validation; required CI; GitHub Release; PyPI; Vercel production deployment; website browser inspection; and strict publication audit are required before release completion.
