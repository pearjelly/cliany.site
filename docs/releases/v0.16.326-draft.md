## 用户价值

- `doctor --llm-live --require-capability <capability> --json` 在底层检查失败时仍保留 `checks`、`summary` 和 blockers，并返回首个硬阻塞项的稳定错误码；没有 Chrome/CDP 时自动化得到 `E_CDP_UNAVAILABLE`，provider 不可用时保留 `E_LLM_UNAVAILABLE`。
- README、quickstart、公开路线图和官网同步这条机器可读修复路径，维护者可以先修复正确依赖再重试，不会把通用 `E_UNKNOWN` 当成可执行信号。

本轮发布资料引用 `cases/README.md`、`cases/manifest.json`、`search-extraction-gap` 和 `llm_live_preflight_not_ready` 作为案例目录与候选门禁边界；这些引用不代表 candidate 已晋级。

## 案例库映射

- active 案例和 candidate 案例状态不变；candidate adapter package、metadata validation、online smoke 仍未有证据。
- 最近真实 `doctor --llm-live --require-capability generate_adapters --json` 未通过，当前环境缺少可用 CDP，LLM live 也不可宣称成功；本轮没有运行 candidate `explore`。

## 风险与兼容性

- 只改变 doctor 能力门禁失败时的错误码和诊断承载位置；成功路径、普通 `doctor`、CLI adapter 命令、SDK、HTTP API、案例状态和 release workflow 不变。
- `error.details.checks` 与 `error.details.summary` 是诊断证据，不代表 Chrome、LLM provider、candidate package 或第三方工作流可用。

## 发版前验证

- 运行 `pytest tests/test_doctor.py -q --no-cov` 和相关 CLI 回归。
- 运行 `node --check site/script.js`、`CLIANY_QA_OFFLINE=1` 全量测试、Ruff、Mypy、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check dist/*`。
- 运行 `python scripts/release_readiness.py --strict --target-version 0.16.326 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 创建 `v0.16.326`，运行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复，不继续发布。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 `vercel inspect www.cliany.site` 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
