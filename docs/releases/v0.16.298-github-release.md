# v0.16.298

The HTTP liveness probe can now identify the installed cliany-site version without overstating runtime readiness.

## What Changed

- `GET /health` now returns `status`, `service`, and the installed package `version`.
- A source-only environment without distribution metadata returns `version="unknown"` instead of failing the health endpoint.
- The README and website distinguish liveness/version from Chrome/CDP and LLM diagnostics, which remain available through `GET /doctor`.

## Compatibility

The existing `status="ok"` health response, HTTP status codes, SDK envelope, and `/doctor` behavior are unchanged. `service` and `version` are additive fields for deployment tooling and API clients.

## Trust Boundaries

`GET /health` proves only HTTP reachability and reports the installed package version. This release does not claim a live LLM provider, candidate adapter package, candidate explore, metadata validation, online smoke, or third-party browser workflow succeeded. Candidate promotion evidence remains pending until it is collected and verified.

## Verification

Focused API and documentation regressions, full offline tests, package build and Twine validation, required CI, GitHub Release, PyPI, Vercel production deployment, website browser inspection, and strict publication audit are required before release completion.
