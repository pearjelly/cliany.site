# v0.16.359

## Accurate Provider Preflight

`doctor --llm-live` now checks the API key for the provider actually selected for exploration, including an exploration-specific provider override. A key for another provider no longer makes the selected path appear ready. The OpenAI-compatible base URL check also follows the exploration-specific override.

HTTP 401/403 authentication failures now return non-retryable `E_LLM_AUTH_FAILED` with status and safe next steps. Upstream response bodies and low-level exception text are not included in the JSON diagnostic. Integrations that switch on exact doctor error codes should recognize the new code.

The configured OpenAI-compatible endpoint remains blocked by a TLS connection closure, and an alternate Anthropic-compatible endpoint returned HTTP 401. No live adapter generation, candidate promotion, or Jev accuracy result is claimed by this release.
