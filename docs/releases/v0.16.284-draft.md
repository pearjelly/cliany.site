# v0.16.284 发布草案

**目标版本：** `0.16.284`
**提交范围：** `v0.16.283..HEAD`
**发布主题：** 让 marketplace dry-run 在需要显式覆盖前，提供当前已安装 adapter 的版本事实。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.284..HEAD`；该锚点不改变实际 release diff。

## 用户价值

`market install <package> --dry-run --json` 已经会返回 incoming package 的 `version`、`would_replace` 和 `requires_force`。本版补充 `installed_version`：当 `would_replace=true` 时，用户或自动化可以在选择 `--force` 前并排审阅当前已安装版本与包内版本。

`installed_version=null` 不等于 adapter 不存在。`would_replace` 仍是存在性事实；`null` 仅表示没有可安全读取的现有版本，或没有已安装 adapter。系统不推断升级或降级，不自动覆盖，也不会让 dry-run 授权后续真实安装。

本地包与固定 SHA-256 远程包都共享这一只读计划。真正重复安装不带 `--force` 仍返回非零 `INSTALL_FAILED`，并在写入 `commands.py`、`metadata.json`、创建 backup 或删除文件前停止。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 继续定义四个 active case、三个 candidate package-search case，以及已知缺口 `search-extraction-gap`。
- 本版不创建、下载、安装、覆盖或声明任何 candidate adapter asset；已发布 active demo 的安装、verify、只读命令顺序不变。
- `llm_live_preflight_not_ready` 仍然约束 candidate 晋级；没有真实 live preflight、adapter package、metadata validation 和 online smoke 证据时，candidate 保持 pending/blocked。

## 变更分组

### Dry-run 覆盖版本事实

- 新安装返回 `installed_version=null` 与 `would_replace=false`。
- 已安装 adapter 的本地和远程 dry-run 返回 `installed_version`；空、损坏或缺失的版本元数据归一为 `null`，同时保留 `would_replace=true` 和 `requires_force=true`。
- `--dry-run --force` 仍只描述 potential backup；它不会创建 backup 或写入 adapter。
- 远程固定 SHA-256 dry-run 仍会在校验后清理下载临时文件，不保留 adapter 或 backup 写入。

## 风险与兼容性

- 这是 JSON 的新增字段。宽松解析器保持兼容；严格 key-set 校验的调用方应接受 `installed_version`。
- 版本字符串不承诺 PEP 440 或 SemVer 语义；调用方负责自己的版本策略。
- `requires_force` 与真实安装保护保持原语义；exit 0 仅表示包校验和只读计划成功。
- 本版不伪造第三方 adapter、live LLM、candidate package、metadata validation 或 online smoke 成功。

## 发版步骤

1. 完成版本、CHANGELOG、官网基线、reviewed GitHub Release Notes 和本草案，在干净 HEAD 运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.284`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.284 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.284`。
5. 运行 `gh release edit v0.16.284 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.284-github-release.md`，再用 `gh release view v0.16.284 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。
