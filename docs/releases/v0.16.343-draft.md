完成 version bump 后，target-mode readiness 使用 `v0.16.343..HEAD` 作为占位锚点；创建本地 tag 后，release-tag mode 校验实际发布范围 `v0.16.342..HEAD`。

## 用户价值

- `GET /adapters?detail=` 与 `GET /doctor?llm_live=` 现在要求布尔查询参数最多出现一次；`?detail=true&detail=false` 或重复 `llm_live` 返回 `BAD_REQUEST` / HTTP `400`，不再由请求参数顺序决定行为。
- 现有的合法 `true`/`false`、`1`/`0`、`yes`/`no` 单值参数保持兼容，省略参数也保持默认行为。

## 证据边界

- 本轮只收紧 HTTP API 的本地查询参数边界，不改变 CLI、adapter、SDK、Chrome、LLM、案例状态或第三方工作流的就绪状态。
- 2026-08-30 的真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回可重试的 `E_LLM_UNAVAILABLE`；不运行 candidate `explore`，不生成或宣称 candidate package、metadata validation、online smoke、live LLM 或第三方成功。

## 案例库与公开 issue

- 案例目录仍为 8 total、4 active、3 candidate、1 known-gap，三个 candidate 的 adapter package、metadata validation、online smoke 仍 pending。
- 本次 GitHub candidate issue 只读审计因 retryable `E_GITHUB_UNAVAILABLE` / GraphQL EOF 未能读取远端状态；不将其判为 missing，也不创建、关闭或改写 issue。
- 没有当前 doctor JSON 时，不执行 `--apply --confirm-rewrite` 覆盖含 Doctor Preflight Evidence 与 64 位 values hash 的公开 issue。

## 风险与兼容性

- 只有重复出现的 `detail` 或 `llm_live` 从此前框架选择一个值的隐含行为改为明确 `400`；合法单值与省略参数保持不变。
- 这是本地 API 契约修复，不表示 Chrome、LLM、candidate adapter 或第三方站点已可用。

## 发版前验证

- 运行 SDK/API、发布说明与官网文档 focused tests、`CLIANY_QA_OFFLINE=1` 全量测试、Ruff、Mypy、`node --check site/script.js`、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check`。
- 版本最终化后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --target-version 0.16.343 --remote`；创建本地 tag 后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.343 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 运行 `git tag v0.16.343`，再执行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 alias inspect 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
