# v0.16.291 发布草案

**目标版本：** `0.16.291`
**提交范围：** `v0.16.290..HEAD`
**发布主题：** 让服务器和 Docker 用户复制到真实的 `explore` 浏览器配置命令。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.291..HEAD`；该锚点不改变实际 release diff。

## 用户价值

官网文档原本把 `--headless` 和 `--cdp-url` 列为 `explore` 的子命令参数，但 CLI 实际将它们定义为根选项。复制旧 Docker 示例会得到 `No such option`，并且把“由 CLI 启动 headless Chrome”和“连接已经运行的远程 CDP 浏览器”混在同一条命令中。

本版在 README 与官网文档给出两条可复制路径：

```bash
cliany-site --headless explore "https://github.com" "Search repositories" --json
cliany-site --cdp-url "ws://chrome:9222" explore "https://github.com" "Search repositories" --json
```

当给出 `--cdp-url` 时，CLI 连接既有浏览器；`--headless` 只影响 cliany-site 自己启动的 Chrome。官网的 `explore` 选项表同步为真实的 `--force`、`--json`、`--interactive`、`--extend` 与 `--record/--no-record`。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 的四个 active case、三个 candidate package-search case 和 `search-extraction-gap` 状态不变。
- 本版不运行 live LLM preflight、explore、adapter package、metadata validation 或 online smoke，也不把 candidate 或第三方浏览器会话称为已验证。
- 后续 candidate 晋级若返回 `llm_live_preflight_not_ready`，仍必须保留 doctor blocker evidence，并让 adapter package、metadata validation 与 online smoke 维持 pending 或 blocked；文档修复不替代任何 live 证明。
- 这是文档契约修复，不创建、下载、安装、覆盖或声明任何 adapter asset。

## 风险与兼容性

- CLI 行为、JSON envelope、CDP 连接优先级和 adapter schema 均未改变；本版只让公开命令与已发布的 Click help 对齐。
- 现有脚本仍可使用根选项；本版不要求用户迁移配置，也不会启动、关闭或连接用户的浏览器。

## 发版步骤

1. 在干净 HEAD 完成版本、CHANGELOG、官网基线、路线图、reviewed GitHub Release Notes 和本草案，并运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.291`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.291 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.291`。
5. 运行 `gh release edit v0.16.291 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.291-github-release.md`，再用 `gh release view v0.16.291 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。
