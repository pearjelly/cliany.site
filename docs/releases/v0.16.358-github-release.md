# v0.16.358

## Clearer Live-Provider Diagnostics

`doctor --llm-live --json` now includes a specific recovery action for TLS certificate failures, interrupted TLS connections, DNS failures, refused connections, timeouts, and HTTP errors. The same safe action appears in the check and preflight summary; low-level exception text is not exposed. A failed TLS handshake does not establish whether an API key is valid.

## Jev and Session Documentation

The public docs now show Jev's experimental, read-only `browser find --by intent` command and its explicit `--allow-remote` consent requirement. It returns a suggested element; it does not click, type, or create an adapter. A TypeSafe key is required, and live model quality has not been measured here.

The login docs now accurately describe host-applicable Cookie persistence and state that LocalStorage restoration is not supported.

## Release Reliability

Release readiness now rejects reviewed notes that still claim the version is an unpublished candidate. The already public v0.16.357 notes were corrected. The active Jira demo passed strict verification and returned five read-only issues on September 23; candidate package generation remains blocked by an upstream model TLS connection failure, and no live Jev evaluation is claimed.
