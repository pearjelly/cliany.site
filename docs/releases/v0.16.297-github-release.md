# v0.16.297

HTTP API deployment commands now match the browser options the CLI actually passes into the server.

## What Changed

- The README and website document `cliany-site --headless serve --port 8080` for a Chrome process started for the API service.
- They document `cliany-site --cdp-url "ws://chrome:9222" serve --port 8080` for an existing remote CDP browser, with root options placed before `serve`.
- `GET /health` is now listed as the copyable service-reachability probe.
- A CLI regression verifies that root `--headless` and `--cdp-url`, host, and port reach `APIServer` unchanged without starting a real server.

## Compatibility

The HTTP API, SDK envelope, `serve` command, and browser connection behavior are unchanged. This release documents the already-supported contract and protects it with a regression test.

## Trust Boundaries

`GET /health` proves only that the HTTP service is reachable. This release does not claim a live LLM provider, candidate adapter package, candidate explore, metadata validation, online smoke, or third-party browser workflow succeeded. Candidate promotion evidence remains pending until it is collected and verified.

## Verification

Focused CLI and documentation regressions, full offline tests, package build and Twine validation, required CI, GitHub Release, PyPI, Vercel production deployment, website browser inspection, and strict publication audit are required before release completion.
