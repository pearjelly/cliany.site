## Website JavaScript now blocks publication when it cannot parse

v0.16.314 adds a dedicated `Website JavaScript Syntax` job to master CI and repeats `node --check site/script.js` in the tag Release Preflight. Strict release readiness verifies both guards remain present.

This follows the real v0.16.313 production incident where an apostrophe in an English translation stopped the static script from parsing and left the homepage blank. The same class of error now fails before GitHub Release, PyPI, or Vercel production publication.

### Validation

- Website JavaScript parses under Node 24.
- Focused workflow and readiness regressions pass.
- Full offline tests, Ruff, Mypy, lock, case catalog, build, Twine, target and tag readiness pass.
- Final master GitHub CI and Embodied CI must both succeed before the tag is pushed.

### Trust boundaries

This release changes publication gates only. It does not claim a new adapter, browser workflow, candidate package, metadata validation, online smoke, or live LLM success. The 2026-08-12 live provider preflight remained blocked by retryable `E_LLM_UNAVAILABLE`.
