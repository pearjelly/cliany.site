# v0.16.290 发布草案

**目标版本：** `0.16.290`
**提交范围：** `v0.16.289..HEAD`
**发布主题：** 让新生成 adapter 的 extract 失败和 JSON 失败退出都能被 shell 与 CI 如实识别。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.290..HEAD`；该锚点不改变实际 release diff。

## 用户价值

新生成的 adapter 原本可能将缺失、空白、纯空白或非字符串的 extract selector 交给 `browser extract`，使抽取动作退化为整页提取并可能看似成功。本版在生成 adapter 实际使用的 runtime helper 中先返回结构化 `E_PARSE_FAILED`，不会调用浏览器命令。

同时，生成 adapter 的 `--json` 失败 envelope 过去仍以退出码 0 结束。`E_SELECTOR_NOT_FOUND`、`E_EMPTY_RESULT` 和其他真实执行错误现在会保留完整 JSON 后以非零状态退出，令 shell、CI 和后续脚本能停止。只有已由命令显式声明的 `expects_nonempty=false` 合法零结果继续返回 `ok=true` 和退出码 0。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 继续定义四个 active case、三个 candidate package-search case，以及已知缺口 `search-extraction-gap`。
- 本版不创建、下载、安装、覆盖或声明任何 candidate adapter asset；当 `llm_live_preflight_not_ready`、缺少 adapter package、metadata validation 或 online smoke 证据时，candidate 保持 pending/blocked。
- active demo 仍使用 release 固定 HTTPS、SHA-256、严格 verify 和只读命令；本版只改生成 adapter 的离线失败语义，不声明第三方站点在线成功。

## 变更分组

### 无效 extract selector 立即失败

- `codegen.runtime_helpers._execute_single_step` 对缺失、`None`、空字符串和纯空白 selector 返回 `E_PARSE_FAILED`，并提供 `selector=null` 与 `extract_mode` 详情。
- 有效 selector 继续透传给 `browser extract`；直接调用内建 `browser extract` 时保留其独立的整页提取选项。

### JSON 失败退出对齐

- `render_command_block_v2` 和空工作流 fallback 都在写出 `ok=false` JSON 后使用非零退出码。
- 失败 JSON 的形状不变；`E_SELECTOR_NOT_FOUND`、`E_EMPTY_RESULT` 和 CDP 错误继续作为可机读 error code。
- `expects_nonempty=false` 只保留已声明的合法空数据成功，不会掩盖 selector、字段质量或浏览器执行失败。

## 风险与兼容性

- 这是新生成或重新生成 adapter 的运行时契约变更；已有生成文件必须重新生成后才会获得非零 JSON 退出行为。
- 消费失败 JSON 但忽略退出码的调用方仍可读取原 envelope；以退出码控制流程的脚本会正确开始失败。
- 没有 adapter metadata schema、直接 `browser extract` CLI、candidate 状态或 live LLM 行为变更。
- 本版不会运行、下载、修复、覆盖或删除 adapter，更不会伪造 live LLM、candidate package、metadata validation 或 online smoke 成功。

## 发版步骤

1. 在允许发布的日期完成版本、CHANGELOG、官网基线、reviewed GitHub Release Notes 和本草案，在干净 HEAD 运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.290`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.290 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.290`。
5. 运行 `gh release edit v0.16.290 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.290-github-release.md`，再用 `gh release view v0.16.290 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.290` makes generated adapters report invalid extract selectors and failed JSON commands with a machine-actionable nonzero exit, while preserving declared empty-result success.
