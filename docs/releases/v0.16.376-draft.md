# v0.16.376 发布草案

**目标版本：** `0.16.376`
**提交范围：** `v0.16.375..HEAD`（以最终 master 为准）
**状态：** 2026-10-08 候选；最终 SHA 的完整回归、CI 和发布门禁待复核。

## 用户价值

- 用 `CLIANY_RUNTIME_HOME` 选择试跑目录，无需替换 Chrome 的 OS HOME。未设置或为空时继续使用 `~/.cliany-site`。
- `demo` 将当前配置的目录传给固定哈希安装、严格验证和只读查询子进程；父进程隔离后，子进程不会再误用默认目录中的同域名 adapter。
- 命令索引、修复与自愈缓存、扩展已有 adapter 的上下文、录制、默认截图、Obscura 缓存和 PID 统一使用配置目录，显式输出或构造器路径继续按调用方指定。

## 验证证据与边界

真实子进程回归先复现安装被默认目录阻断，修复后完成本地固定哈希包安装、严格验证和新目录数据读取；默认目录的 adapter、Session 和索引字节保持一致。截图、录制、缓存、索引和 PID 落盘回归覆盖所选目录。

[公开 Jira 复测](../user-evidence/2026-10-08-runtime-home-isolation.md)在干净实现提交上使用正常 OS HOME：第一次安装并返回 5 条 SPARK issue，第二次复用安装并返回 5 条；单条标题和状态经直接 API 读取确认。这是维护者 API-backed 首跑检查，不是独立用户或浏览器生成验收。[Issue #70](https://github.com/pearjelly/cliany.site/issues/70) 待已发布包复核后关闭，#33 与 #55 保持开放。

## 案例库映射

`cases/README.md` 和 `cases/manifest.json` 状态不变：4 个 active、3 个 candidate、1 个 known-gap，`search-extraction-gap` 保持原状态。没有候选晋级，也没有本轮真实模型探索或 Jev 准确率结论；后续探索若返回 `llm_live_preflight_not_ready`，须记录阻塞并先恢复严格 live preflight。

## 风险与兼容性

CLI 参数、JSON envelope 和 adapter 格式不变。显式运行目录只选择 cliany-site 文件；Chrome OS HOME、自行指定的浏览器 profile、XDG 模型配置和系统 Keychain 不迁移。旧测试替身须提供真实 `adapters_dir`，因为扩展上下文也遵守统一配置。浏览器冷启动和独立首次用户成功仍需各自验证。

## 发版前验证

1. 最终 SHA 运行完整离线测试、Ruff、Mypy、锁文件与官网 JavaScript 检查、严格案例校验，以及 wheel/sdist 构建与 Twine 检查。
2. 等待最终 master 的普通 CI 与真实 Chromium CI 均通过。
3. 在线运行 `scripts/check_github_release_cap.py --strict --json`，再运行 `scripts/release_readiness.py --strict --target-version 0.16.376 --remote --remote-name origin`；创建本地 tag 后用 `--release-tag v0.16.376` 严格复核，通过才推送。

## 发版步骤

1. 核对 GitHub Release 审阅说明和 PyPI 精确版本及分发文件。
2. 在 `site/` 运行 `vercel link --yes --project cliany.site` 和 `vercel --prod --yes`；检查生产别名、首页与文档页。
3. 从新 PyPI 安装重复独立运行目录的只读首跑与复用，再执行 `scripts/check_release_publication.py --strict --remote --distribution --json`。
