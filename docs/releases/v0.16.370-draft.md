# v0.16.370 发布草案

**目标版本：** `0.16.370`
**提交范围：** `v0.16.369..HEAD`（以最终 master 为准）
**状态：** 候选，尚未发布；只有最终 master 的门禁通过后才能创建 tag。

## 用户价值

- 新用户在 human `doctor` 输出中看到一条可复制的 `cliany-site demo --case-id apache-jira-issues --json` 命令。该命令对已发布的 active 无登录案例先安装（仅当目标缺失）、严格校验，再返回至少一条只读结果；失败会非零退出。
- JSON `doctor` 的 `summary.recommended_next_step`、`demo_adapter_quickstart.recommended_commands` 和真实模型预检契约不变，已有自动化仍可按逐步命令执行。
- 公开路线图链接十月价值计划，将独立首用验收与生成浏览器命令的可靠性目标分开记录。

## 验收证据

- 2026-10-03 在隔离 HOME 下，v0.16.369 基线上的候选 `doctor` 输出一条 Jira demo 命令；照此执行返回 `ok=true`、`installed_now=true`、`row_count=5` 和非空 SPARK issue。此为维护者的 API 支持只读案例实测，不是独立用户试用，也不是 LLM 生成浏览器工作流。
- [十月价值计划](../plans/2026-10-02-october-value-plan.md)记录固定提交的严格 30 次三任务样本为 25/30，低于 27/30 目标；本版不包含该 draft 生成改动，不宣称生成成功率提升。
- PR #42 和 #32 的精确提交普通及具身 CI 已通过。发布仍须在二者合并后的最终 master SHA 重新验证。

## 案例库映射

- `cases/manifest.json` 与 `cases/README.md` 本版不调整案例状态：Jira、Confluence、Jenkins、SuiteCRM 保持 active；PyPI、npm、crates.io 搜索保持 candidate，`search-extraction-gap` 保持 known-gap。
- 安装包验证不等于第三方页面成功。候选晋级前必须运行真实 `doctor --llm-live --require-capability generate_adapters --json`；若结果是 `llm_live_preflight_not_ready` 或网站验证页，则不执行或宣称真实模型探索成功。

## 风险与兼容性

- `demo` 依赖 GitHub Release 资产和第三方只读服务可达，不会覆盖已有 adapter。已有安装目标若损坏，命令按原有校验规则失败并给出修复提示。
- 一命令引导仅改变 human 输出；机器 JSON 和需要登录、Chrome/CDP、LLM 的工作流没有被当作已验证的首用路径。
- Issue #33 所需的至少两名独立初次用户反馈仍未收集；PR #34 的生成可靠性样本仍低于目标。

## 发版前验证

1. 确认版本号、锁文件、CHANGELOG、两份路线图、官网首页与文档页、审核过的 GitHub Release 文案同为 v0.16.370。
2. 在最终 master SHA 运行完整离线测试、具身 Chromium 测试、Ruff、Mypy、锁文件和官网脚本检查、案例严格校验，以及 wheel/sdist 构建与 Twine 检查。
3. 确认该 SHA 的普通 CI 与 Embodied CI 均通过；在线严格检查上海时间 GitHub Release 发布上限，运行 target readiness 后才创建本地 tag，并以 tagged readiness 再核验。

## 发版步骤

1. 运行 `uv run python scripts/check_github_release_cap.py --strict --json`，确认 GitHub Release 发布日期而非本地 tag 日期仍有每日名额，未知时停止。
2. 在干净的最终 master 上运行 `uv run python scripts/release_readiness.py --strict --target-version 0.16.370 --remote --remote-name origin`；通过后创建本地 `v0.16.370`，运行 `--release-tag v0.16.370` 严格门禁，通过才推送 tag。
3. 等待 GitHub Release 和 PyPI 精确版本公开，再从 `site/` 运行 `vercel link --yes --project cliany.site` 与 `vercel --prod --yes`，检查 `www.cliany.site` 的首页、文档页和生产别名。
4. 在全新 master 克隆运行 `python3 scripts/check_release_publication.py --strict --remote --distribution --json`，并用正式 PyPI 包与隔离 HOME 复测首条只读结果；独立用户验收继续按 Issue #33 收集。
