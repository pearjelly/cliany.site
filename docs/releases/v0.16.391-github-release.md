## Preserve The Intended Workflow

Newly generated commands preserve recorded business action order and multiplicity. Identical buttons or inputs can represent different stages; generating a command must not silently delete them. A scalar `action_index` changes only its declared input. Intentional reuse declares explicit `action_indices`, while ambiguous default matching fails rather than guessing or changing an independent fixed baseline.

Generation validates every declared argument after all overrides. No-op options, value bindings on fixed navigation and later arguments clobbering earlier ones are rejected. Exploration retains its existing shared correction budget and declared parameters; removing a binding cannot masquerade as a repair. Extraction choices must currently ground and resolve uniquely, without hiding other AX action refs or weakening semantic tie refusal.

Read purpose is fixed before execution: structural `probe` data stays in complete exploration history but is not compiled into business replay; explicitly requested `baseline` data is replayed and returned. Ordinary search outputs cannot quietly include earlier fixed-query collections. There is no posthoc relabeling, selecting the last array or output deduplication to obtain a passing result.

## Migration

Existing generated CLI files and fixed-hash packages are not patched. A runtime upgrade does not repair old emitted steps or placeholders: regenerate or normally merge an explicit workflow when needed. One parameter used by multiple type/select steps must list their owned, unique integer indices. SDK and merge rebase bindings across original-history gaps without mutating original declarations. Invalid or ambiguous legacy SDK bindings return `E_VERIFY_STATIC` before browser work, including dry-run; HTTP uses the existing JSON422 status and fixed reason instead of input values or exception bodies.
