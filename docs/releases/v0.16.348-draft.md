## 用户价值

- Python SDK 的 `ClanySite.explore()` 与 `ClanySite.login()` 现在复用 HTTP API 的 URL 边界：只接受无空白、带 host 的 `http` 或 `https` URL。
- 无效协议、缺失 host、畸形端口、含空白或非字符串值会在构造 explorer 或浏览器 session 前返回 `INVALID_URL`；合法 HTTP(S) URL 和 `POST /execute` 保持兼容。

## 证据边界

- 2026-09-02 的真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回可重试的 `E_LLM_UNAVAILABLE` / `llm_live_preflight_not_ready`；不运行 candidate `explore`，不生成或宣称 candidate package、metadata validation、online smoke、live LLM 或第三方成功。

## 案例库与公开 issue

- `cases/manifest.json` 仍记录 8 total、4 active、3 candidate、1 known-gap；三个 candidate 的 adapter package、metadata validation 与 online smoke 仍 pending。
- 2026-09-02 的只读 candidate issue 审计实际返回三个 `missing` candidate issue；未创建、关闭或改写公网 issue。

## 风险与兼容性

- SDK 调用方如果此前传入不合规 URL，会从可能进入后续运行时的行为变为稳定的 `INVALID_URL` 信封；合法 HTTP(S) URL 及其他 SDK 方法保持不变。
- 这是本地输入边界修复，不表示 Chrome、LLM、candidate adapter 或第三方站点已可用。

## 发版前验证

- 运行 SDK/API、发布说明与官网文档 focused tests、`CLIANY_QA_OFFLINE=1` 全量测试、Ruff、Mypy、`node --check site/script.js`、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check`。
- 版本最终化后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --target-version 0.16.348 --remote`；创建本地 tag 后运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.348 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 运行 `git tag v0.16.348`，再执行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 alias inspect 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
