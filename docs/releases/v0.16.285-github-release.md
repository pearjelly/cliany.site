# v0.16.285

Doctor now avoids suggesting a duplicate active-demo install when its local install target is already occupied.

## What Changed

- `doctor --json` adds `data.summary.demo_adapter_quickstart.adapter_present` and `recommended_commands`.
- When the target is unoccupied, `recommended_commands` keeps the install, `verify`, read-only sequence.
- When the target is occupied, `recommended_commands` starts with `verify`, then the read-only command; human doctor output and `recommended_next_step` use the same sequence.

## Compatibility

`commands` and `install_command` remain the original static install path for compatibility. Consumers that execute doctor guidance should use `recommended_commands` and accept the additive `adapter_present` field.

An occupied target is not proof of a valid adapter. `verify` remains the required diagnostic step, and the release does not weaken `market install` overwrite protection or introduce automatic overwrite.

## Trust Boundaries

This release does not install, overwrite, delete, repair, download, or execute an adapter merely by running doctor. It does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result. Candidate cases remain pending until their required evidence is attached.

## Verification

Focused doctor, documentation, and release-doc tests, the full offline suite, package build, Twine metadata validation, required CI workflows, GitHub Release, PyPI, Vercel production deployment, browser inspection, and strict publication audit are required before this release is complete.
