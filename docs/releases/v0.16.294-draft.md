# v0.16.294 发布草案

**目标版本：** `0.16.294`
**提交范围：** `v0.16.293..HEAD`
**发布主题：** 让普通 `cliany-site doctor` 不会把本地 LLM 配置误说成可以直接 `explore`。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.294..HEAD`；该锚点不改变实际 release diff。

## 用户价值

普通 `cliany-site doctor` 默认只读取本地配置和浏览器可达性，不会真实调用 LLM provider。此前在 CDP、key 和 provider 配置都存在时，它会直接建议 `explore`，容易让用户把“配置有效”误解为“上游 provider 现在可用”。

2026-08-02 的真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 预检正好显示这个边界：Chrome/CDP、key 和 provider 配置可用，但 provider connection error 触发可重试的 `E_LLM_UNAVAILABLE`，`generate_adapters` 未 ready。

本版让普通人类输出先给出显式 live preflight 命令；只有预检成功的 `doctor --llm-live` 才展示可继续执行的 `explore`。默认 `doctor` 仍不发起 provider 请求，JSON schema 和自动化字段不变。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap`；candidate 的九项 promotion evidence 仍是 pending。
- 因今天的 live preflight 是 `E_LLM_UNAVAILABLE`，本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation 或 online smoke 成功。
- 在没有 ready 预检时，release handoff 必须保留 `llm_live_preflight_not_ready` blocker；本版的人类引导让这个既有门禁在直接 `explore` 前可见。
- `scripts/audit_candidate_issues.py --repo pearjelly/cliany.site --json` 必须继续确认公开 candidate issues #14、#15、#16 为 current；本地 provider 错误不会写成外部成功证据。

## 风险与兼容性

- `doctor --json` 的 checks、summary、capabilities 和 `llm_live_preflight` schema 均不变。
- 不带 `--llm-live` 的普通 `doctor` 仍绝不调用 provider；它只把下一步从直接 `explore` 改为先做 live preflight。
- 成功的 `doctor --llm-live` 仍会在普通输出中显示 `explore`；失败时保留既有 blockers 和非零 strict exit。
- 本版不代表 live LLM、candidate workflow、adapter package 或第三方站点操作成功。

## 发版步骤

1. 在干净 HEAD 完成版本、CHANGELOG、官网基线、路线图、reviewed GitHub Release Notes 和本草案，并运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.294`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.294 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.294`。
5. 运行 `gh release edit v0.16.294 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.294-github-release.md`，再用 `gh release view v0.16.294 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.294` makes human doctor guidance require a live provider preflight before it presents `explore`, without changing JSON contracts or claiming a provider or candidate workflow succeeded.
