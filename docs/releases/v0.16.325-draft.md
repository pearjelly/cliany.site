## 用户价值

- 新增 `scripts/capture_active_demo_evidence.py`，维护者可以明确指定 active case 和输出路径，自动从案例目录派生 `verify --strict --json` 与 manifest 声明的只读 JSON 命令。
- 捕获器严格串行：静态校验返回成功 envelope 后才运行只读命令；`ok=true` 和既有 adapter 的兼容 `success=true` 都会保留，失败或跳过会写出原始结果并返回非零。
- quickstart、维护者循环、公开路线图、官网首页和 `/docs` 链接 2026-08-17 的真实 `issues.apache.org` / Apache Spark 证据快照，并明确它不是下载资产、candidate package、live LLM 或第三方持续可用性证明。

`cases/README.md` 与 `cases/manifest.json` 仍是案例目录和命令声明的来源；本版不改变 `search-extraction-gap` known-gap 或任何 candidate 状态。最近真实 live preflight 仍为 `llm_live_preflight_not_ready` / `E_LLM_UNAVAILABLE`，候选晋级保持阻断。

## 案例库映射

- `cases/manifest.json` 仍是 active case 的命令来源；捕获器拒绝 candidate、非只读 online 描述或缺少 JSON 命令的案例。
- 本轮真实捕获：`issues.apache.org` 严格静态校验返回 `ok=true`，随后 Spark 只读查询返回 5 条结果；实际数据保存在 `docs/user-evidence/2026-08-17-issues-apache-spark.md`。
- `pypi-project-search`、`npm-package-search` 和 `crates-io-crate-search` 仍是 candidate，公开 issue #14/#15/#16 保持 current；最近 live preflight 仍为 retryable `E_LLM_UNAVAILABLE`，没有候选晋级证据。

## 风险与兼容性

- 变更限于维护者脚本、测试、证据文档、quickstart、路线图和官网内容，不改变 CLI、adapter、SDK、HTTP API、案例状态或 release workflow。
- 捕获结果是单次、日期化环境证据；第三方 issue 数量、标题和状态会变化，不能把 snapshot 当作当前或持续服务保证。
- 捕获器不安装、覆盖、发布 adapter，也不调用 live LLM；它不会绕过 candidate promotion gate。

## 发版前验证

- 运行 `uv run --extra dev --frozen python scripts/capture_active_demo_evidence.py --case-id apache-jira-issues --output /tmp/active-demo-evidence.md --json`，确认真实静态校验与只读命令均成功。
- 运行 `node --check site/script.js`、相关 focused tests 和 `CLIANY_QA_OFFLINE=1` 全量测试。
- 运行 Ruff、Mypy、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check dist/*`。
- 运行 `python scripts/release_readiness.py --strict --target-version 0.16.325 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 创建 `v0.16.325`，运行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复，不继续发布。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 `vercel inspect www.cliany.site` 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
