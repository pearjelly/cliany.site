# v0.16.289 发布草案

**目标版本：** `0.16.289`
**提交范围：** `v0.16.288..HEAD`
**发布主题：** 让缺失抽取定位和过期官网基线都在发布前显式失败。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.289..HEAD`；该锚点不改变实际 release diff。

## 用户价值

生成的搜索或列表命令如果带有缺失、空白或非字符串的 extract selector，过去可能只记录 warning 后继续，好像步骤完成但没有可靠的抽取结果。现在该步骤会记录 `E_PARSE_FAILED`、步骤索引和空 selector；默认回放会立刻以现有 `ActionExecutionError` 失败。显式 `continue_on_error=true` 仍可以收集后续步骤，但结果中保留 `ok=false`，不会产生假阳性。

本版还把刚刚实际发生的官网版本漂移收进 release readiness：严格发布前检查要求 `site/index.html`、`site/script.js` 和 `site/docs/index.html` 都携带与 `pyproject.toml` 相同的版本基线。缺任一标识都会在 tag 前阻断，而不是等 PyPI 发布后才发现公开页面还在描述旧版本。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 继续定义四个 active case、三个 candidate package-search case，以及已知缺口 `search-extraction-gap`。
- 本版不创建、下载、安装、覆盖或声明任何 candidate adapter asset；`llm_live_preflight_not_ready`、缺少 adapter package、metadata validation 或 online smoke 证据时，candidate 保持 pending/blocked。
- active demo 仍使用 release 固定 HTTPS、SHA-256、严格 verify 和只读命令；本次本地抽取错误语义不声明第三方站点在线成功。

## 变更分组

### 抽取失败不再静默

- `execute_action_steps` 将缺失、`None`、空字符串和纯空白 extract selector 统一为无效定位。
- 传入 `extraction_results` 时会追加包含 `E_PARSE_FAILED`、`step_index` 和 `selector=null` 的失败结果。
- 默认模式抛出 `ActionExecutionError`；`continue_on_error=true` 保留已有部分失败收集契约，调用方必须检查 `results[*].ok`。

### 发布前官网基线门禁

- `release_readiness.py` 将三个官网文件纳入开放源代码 metadata 检查。
- 每个文件必须带有当前 `pyproject.toml` 版本的对应用户可见标识；严格 readiness 会报告缺失的文件和片段。
- 这只校验源码与版本一致性，不宣称 Vercel、GitHub Release 或 PyPI 已成功；它们仍在 tag 后逐项审计。

## 风险与兼容性

- 以前依赖缺失 selector 被忽略的自定义 action 会从静默成功变成明确失败；这符合已有严格抽取质量和错误 envelope 约定。
- `continue_on_error=true` 不改变为进程错误，但现在会公开失败记录，调用方应按既有部分结果契约判断 `ok=false`。
- 官网基线检查要求三个现有文件保留版本字符串；无公共 API、adapter schema 或 candidate 状态变更。
- 本版不会运行、下载、修复、覆盖或删除 adapter，更不会伪造 live LLM、candidate package、metadata validation 或 online smoke 成功。

## 发版步骤

1. 在允许发布的日期完成版本、CHANGELOG、官网基线、reviewed GitHub Release Notes 和本草案，在干净 HEAD 运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.289`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.289 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.289`。
5. 运行 `gh release edit v0.16.289 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.289-github-release.md`，再用 `gh release view v0.16.289 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

`v0.16.289` makes invalid extract selectors and stale website release baselines fail explicitly, preventing local replay and public-release false success states.
