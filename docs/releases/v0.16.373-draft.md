**目标版本：** `0.16.373`
**提交范围：** `v0.16.372..HEAD`（以最终 master 为准）
**状态：** 候选；最终 master 门禁和上海时间线上发布配额通过后才能推送 tag。

## 用户价值与边界

- 生成命令的只读提取需要当前 AXTree 证实选择器；列表提取等待结果稳定，未稳定时返回 `E_PAGE_NOT_READY`，不再把部分前缀报告为成功。
- 未录制动作却声明命令的非交互探索可继续一次；无效命令分区可受限修正一次，仍无效则停止生成。
- 空标量文本不再作为零匹配证据；提取文件遵守隔离的运行目录。
- Python 文档站适配器仍是 candidate，100 行上限、公开包 URL 和独立用户反馈是剩余边界。

## 验证证据

- PR #47 的完整离线、Python 3.11-3.13、Windows、Ruff、Mypy 与具身 Chromium CI 通过。
- 干净固定提交 `4d90e3c` 的受控矩阵为 30/30，40 次改参回放的返回值与独立 DOM 一致；p95 186.4 秒，且没有真实命令分区修正尝试。
- 三轮独立运行目录中的 Python 官方文档搜索生成、严格验证和改参回放通过；另一个空运行目录安装本地包后也通过。尚未从公开 URL 安装。

## 发版前验证

1. 在最终 master SHA 运行完整离线测试、具身 Chromium、Ruff、Mypy、`uv lock --check`、官网脚本和案例严格校验；构建 wheel/sdist 并运行 Twine 检查。
2. 确认最终 master 的普通和 Embodied CI 均通过，运行 `uv run python scripts/check_github_release_cap.py --strict --json`，达到上海时间当日 3 次上限时停止。
3. 运行 `uv run python scripts/release_readiness.py --strict --target-version 0.16.373 --remote --remote-name origin`；通过后创建本地 tag `v0.16.373`，再以 `--release-tag v0.16.373` 严格验证后推送。

## 发版步骤

1. 推送 `v0.16.373`，等待 GitHub Release 和 PyPI 精确版本公开。
2. 仅在 GitHub Release 已就绪后附上 Python 文档站候选适配器包，核对公开 URL 和 SHA-256，再用空 HOME 从该 URL 安装、严格验证和改参回放；失败时不晋级 candidate。
3. 在 `site/` 执行 `vercel link --yes --project cliany.site`、`vercel --prod --yes`，核查生产别名和版本。
4. 从干净 master 运行 `scripts/check_release_publication.py --strict --remote --distribution --json`。独立首次用户仍在 Issue #33 验收，不以维护者试验代替。
