## 用户价值

自动化调用方此前只能先调用浏览器相关的执行路径，或重新组装 CLI 命令来判断一个已安装 adapter 是否可用。本版新增 `ClanySite.verify(domain)`、同步 `verify(domain)` 以及 `GET /verify?domain=<domain>`：它们复用 `cliany-site verify <domain> --strict` 的 metadata、生成模块安全扫描、manifest 和 runtime loader 合约，返回相同 `results` / `failed_domains` 诊断而不连接 CDP 或 LLM。

HTTP 调用方可依照现有信封语义分支：缺少 `domain` 为 `400`，不存在的 adapter 为 `404`，已安装 adapter 的静态验证失败为 `422`。SDK 对错误 `commands.py` 返回 `E_VERIFY_STATIC`，因此服务编排可以在执行前停止，而不是把错误误判为浏览器故障。

`domain` 现在必须是单个安全 adapter 目录名。SDK、HTTP 和 CLI `verify` 一致拒绝空值、相对路径、POSIX/Windows 绝对路径、分隔符和盘符，并以 `E_INVALID_PARAM` / HTTP `400` 返回，防止验证路径逃出 adapters 目录后交给 runtime loader。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不改变案例、adapter 或浏览器运行时行为。
- candidate 的九项 promotion evidence 仍为 pending。2026-08-04 最近一次真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回可重试 `E_LLM_UNAVAILABLE`，并记录 `llm_live_preflight_not_ready` blocker。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、第三方工作流或 live LLM 成功。

## 风险与兼容性

- 有效的单目录 adapter domain 保持兼容；新校验只拒绝原本不应作为 adapter 名的路径输入。
- `verify` 不连接 Chrome 或 LLM，但为确认 loader 合约会读取并加载已安装 adapter 的 `commands.py`；仅验证已安装且受信任的 adapter。
- `GET /verify` 复用既有 SDK 信封和 HTTP 错误映射，不改变 `GET /health`、`GET /doctor`、`GET /adapters` 或 mutation endpoint 的契约。
- 本版不代表 live LLM、candidate workflow、candidate adapter package 或第三方站点操作成功。

## 发版步骤

1. 仅在 v0.16.303 已完整发布且版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.304`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.304 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.304`。
5. 运行 `gh release edit v0.16.304 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.304-github-release.md`，再用 `gh release view v0.16.304 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

`v0.16.304` adds a verified adapter-readiness boundary for SDK and HTTP integrations, while rejecting unsafe path-shaped adapter names and preserving the established browser, LLM, publication, and candidate-evidence trust boundaries.
