# v0.16.305 发布草案

**目标版本：** `0.16.305`
**提交范围：** `v0.16.304..HEAD`
**提交范围：** `v0.16.305..HEAD`
**发布主题：** 固定已安装 adapter 的本地文件边界，避免静态验证或运行前预检沿符号链接读取或导入目标目录外的内容。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.305..HEAD`；该锚点不改变实际 release diff。

## 用户价值

已安装 adapter 的 `commands.py` 虽然会在严格验证或 runtime loader 合约检查中读取、扫描或导入，但此前目录、metadata、命令模块和 manifest 文件可以是符号链接。用户无法从 `verify --strict` 的成功或失败结果中判断它是否越过 adapter 根目录读取了其他位置的文件。

本版在读取 adapter 自有内容或导入模块前拒绝符号链接 adapter 目录、`metadata.json`、`commands.py` 和 `manifest.json`，并在 manifest 完整性检查中拒绝任何声明文件符号链接。`cliany-site verify <domain> --strict`、根 CLI 的动态 adapter 诊断、异步 `ClanySite.verify(domain)`、`GET /verify?domain=<domain>`、`ClanySite.execute()` 和 HTTP `POST /execute` 都返回现有 `security_issue` / `E_VERIFY_STATIC` 契约；HTTP 静态失败仍为 `422`，不会先启动浏览器。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不改变案例、adapter package 或浏览器运行时行为。
- candidate 的九项 promotion evidence 仍为 pending。2026-08-04 最近一次真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回可重试 `E_LLM_UNAVAILABLE`，并记录 `llm_live_preflight_not_ready` blocker。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、第三方工作流或 live LLM 成功。

## 风险与兼容性

- 正常目录中的普通 adapter 文件保持原有 `verify`、SDK、HTTP 和执行语义；本版不改变 action runtime、CDP、session 或 LLM 行为。
- 任何使用符号链接组织 adapter 文件的本地安装现在会被明确拒绝；请用可信分发包重新安装为普通文件，再运行 `cliany-site verify <domain> --strict --json`。
- `security_issue` 表示本地静态文件边界不满足，不证明浏览器、第三方网站、GitHub Release、PyPI、Vercel、candidate package 或 live LLM 已就绪。

## 发版步骤

1. 仅在 v0.16.304 已完整发布且版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.305`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.305 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.305`。
5. 运行 `gh release edit v0.16.305 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.305-github-release.md`，再用 `gh release view v0.16.305 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.305` makes installed adapter files a bounded local trust surface: static verification and runtime preflight reject symbolic links before reading or importing them, while preserving existing CLI, SDK, HTTP, browser, LLM, and candidate-evidence boundaries.
