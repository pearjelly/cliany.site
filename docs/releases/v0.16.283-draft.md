# v0.16.283 发布草案

**目标版本：** `0.16.283`
**提交范围：** `v0.16.282..HEAD`
**发布主题：** 让重复 adapter 的 marketplace dry-run 返回完整、只读且可自动化处理的安装计划。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.283..HEAD`；该锚点不改变实际 release diff。

## 用户价值

`market install --dry-run` 的职责是验证分发包并计算安装计划，不写入 adapter。此前目标 domain 已安装时，dry-run 会沿用真实安装的覆盖保护，直接以 `INSTALL_FAILED` 退出，调用方既无法读取包 hash，也无法判断是否只需显式确认覆盖。

本版让重复 adapter 的 dry-run 返回 `ok=true` / exit 0 的只读计划，并将 `would_replace=true`、`would_create_backup=false` 和 `requires_force=true` 一起返回。这里的成功只表示包校验与计划计算成功，绝不表示 adapter 已安装，亦不表示调用方可以直接覆盖。自动化必须检查 `requires_force` 并在用户明确同意后才以 `--force` 执行真实安装。

不带 `--force` 的真实重复安装继续返回非零 `INSTALL_FAILED`，且在创建 backup、删除或写入 adapter 前失败。即使 dry-run 加上 `--force` 而显示 `requires_force=false`，它也仍然只是只读计划，不会授权后续不带 `--force` 的安装。固定 SHA-256 远程包与本地包共享该契约。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 继续定义四个 active case、三个 candidate package-search case，以及已知缺口 `search-extraction-gap`。
- 本版不创建、下载、安装、覆盖或声明任何 candidate adapter asset；已发布 active demo 的安装、verify、只读命令顺序不变。
- `llm_live_preflight_not_ready` 仍然约束 candidate 晋级；没有真实 live preflight、adapter package、metadata validation 和 online smoke 证据时，candidate 保持 pending/blocked。

## 变更分组

### 重复安装 dry-run 计划

- `market install <package> --dry-run --json` 对已有 adapter 返回成功的只读 plan，而非 `INSTALL_FAILED`。
- `requires_force=true` 明确表示真实覆盖仍需要显式 `--force`；`would_create_backup` 仅描述真正加 `--force` 后的安装计划。
- 远程固定 SHA-256 dry-run 也覆盖重复 adapter 场景；它不写入 adapter 或 backup，下载临时文件在校验后清理。
- 普通重复安装仍保持非零错误、`--force` 修复提示，以及 commands.py 和 metadata.json 文件不变。

## 风险与兼容性

- 依赖 dry-run 重复 adapter 的非零退出码来决定后续动作的自动化需要改为读取 `data.requires_force`；exit 0 不代表已安装或可以不带 `--force` 覆盖。
- 真实安装与覆盖保护的错误码、写入顺序、backup 行为不变。
- 本版不伪造第三方 adapter、live LLM、candidate package、metadata validation 或 online smoke 成功。

## 发版步骤

1. 完成版本、CHANGELOG、官网基线、reviewed GitHub Release Notes 和本草案，在干净 HEAD 运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.283`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.283 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.283`。
5. 运行 `gh release edit v0.16.283 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.283-github-release.md`，再用 `gh release view v0.16.283 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.283` makes duplicate marketplace dry-runs return an explicit read-only `requires_force` plan while preserving real-install overwrite protection and no-write guarantees.
