# v0.16.306 发布草案

**目标版本：** `0.16.306`
**提交范围：** `v0.16.305..HEAD`
**提交范围：** `v0.16.306..HEAD`
**发布主题：** 让 root CLI 注册与 SDK/API 执行路径在启动浏览器或导入命令前，完整执行已安装 adapter 的 manifest 文件边界检查。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.306..HEAD`；该锚点不改变实际 release diff。

## 用户价值

已安装 adapter 的 manifest 用于描述可信分发包包含哪些普通文件及其哈希。此前 `verify --strict` 会检查 manifest，但 root CLI 注册只检查 metadata 与 commands，`ClanySite.execute()` / `POST /execute` 也可能在浏览器启动前跳过 manifest 完整性检查。

本版让 root CLI 在导入 adapter 命令前拒绝符号链接 `manifest.json`；SDK `execute` 与 HTTP `POST /execute` 在启动浏览器前复用 manifest 检查，拒绝符号链接 manifest、符号链接声明文件和哈希不匹配。失败保留 `security_issue` 或 `manifest_error` 的 `E_VERIFY_STATIC` 信封；HTTP 保持 `422`，不会先启动浏览器。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 仍包含四个 active case、三个 candidate package-search case 和一个 `search-extraction-gap` known gap；本版不改变案例、adapter package 或浏览器运行时行为。
- candidate 的九项 promotion evidence 仍为 pending。保留的最近真实 live preflight 是 retryable `E_LLM_UNAVAILABLE` / `llm_live_preflight_not_ready` blocker；本版不把它当作成功。
- 本版不运行 candidate `explore`，不生成、安装或发布 candidate adapter package，也不声称 metadata validation、online smoke、第三方工作流或 live LLM 成功。

## 风险与兼容性

- 没有 `manifest.json` 的本地 adapter 保持原有可执行行为；存在 manifest 的 adapter 现在必须满足与严格验证一致的普通文件和哈希契约。
- 使用符号链接或已损坏 manifest 的本地安装会在浏览器工作前失败；请用可信包重新安装，再运行 `cliany-site verify <domain> --strict --json`。
- `E_VERIFY_STATIC` 只表示本地静态边界未通过，不证明 Chrome、LLM、session、action replay、第三方网站、GitHub Release、PyPI、Vercel 或 candidate package 已就绪。

## 发版步骤

1. 仅在 v0.16.305 已完整发布且版本、CHANGELOG、官网基线和路线图完成实际 finalization 后运行 target-mode readiness；finalization 后的 CI 才是 tag authority。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.306`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.306 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.306`。
5. 运行 `gh release edit v0.16.306 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.306-github-release.md`，再用 `gh release view v0.16.306 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。

## Release Notes 摘要

`v0.16.306` makes manifest integrity part of every pre-browser adapter execution path, while preserving the existing local-only static-error contract and not claiming workflow or provider success.
