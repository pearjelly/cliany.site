# v0.16.311 发布草案

**目标版本：** `0.16.311`
**提交范围：** `v0.16.310..HEAD`
**提交范围：** `v0.16.311..HEAD`
**发布主题：** 让 doctor 的本地就绪证据不被 live provider 故障污染。

完成 version bump 后，target-mode readiness 会检查占位锚点 **提交范围：** `v0.16.311..HEAD`；该锚点不改变实际 release diff。

## 用户价值

v0.16.310 新增了 `local_ready`，但显式 live preflight 返回 `llm_live` warning 时，该字段仍沿用了包含 live blocker 的整体 `ready`，导致 CDP、目录、key 均正常时也显示本地未就绪。

本版新增 `local_blockers`，并让 `local_ready` 仅由本地 blockers 决定。真实 provider 故障时可同时保留 `local_ready=true`、整体 `ready=false` 与 `live_blockers=["llm_live"]`，`next_step` 给出严格重试命令。

## 案例库映射

- [cases/README.md](../../cases/README.md) 与 `cases/manifest.json` 中四个 active case、三个 candidate package-search case 和 `search-extraction-gap` known gap 均不变。
- 2026-08-10 的真实严格预检返回 retryable `E_LLM_UNAVAILABLE` / connection error；`doctor_preflight_state.reason_codes` 包含 `llm_live_preflight_not_ready`，candidate adapter package、metadata validation 与 online smoke 仍为 pending。
- 本版不生成、安装或发布 candidate adapter package，也不声称 live LLM、第三方 workflow 或 online smoke 成功。

## 风险与兼容性

- 既有整体 `generate_adapters.ready` 行为不变；live 失败时仍为 false。变更只修正新增 `local_ready` 的定义并补充 `local_blockers`。
- 新字段仍是诊断证据，不证明 Chrome session、action replay、GitHub Release、PyPI 或 Vercel 已就绪。
