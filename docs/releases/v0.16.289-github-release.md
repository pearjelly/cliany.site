# v0.16.289

Invalid extract selectors and stale website release baselines now fail explicitly instead of looking successful.

## What Changed

- An `extract` action whose `selector` is missing, `None`, empty, or whitespace-only now records `E_PARSE_FAILED` with its step index. Default replay stops with `ActionExecutionError`; `continue_on_error=true` keeps the structured failed result for partial-output callers.
- Strict release readiness now verifies the version displayed in `site/index.html`, `site/script.js`, and `site/docs/index.html` matches `pyproject.toml`. A stale public-site source blocks before tagging.

## Compatibility

Valid extract actions and their result format are unchanged. The existing `continue_on_error` path still continues, but callers now receive an explicit `ok=false` result rather than a silent skip. No adapter metadata schema or CLI option changed.

## Trust Boundaries

This release validates local action input and repository website source consistency only. It does not prove a third-party page is online, a session is valid, a selector will match on a changed page, or a Vercel deployment has completed. It does not install, overwrite, delete, repair, download, or execute an adapter merely by running release readiness. It does not claim live LLM success, a candidate adapter archive, metadata validation, or an online smoke result.

## Verification

Focused action-runtime, readiness, documentation, and site tests; the full offline suite; package build; Twine metadata validation; required CI workflows; GitHub Release; PyPI; Vercel production deployment; browser inspection; and strict publication audit are required before this release is complete.
