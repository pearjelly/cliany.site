完成 version bump 后，target-mode readiness 使用 `v0.16.327..HEAD`；创建本地 tag 后，release-tag mode 校验同一实际发布范围。

## 用户价值

- 普通 `doctor --llm-live --require-capability generate_adapters` 现在将缺少 LLM key 的 `E_LLM_DISABLED` 明确指向 key 配置，把 `E_LLM_UNAVAILABLE` 保留给 provider 网络或上游重试。
- 人类用户不必从 JSON `error.details` 反推下一步；自动化仍可读取完整 checks、summary 和 capability blockers。
- 只修正诊断表达，不放宽 live LLM、candidate adapter package、metadata validation 或 online smoke 门禁。

## 案例库映射

- active 案例和 candidate 案例状态不变；三个 candidate 的 adapter package、metadata validation、online smoke 仍 pending。
- 若真实 `cliany-site doctor --llm-live --require-capability generate_adapters --json` 返回 `E_LLM_UNAVAILABLE` 或其他 blocker，不运行 candidate `explore`，也不生成或宣称 adapter asset。
- 本轮引用 `cases/README.md`、`cases/manifest.json`、`search-extraction-gap` 和 `llm_live_preflight_not_ready` 只用于说明验证边界，不代表 candidate 已晋级。

## 风险与兼容性

- 成功 doctor、CLI adapter 命令、SDK、HTTP API、案例状态和 release workflow 不变。
- `E_LLM_DISABLED` 与 `E_LLM_UNAVAILABLE` 都是本地 readiness evidence，不代表 live LLM、candidate package、online smoke 或第三方工作流可用。

## 发版前验证

- 运行 `pytest tests/test_doctor_v3.py tests/test_doctor.py tests/test_site_content.py tests/test_release_draft_docs.py -q --no-cov`。
- 运行 `node --check site/script.js`、`CLIANY_QA_OFFLINE=1` 全量测试、Ruff、Mypy、`uv lock --check`、strict case catalog、`uv build` 与 `uvx twine check dist/*`。
- 运行 `python scripts/release_readiness.py --strict --target-version 0.16.328 --remote --remote-name origin`。
- 只有最终 master SHA 的 GitHub CI 与 Embodied CI 都 success 后，才允许创建本地 tag。

## 发版步骤

1. 推送最终 master，等待该 SHA 的 GitHub CI 与 Embodied CI 成功。
2. 创建 `v0.16.328`，运行带 remote 的 `--release-tag` readiness；失败时删除未推送 tag 并修复，不继续发布。
3. 推送 tag，等待 Release workflow，精确核验 GitHub Release 与 PyPI 专属版本/latest。
4. 将 `site/` 部署到 cliany.site Vercel production，执行 `vercel inspect www.cliany.site`、`vercel inspect cliany.site` 和真实浏览器检查。
5. 最后运行 `python scripts/check_release_publication.py --strict --remote --distribution --json`。
