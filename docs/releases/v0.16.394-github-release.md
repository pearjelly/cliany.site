# v0.16.394

Local CDP discovery now rejects malformed response shapes and invalid browser
WebSocket URLs. If a local port is occupied without a valid discovery response,
do not launch another browser. `doctor` reports `E_CDP_UNAVAILABLE` and suggests
checking whether another service holds the port instead of returning an
uncaught `E_UNKNOWN`.

## Evidence And Limits

The [failure record](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-27-local-cdp-discovery.md)
keeps the original fixture failure, scoped local controls and the separate
fixed387 maintainer first-use failure and retry. This guard does not establish
the cause of earlier intermittent Chrome startup timeouts, eliminate port races
or authenticate a valid-looking endpoint. Existing generated adapters are not
rewritten.

Independent first use remains pending on the fixed published 0.16.387 trial;
maintainer tests and assisted retries do not fill those slots. No candidate is
promoted and no alpha-readiness claim follows from this release.
