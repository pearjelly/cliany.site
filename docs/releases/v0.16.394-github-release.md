# v0.16.394

Local CDP discovery now rejects malformed response shapes and invalid browser
WebSocket URLs. If a local port is occupied without a valid discovery response,
do not launch another browser. `doctor` reports `E_CDP_UNAVAILABLE` and suggests
checking whether another service holds the port instead of returning an
uncaught `E_UNKNOWN`.

During Click command execution, cancellation returns `E_CANCELLED` with a nonempty message and a
safe reason. Direct keyboard interruption exits 130. EOF and explicit abort
exit 1; existing generated adapter wrappers preserve `E_CANCELLED` and stop
later actions but continue to exit 1. Optional healing does not run on a
cancellation. No generated adapter is rewritten.

Test-only pytest dependencies exclude9.2 after nine benchmark fixture errors
were reproduced with pytest-benchmark5.3.0. The same tests pass with9.1.1;
performance coverage and CI jobs remain enabled. Runtime bounds are unchanged.

## Evidence And Limits

The [failure record](https://github.com/pearjelly/cliany.site/blob/master/docs/user-evidence/2026-10-27-local-cdp-discovery.md)
keeps the original fixture failure, scoped local controls and the separate
fixed387 maintainer first-use failure and retry. This guard does not establish
the cause of earlier intermittent Chrome startup timeouts, eliminate port races
or authenticate a valid-looking endpoint. Existing generated adapters are not
rewritten.

Separate signal controls reproduced the empty error and the revised error, but
an earlier post-change control timed out without recording whether its signal
was delivered. Its cause and the earlier page-readiness warning remain open in
[Issue 116](https://github.com/pearjelly/cliany.site/issues/116); later passes
do not erase them.

Independent first use remains pending on the fixed published 0.16.387 trial;
maintainer tests and assisted retries do not fill those slots. No candidate is
promoted and no alpha-readiness claim follows from this release.
