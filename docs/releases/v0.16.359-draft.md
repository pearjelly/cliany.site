# v0.16.359 发布草案

**目标版本：** `0.16.359`
**提交范围：** `v0.16.359..HEAD`（升版后 target-mode readiness）

状态：发布候选；最终提交的测试与 CI 通过后才能创建标签。

## 用户价值

- 只配置另一家 provider 的 key 时，`doctor --llm-live --require-capability generate_adapters` 会在联网前返回 `E_LLM_DISABLED`，避免错误地放行探索。
- 真实 HTTP 401/403 现在返回不可重试的 `E_LLM_AUTH_FAILED`、安全提示与状态码，不再以 `E_UNKNOWN` 回显上游正文。
- 探索专属 OpenAI base URL 覆盖配置会被 doctor 一并校验，与实际模型客户端一致。

## 案例库映射

`cases/README.md` 与 `cases/manifest.json` 保持 2 active、3 candidate、2 degraded、1 known-gap；`search-extraction-gap` 未关闭。Jira active 案例可返回 5 条只读 issue，但三个 candidate 仍缺真实 adapter 包。当前 `llm_live_preflight_not_ready` 不因分类改善而消失。

## 风险与兼容性

- 当前 OpenAI-compatible 路径在 TLS 阶段断开，备用 Anthropic-compatible 路径返回 401；不能声称真实模型发现、候选晋级或 Jev 评测成功。
- 新错误码可能需要依赖 doctor 精确错误码的调用方识别。错误文本刻意不包含上游响应正文。
- 不修改旧生成 adapter、会话文件或案例状态。

## 发版前验证

- 定向 doctor 测试和真实 401 复验已完成；最终发布提交仍需完整离线测试、Ruff、Mypy、Node、案例校验与构建/Twine。
- 需等待最终 SHA 的普通 CI 与 Embodied CI，tagged readiness、Release workflow、GitHub Release/PyPI 和官网生产验收。

1. 核对版本、CHANGELOG、路线图、官网、锁文件与发布说明，运行严格 target readiness。
