# v0.16.351

## What Changed

- Direct Python SDK control options now reject malformed values with `E_INVALID_PARAM` before adapter lookup or browser work: `explore(force=...)`, `execute(..., params=..., dry_run=..., sandbox=...)`, and `list_adapters(detail=...)`.
- The synchronous `execute()` helper now supports `sandbox=True` and forwards the same local action preflight as the asynchronous SDK.

## Compatibility

Valid booleans, object `params`, and non-empty command names keep their existing behavior. Callers that previously relied on strings or numbers being truthy now receive a stable local error envelope.

## Trust Boundaries

This is a local SDK input-validation change. It does not establish Chrome availability, live LLM success, candidate adapter package availability, metadata validation, online smoke, or third-party workflow success.
