# v0.16.316

GitHub Release creation now uses these reviewed versioned notes from the tag itself, so the release body is ready before PyPI publication begins.

## Fixed

- The tag Release workflow checks out the tagged source and passes `docs/releases/vX.Y.Z-github-release.md` to `gh release create` with `--notes-file`.
- Strict release readiness now requires reviewed versioned notes, validates their `# vX.Y.Z` heading and user-facing content, and rejects `--generate-notes` in the workflow.

## Trust Boundaries

This improves release publication reliability only. It does not create candidate adapter packages, validate adapter metadata, run an online smoke, execute browser replay, or prove live LLM availability. The real 2026-08-12 provider preflight remained blocked by retryable `E_LLM_UNAVAILABLE`.
