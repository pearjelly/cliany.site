# v0.16.281 发布草案

**目标版本：** `0.16.281`
**提交范围：** `v0.16.280..HEAD`
**发布主题：** 让 candidate issue 审计的人工终端输出直接定位未知公开交接项。

完成 version bump 后，target-mode readiness 还会检查占位锚点 **提交范围：** `v0.16.281..HEAD`；该锚点不改变实际 release diff。

## 用户价值

v0.16.280 已将不属于当前 candidate manifest 的开放 `case-proposal` issue 作为 `unexpected` blocker 写入 JSON。维护者在常规终端中不使用 `--json` 时，却只看到 case id、状态和编号，还要再次查询 GitHub 才能知道该 blocker 的实际标题和链接。

本版让 `scripts/audit_candidate_issues.py` 的人工报告直接在 `unexpected` 行展示 actual title and URL。它保持默认只读，也不改变 JSON contract、body SHA-256、issue rewrite 条件或 candidate promotion 状态；维护者可以先定位公开协作项，再决定是否处理。

2026-07-27 的真实公开审计仍为 #14、#15、#16 三条 `current`，没有 `unexpected` issue。真实 live LLM preflight 仍返回 `E_LLM_UNAVAILABLE`，因此本版没有运行真实 explore、没有生成 adapter package、没有 metadata validation 或 online smoke，也不声称第三方站点或 live LLM 成功。

## 案例库映射

- `cases/manifest.json` 与 [cases/README.md](../../cases/README.md) 继续定义四个 active case、三个 candidate package-search case，以及已知缺口 `search-extraction-gap`。
- 该人工输出改进只帮助维护者处理 `case-proposal` 公共交接 blocker，不改变 case manifest、promotion evidence 或 candidate 状态。
- `llm_live_preflight_not_ready` 仍然约束 candidate 晋级：缺少真实 live preflight、adapter package、metadata validation 和 online smoke 证据时，案例保持 pending/blocked。

## 变更分组

### Unexpected issue handoff

- 人工报告的 `unexpected` 行追加实际 title 与 URL；`current`、`stale`、`missing` 与 `duplicate` 行继续保持紧凑格式。
- JSON 输出、`unexpected_issue_count` / `unexpected_issue_numbers`、`--apply --confirm-rewrite` 和没有 `missing`、`duplicate`、`unexpected` 才可重写 stale body 的门禁均保持不变。
- README、案例目录和官网文档说明 non-JSON 输出可直接定位 unexpected blocker。

## 风险与兼容性

- 脚本仍需要已认证的 GitHub CLI；离线 CI 只覆盖纯函数和 mock 的 GitHub 边界。
- 只有 `unexpected` 行增加人类可读文字，自动化应继续使用原有 JSON contract。
- 本版不会创建、关闭、重命名、重标记或晋级 issue，也不构成 adapter package、metadata validation、online smoke 或 live LLM 成功证据。

## 发版步骤

1. 完成版本、CHANGELOG、官网基线、reviewed GitHub Release Notes 和本草案，在干净 HEAD 运行 target-mode readiness。
2. 推送最终 `master` 后，等待 GitHub CI 与 Embodied CI 都成功；任一失败都不创建 tag。
3. 仅在 CI 成功后创建本地 `git tag v0.16.281`，运行 `uv run --extra dev --frozen python scripts/release_readiness.py --strict --release-tag v0.16.281 --remote --remote-name origin`。
4. 通过 tag gate 后推送 tag，等待 GitHub Release workflow，逐版本检查 GitHub Release 与 PyPI `0.16.281`。
5. 运行 `gh release edit v0.16.281 --repo pearjelly/cliany.site --notes-file docs/releases/v0.16.281-github-release.md`，再用 `gh release view v0.16.281 --repo pearjelly/cliany.site --json body` 检查 release notes。
6. 在 `site/` 运行 `vercel link --yes --project cliany.site`、`vercel --prod --yes` 与 `vercel inspect www.cliany.site --wait --timeout 90s`，然后浏览 www.cliany.site。
7. 运行 `uv run --extra dev --frozen python scripts/check_release_publication.py --strict --remote --distribution --json`；audit 成功后才报告完成。
