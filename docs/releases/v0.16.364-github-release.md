# v0.16.364

## Clearer Navigation Failures for CLI and SDK

Read-only replay of the published PyPI adapter exposed a browser navigation timeout. The `browser navigate` command now reports observed navigation timeouts as `E_PAGE_NOT_READY` with a site-access hint, rather than confusing them with a lost Chrome CDP connection. Python SDK `navigate()` applies the same distinction instead of returning a generic execution failure. Unrelated disconnects retain their existing errors.

Chrome `browser navigate` also checks the page AXTree before claiming success. In an isolated npm search check, Cloudflare served a verification page; both complete and partially loaded challenge trees now return `E_PAGE_NOT_READY`. Five subsequent headless retries reported that blocker, while a normal example page still navigated successfully. This does not establish npm search results or bypass the challenge. Providers without AXTree support retain their existing navigation behavior.

The PyPI adapter package installs and verifies from its public release asset, but the online search remains unverified: a run with a temporary system HOME timed out; with normal system HOME and isolated runtime data, a browser reached PyPI's `Client Challenge` page and the adapter returned `E_SELECTOR_NOT_FOUND`. The case stays `candidate`; this release does not bypass site controls or claim a successful search workflow.

Generated text-reading commands now accept nonempty text as data instead of requiring list rows. Exploration also detects when a read-only follow-up would lose earlier interactions because each command starts from the source URL; it asks the model to combine those steps and refuses to emit the broken split if repair fails. For local URLs with ports, `explore.data.command_group` identifies the name accepted by CLI execution and `verify`.

Generated commands now retain one auto-launched Chrome across their browser steps and close only that owned process afterward. An unchanged published PyPI adapter could then navigate, type, and click before PyPI's observed `Client Challenge` blocked extraction; the error was `E_PAGE_NOT_READY`, not a fabricated empty search result. Missing action targets on an observed challenge page also report page unreadiness rather than suggesting selector repair. The case remains `candidate`.

Cold-start readiness for auto-launched Chrome now waits up to 20 seconds, reports an early process exit immediately, and reaps a browser that never opens its CDP port. This improves startup reliability and failure diagnosis without disabling the browser sandbox.

In an isolated local-page run with a real model, the candidate produced one parameterized command and replayed `Ada:Blue` and `Grace:Red` successfully. After the browser-lifetime fix, that generated command independently returned both results through auto-launched headless Chrome too. Navigation timeouts in tests that replaced the system HOME were a confound. Neither result proves third-party site availability or Jev model accuracy.

A separate read-only probe of Apache Confluence's documented CQL search returned five results for the original `SPARK` / `release` query. The published adapter still filters exact titles, so this is a recovery lead, not a restored active case.
