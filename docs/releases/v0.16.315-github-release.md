# v0.16.315

Candidate issue handoffs now show the current doctor execution gate before any command that would require the gate to pass.

## Added

- `cliany-site cases --case-id <id> --issue-template --doctor-json <path>` now puts the current gate state, adapter-package runnable state, blocker reason, and next action at the top of Primary Evidence Task.
- `issue_template_primary_task` now exposes matching flat fields for automation consumers.
- The same output works when a strict doctor failure places diagnostic evidence in `error.details`.

## Trust Boundaries

This is a handoff and evidence-display improvement only. It does not create a candidate adapter package, validate metadata, run an online smoke, execute `explore`, or establish browser or live LLM readiness. The real 2026-08-12 preflight remained blocked by retryable `E_LLM_UNAVAILABLE`.
