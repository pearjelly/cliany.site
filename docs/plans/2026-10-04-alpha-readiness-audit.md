# Alpha readiness audit (2026-10-04)

**Verdict: not ready for a 1.0 alpha stability promise. Updated: 2026-10-09.** The published baseline is [v0.16.378](https://github.com/pearjelly/cliany.site/releases/tag/v0.16.378); its timing, production anchors and public-package checks passed. The v0.16.379 first-generation fix target requires separate final-commit and public-package gates. The [October value plan](2026-10-02-october-value-plan.md) still prioritizes an independently verified install-to-result path. [#33](https://github.com/pearjelly/cliany.site/issues/33) and [#55](https://github.com/pearjelly/cliany.site/issues/55) need users who did not build the adapters; maintainer trials and green CI do not substitute.

## Observable contract, not a stability guarantee

| Surface | Current observable behavior | Alpha commitment still needed |
| --- | --- | --- |
| CLI and JSON | Root options such as `--json`, `--headless`, `--cdp-url`, and `--sandbox` feed built-in and generated commands. The command envelope has `ok`, `version`, `command`, `data`, `error`, and `meta` ([envelope.py](../../src/cliany_site/envelope.py)); failures exit nonzero. v0.16.378 adds optional `duration_measured` and per-invocation timing; v0.16.377 durations remain unmeasured. | Decide and test the broader public versioned JSON commitments. SDK/HTTP still use `success`, `data`, `error` ([response.py](../../src/cliany_site/response.py)), so clients must not assume cross-entrypoint identity. Require an explicit timing flag and verify the published package, not an earlier PR's tests. |
| Generated adapters | The current metadata schema is v3 ([generator.py](../../src/cliany_site/codegen/generator.py), [schema_v3.py](../../src/cliany_site/codegen/schema_v3.py)); loader discovery excludes older schema by default and checks current adapters before import ([loader.py](../../src/cliany_site/loader.py)). Pinned marketplace archives can be installed and strictly verified before replay. | Publish a compatibility and migration policy. `migrate` updates old metadata and backs it up, but this alone does not prove an old generated command works with a new runtime. Test representative old archives across releases, or require regeneration with an explicit break notice. |
| Python SDK | `ClanySite` and synchronous helpers expose explore, execute, login, doctor, list, and verify paths ([sdk.py](../../src/cliany_site/sdk.py)); README has a minimal usage example. SDK methods return the older `success` envelope. | Define supported method signatures and error codes, then test parity for the first successful user flows. Do not promise that SDK, CLI, and HTTP return identical envelopes or that every generated adapter is portable across versions. |
| HTTP API | The local aiohttp server exposes `/health`, `/doctor`, `/adapters`, `/verify`, `/explore`, `/execute`, and `/login`, with explicit request validation and status mapping ([server.py](../../src/cliany_site/server.py)). `/health` is service liveness, not browser or provider readiness. | Treat this as an experimental local API until auth, versioning, and concurrency contracts are decided. The app registers routes without an authentication layer and defaults to loopback; do not expose it to an untrusted network merely by changing `--host`. |

## Command timing contract from v0.16.378

The implementation from [PR #73](https://github.com/pearjelly/cliany.site/pull/73) shipped in v0.16.378. [Issue #69](https://github.com/pearjelly/cliany.site/issues/69) completed publication and installed-package acceptance. Envelope version 1 and integer `duration_ms` remain, with optional `duration_measured`. Only `true` identifies a measured span; `false` is unavailable with a zero sentinel, and an absent historical flag is unverified. A measured submillisecond span can validly round down to zero.

The monotonic span starts on entry to `SafeGroup.main`, before argument parsing and dispatch, and is sampled when metadata is constructed. It is not process startup, output printing, post-envelope cleanup, CPU time or LLM-only time. Nested root calls have separate child spans while the parent includes child work; overlapping same-name calls do not share a command-keyed clock. Outside an active invocation, including an expired copied context, timing is unavailable. Newly generated adapter metadata uses the shared helper; old manually assembled metadata is not rewritten and may need regeneration. Direct generated Click groups that bypass `SafeGroup` are not promised measured timing.

The earlier isolated timing candidate passed 3,245 deterministic tests and exact-head ordinary/Chromium CI. The final v0.16.378 release repeated full checks and fresh public-package acceptance. SDK/HTTP top-level responses and doctor's separate per-check durations remain unchanged, with no new request-timing guarantee. The [exact contract and examples](../command-envelope-timing.md) support correctness only, not faster workflows, browser concurrency or independent first use; #69 records publication acceptance.

## Trust and runtime limits

- Static adapter checks, manifest hashes, source scanning, and optional sandbox preflight are useful local gates, not execution isolation or proof that a third-party page is safe. Keep pinned SHA-256 and `verify --strict` in the public install path. The sandbox rejects configured dangerous actions before browser work; it is not a general security boundary for arbitrary generated Python.
- Session storage encrypts cookies and restores them for a matching domain before navigation ([session.py](../../src/cliany_site/session.py)). Full localStorage restoration, cross-process session isolation, and arbitrary authenticated workflows have not been verified. Do not promise them.
- Browser execution and batch paths have some serial and two-request controls, but not a supported concurrent-browser contract. The [reliability acceptance plan](2026-09-22-reliability-acceptance.md) explicitly leaves target-tab routing, localStorage, parallel sessions, and cross-process isolation open.
- Obscura is an experimental provider path. A passing smoke test does not establish parity with Chrome/CDP for a public user workflow.

## Product evidence and blockers

The [October 9 returned-value review](../user-evidence/2026-10-09-returned-value-and-first-generation-review.md) adds a per-row-v2 public-baseline matrix and three fresh website generations. Historical studies below cannot be rescored under the stronger oracle. The fresh 9/9 matrix still contains a 264.62-second wait; six 100-row prefixes remain capped. #77's first-generation metadata fix has source evidence but requires its own published-package acceptance.

1. **Independent first result:** A public PyPI package and pinned read-only adapter assets have passed maintainer installs and browser replays, including the [Python docs candidate](../user-evidence/2026-10-03-python-docs-browser-candidate.md). No independent new user has completed the public quickstart or candidate trial. Keep the case labeled candidate and collect the first failure, elapsed time, strict verify result, and independently checked nonempty data via #33 and #55.
2. **Generated-command reliability and latency:** The [bounded-request policy](https://github.com/pearjelly/cliany.site/pull/67) is published in v0.16.377. Its [fixed-commit full controlled study](../user-evidence/2026-10-04-openai-request-budget.md) reached 29/30 with all 38 changed-input returned-value and independent DOM checks passing, but retained a 300-second timeout and 222.85-second p95. The [fresh integration review](../user-evidence/2026-10-08-request-budget-integration.md) passed 9/9 explorations and 12/12 replays after two preflight-only starts failed. The [published-package repeat](https://github.com/pearjelly/cliany.site/pull/67#issuecomment-6051817216) checked client configuration, Jira install/reuse and a new Python docs browser workflow. [#30](https://github.com/pearjelly/cliany.site/issues/30#issuecomment-6051907127) is complete for its controlled measurement scope; [#38](https://github.com/pearjelly/cliany.site/issues/38) remains open for broader provider/public-site tail and availability evidence. The network-operation timeout is not an end-to-end deadline; these maintainer samples do not establish a population success rate or causal latency gain.
3. **Public browser case:** Python docs search has a distributed candidate archive and changed-query maintainer checks, but extraction caps at 100 rows while the site can report more. The cap is explicitly marked; a correct prefix is not complete collection. Its synthetic-HOME macOS navigation failure is narrowed to Chrome's launch environment on one host ([#53](https://github.com/pearjelly/cliany.site/issues/53)), not proven to be a cliany defect or resolved for new accounts.
4. **Contract decision:** Before using an alpha label, choose the broader CLI/SDK/HTTP envelope and error-code commitments, retain the publication evidence for #69's duration semantics, specify adapter v3 migration and support policy, and document the local-only HTTP security boundary. Then test those promises against the independent first-user path rather than only fixture CI.

The next audit should follow the first independent attempt or a change to one of these contracts. Until then, continue verified patch releases without implying 1.0 alpha readiness or broad third-party site reliability.
