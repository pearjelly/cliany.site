## Correction Boundary

An extract's purpose is declared before execution and frozen in its recorded
ActionStep. Default `workflow` is a business read. `probe` is an exploratory
structure/field read, preserved with every original action index and raw extraction
evidence but never owned by a replay command. `baseline` is returned business data
only when the user explicitly requests independent fixed data or comparison. It
does not authorize turning a single-search task into a comparison to bypass checks.
No final command, partition repair or canonical-action declaration can rewrite a
recorded purpose. Existing unmarked histories keep their original meaning.

Commands must cover every non-probe original index exactly once. Generation also
rejects exported probes. A parameterized business extract must follow an actual
executable parameter effect in replay order, unless predeclared baseline. This is
a necessary temporal condition, not proof of causal/task correctness. Auto-detected
value parameters use the same rule; unparameterized and valid multi-input/multiple
collection workflows remain supported. Runtime outputs are not filtered. A raw
unmarked fixed read before later input fails; it is not retrospectively relabeled.

Saved metadata retains complete probe-bearing exploration histories separately
from business command actions. Merge appends histories without rebasing them;
business argument indices are rebased only from a complete unique original mapping.
Baseline purpose survives save/merge. Atom extraction excludes probe inputs and
refuses returned probe actions. A probe may be followed by a real business read;
repeated probes and existing duplicate business reads retain their refusal.
No CSS fallback, generated-file patch, archive change, model/action/navigation
retry increase, step-budget increase or case promotion is introduced.
