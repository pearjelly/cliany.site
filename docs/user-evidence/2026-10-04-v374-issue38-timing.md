# Controlled LLM timing sample on published v0.16.374

On 2026-10-04, the opt-in live benchmark ran on clean master commit `584edbbdd24b9745a7a21f619ac298e936f83bba`, package `0.16.374`. Three fresh trials each covered the form, filter, and semantic-reorder tasks. The configured explore model was `deepseek-v4.1-flash` through an OpenAI-compatible custom endpoint. The source report did not yet classify the provider or endpoint; the configuration was checked separately without recording its URL or key. The report stayed under `/tmp`, outside the repository.

All **9/9** trials passed the generated-command contract and returned-value plus independent DOM oracle. All **12/12** changed-input replays had `output_ok=true` and `oracle_ok=true`; no command-partition repair occurred. The live preflight passed in 3.45 seconds. Exploration durations, sorted, were 7.81, 8.05, 8.23, 9.15, 9.15, 14.22, 16.76, 16.99, and 18.37 seconds: median 9.15 seconds and nearest-rank p95 18.37 seconds. The progress events recorded 12 LLM attempts, all successful on the first try, with zero retries and zero scheduled backoff; individual attempt durations ranged from 4.10 to 12.14 seconds.

This small controlled sample did not reproduce the earlier long exploration tail. It does not show that the tail is fixed, establish a population success rate, or cover a public third-party exploration. Earlier samples used different fixed commits and provider conditions, so their timing cannot be attributed to one code change. The next latency study should preserve the same output-plus-DOM gate while predeclaring provider/model/endpoint class, cross-task count, and a legitimate public-site flow; a timeout must remain in the denominator.

A separate 1-trial-per-task live smoke on this documentation/runner-change worktree validated the new privacy-safe report fields: `provider=openai`, `endpoint_type=custom`, with no URL present in the report. It passed 3/3, but the preflight took 78.56 seconds and explorations took 31.08, 36.13, and 8.96 seconds. Its four LLM attempts all succeeded without retry or scheduled backoff; the slowest individual attempt took 27.21 seconds. This is not a clean-commit reliability sample and is excluded from the 9/9 summary above. It demonstrates that long waits can occur inside one successful provider call, not only in retry/backoff, but does not establish their frequency or cause.
