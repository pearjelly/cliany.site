## Public Evidence And Failed Probes

A non-editable official Python 3.11 install passed strict real doctor in 6.66 seconds. Three fresh public Python documentation CLI generations completed in 25.00, 42.56 and 35.56 seconds. All seven observed model attempts succeeded without outer retries. Generation success alone does not establish replay success.

The initial nine replay probes queried the launching Playwright pipe's context list, which did not enumerate targets created through the application's separate CDP connection. An explicit-CDP control observed a real pathlib search page and 100 returned rows while the launching pipe observed zero pages. A second fresh-browser review retained the same observation error. Neither report is rescored as end-to-end acceptance.

A corrected explicit-CDP review of the three unchanged adapters passed **7/9**: four positive 100-row prefix checks and three zero-match checks, with independent completed pages containing 134 pathlib and 403 asyncio results. Two actual SDK `EXECUTION_FAILED` responses remain unresolved; their observed query fields were blank despite query URLs. No passing rerun replaces those failures. Zero-match acceptance follows each command's recorded `expects_nonempty`, which differed between adapters.

## Responsive Failure

Four independent width/context controls used one unchanged public-generated adapter. At 800 pixels it returned a nonempty result in default and isolated contexts. At 1280 pixels both contexts failed: the actual AX map contained two `Quick search` searchboxes, each with replay score 125. Both had navigation ancestors named `Related`; named-ancestor metadata alone is therefore not a demonstrated fix. Runtime correctly refuses the equal-score ambiguity. No CSS fallback, arbitrary ref preference or old-file rewrite is permitted.

Generation uses raw observed refs to execute plans, then records role/name/attributes for later replay. That permits a currently duplicated target to be executed even though the resulting semantic identity cannot be replayed uniquely. On release source, the new local Chromium regression wrote `DO-NOT-WRITE` into one of two identical fields before the next planning request. Three deterministic regressions failed; the distinct-observed-attribute control passed.

## Source Correction

Before recording or executing an interactive plan, the source candidate applies the existing runtime semantic ranking. It permits one planning correction within the original maximum steps. Rejected actions do not mutate fields, enter action history or consume command action indices. If the user has not required a particular widget, an observed unique link can lead to a separate form; the planner cannot invent URLs or disregard an explicit widget requirement. Persistent ambiguity fails closed. Existing runtime tie refusal and generated files are unchanged.

Four deterministic tests pass, including repeated ambiguity, exhausted step budget and distinct-attribute preservation. The real Chromium test passes: the rejected fields remain empty, a unique `Full Search` link is used, recorded action ownership remains valid, and generated/static-verified SDK replay returns Grace with an independent DOM check. Full unversioned-source offline regression passed **3,505 tests in 322.27 seconds**; Ruff and Mypy (125 source files) passed. These do not replace exact-head CI or final publication gates.

This changed task and viewport is not a causal comparison to the public baseline. The source produced **2/3** complete generations in 33.60 and 53.02 seconds; their six changed-input SDK/independent-browser checks passed. Every returned title/link matched the independent 100-row prefix; correct prefixes are still capped collection.

The second source trial exercised the bounded repair: four successful model attempts correspond to three recorded steps numbered 1, 2 and 3, with rejected step 0 absent. The recorded valid route begins at the observed Search page link; the failed target is not substituted into the adapter. All ten recorded source-model attempts succeeded without outer retry, so neither provider availability nor faster generation is established by this small sample.

The third generation failed after 41.31 seconds with `extract_selector_ungrounded`, exposed as CLI `E_UNKNOWN`. Its last completed snapshot already listed the observed `#search-results li` candidate. The failed turn's model plan was not recorded, so the exact selector and cause cannot be asserted from these artifacts. Do not attribute the failure to the provider or page timing without stronger evidence, relax grounding, or claim 3/3 success.
