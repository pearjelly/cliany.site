# Python docs browser candidate (2026-10-03)

This is one maintainer-run, read-only third-party browser trial on draft PR #47, not a published case or independent-user result. The starting page was `https://docs.python.org/3/`. A fresh browser showed the normal Python documentation and a working Quick search form without login or a challenge.

With an isolated runtime directory (`/tmp/cliany-public-python-20261003-1`), headless Chrome, and the live provider, `explore` searched for `asyncio` and generated one `search-docs --query` command in about 52 seconds. `verify docs.python.org --strict --json` returned `verdict=ok`; its report also noted that no market manifest exists. Replaying the generated command with changed input `pathlib` returned `ok=true`, an `ok` list extraction with 100 rows, and first row `title=pathlib`, `url=library/pathlib.html#module-pathlib`. An independent browser submitted `pathlib` through the site's own Quick search form and showed the same first result title and relative link. The page reported 131 matching pages, so this check does not establish complete collection of all results.

Two limitations block promotion. The generated extract action used `#search-results li` with `a` and `a@href` fields, but the saved selector pool was empty; this trial has not shown an AXTree-grounded semantic extract target. It also comprises only one fresh exploration, not the three required by the October plan. Do not publish the adapter or count this as a maintained browser case yet.

The trial exposed an isolation defect: exploration saved its Markdown extract under the user's normal `~/.cliany-site/adapters/docs.python.org/extracts/` despite the isolated runtime directory. The exact file created by this run was removed; two older files in that directory were left untouched. A focused test reproduced the defect, and the writer now uses the configured `adapters_dir` for its default path. The fix passed 3196 offline tests, 28 embodied tests, Ruff, and mypy. A direct save using an overridden runtime home wrote only under `/tmp/cliany-public-python-20261003-2/adapters/docs.python.org/extracts/`.

A second fresh, isolated live exploration searched for `pathlib`. It completed the search and extraction steps, but the third model call remained in flight beyond about five minutes. The run was interrupted and returned `E_UNKNOWN`; Chrome exited and the user's normal extract directory gained no new file. Because exploration never reached its final save, this is a failed trial, not live confirmation of the path fix or a second successful browser case. No retry was run to replace it.
