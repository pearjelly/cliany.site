## Captured Document Initialization Race

Two further predeclared, read-only three-replay diagnostic cohorts each retained one CLI success and two failures, reusing the unchanged second source adapter. Actual type-event readback and the live field both contained the entire requested word immediately after typing. In the failed boundary cohort, a subsequent snapshot observed the field empty before submission, or submission produced `q=` while the document was still interactive. The lifecycle cohort additionally captured `domContentLoadedEventStart=0` and `domContentLoadedEventEnd=0` immediately after successful typing in both failures. Its passing trial had completed that event before typing. These are separate captured failures, not a reconstructed cause for the original untraced failed turns.

The site's actually loaded [searchtools.js](https://docs.python.org/3/_static/searchtools.js) registers `Search.init` through `_ready`; it assigns query input values from the current URL. The loaded [doctools.js](https://docs.python.org/3/_static/doctools.js?v=9bcbadda) registers that callback on DOMContentLoaded while loading. A deferred search-index script can leave a visible, interactive form before those callbacks run. The observed source SHA-256 values are `371b49c7f094b525244e2a59d7809a6b946fc1c8791201d10dda1dd191133bb7` and `2992c09df91826a8d33e3b48b645ee77e457adcf7c712d776a814e1e2c448b43`, respectively. No vendor script is modified or copied into the package.

A new native generated-adapter fixture reproduces the loss: an inline DOMContentLoaded initializer resets the visible field after a delayed deferred script. Before this correction, the controlled run retained **1 failed / 1 passed in 14.80 seconds**. The failed page recorded the full requested word as its reset value, an empty actual submitted query and exactly one submission. Raw CLI and independently observed DOM JSON are preserved outside the repository. A separate slow-image control already passed, so waiting for all page resources is not justified.

Named typing now observes document initialization within the same ten-second target budget, then recaptures semantic references before dispatch. `interactive` is sufficient once NavigationTiming reports a positive DOMContentLoaded end; `complete` also qualifies. A stalled or late initialization probe fails with `E_PAGE_NOT_READY / document_not_ready` before typing. Explicit refs keep their existing one-snapshot behavior. No input/submission retry or missing-list acceptance is added. This scope does not promise arbitrary post-DOMContentLoaded SPA hydration readiness.

The correction passed 74 focused unit/action/extraction controls in 11.74 seconds, including strict structured readiness parsing, changed refs, late results, cancellation and explicit-ref behavior. An initial native run passed all four initialization/delayed-target cases in 39.16 seconds; the reviewed run with unchanged-core hashes passed all four in 36.13 seconds. These include exactly one submission and success before a slow image completes. Ruff passed and Mypy passed all 126 source files. Final clean-source regression and a new real study still remain required. Keep PR 101 in draft, with no version increment, merge, tag or new release until those and all release gates pass.

Version preparation separately retained a 35-failure / 610-pass documentation-gate run, then a 1-failure / 649-pass recheck. These assertions still pinned the moving Unreleased compare range and website cache marker to v0.16.389; the second failure was a split literal missed by the first mechanical update. Strict target readiness on first version commit `2ac8ea72f7bfa6cc23befdf3422830bb09a53e33` failed the required release-draft sections and current source-roadmap version markers. Its full run was deliberately interrupted after 45 passes / 74.24 seconds for document correction; it is not a completed full-regression pass. On that earlier version commit, separate fresh Jenkins/Jira/Confluence first-install, strict verification and reused-query checks all passed with unchanged generated core (5/5, 5/5 and 6/6 rows respectively). These API maintainer checks do not establish independent users or final revised-head acceptance. Final-version full acceptance remains pending.

- Named `browser type` targets may appear during up to ten seconds of read-only AX/node/document-initialization observation, before any input event is dispatched. References are refreshed after initialization. Equal highest semantic scores fail without changing either field; observed challenges stop immediately. Explicit refs still use one snapshot and are not retargeted later. Typing/clear/Enter behavior stays outside the observation loop and is not retried.
- List/table and status-text semantic extraction uses one existing ten-second readiness budget for initial semantic identity, settling and recapture. It does not repeatedly reset the budget. Late results cannot become success, permanent missing/ambiguous targets remain errors, and external cancellation propagates. Other text/attribute resolution policy is unchanged.
- These are cooperative observation budgets, not entire CLI/workflow deadlines. CDP acquisition, dispatched action handlers, model calls and the rest of the command are not given a new global deadline. Other interactive atoms and the SDK's separate interactive action resolver are not claimed to share the new named-type waiting policy.
- No guessed CSS fallback, navigation/action/model retry, generated-file rewrite, archive change or case promotion is introduced. Model request limits are unchanged; the list readiness budget remains ten seconds but now covers all preparation phases instead of restarting between them. Semantic identity, unique live DOM region, quality checks and the 100-row cap remain required.
