## Preserved Public Failure

A non-editable official PyPI 0.16.389 installation passed real strict generation-capability doctor in 3.69 seconds. Exactly three fresh 1280-pixel Python documentation generations took 89.06, 43.24 and 30.30 seconds. All three verified strictly before/after replay, but complete workflows passed only **1/3** and changed-query replays **6/9**. Three positive replays failed closed with `E_SELECTOR_NOT_FOUND / extract_target_unresolved`. Their failed-turn AX snapshots were not captured, so the exact cause remains unknown.

The three successful positive outputs matched every ordered title/link in independent completed 100-row prefixes; the normal pages contained 134 pathlib and 403 asyncio rows. Three legitimate zero matches agreed with an independent normal page. Capped prefixes are not complete collection. All ten recorded exploration model attempts succeeded without outer retries; that does not explain the browser failures. The original local report SHA-256 is `28ea0e3c4f9d321b8068abc710ab7a288a25ff324c5430d40eca3740e9f65115`.

The separate controlled three-task sample passed 9/9 explorations and 12/12 output/DOM replays, retaining a 120.06-second exploration and 91.60-second single model wait. One form trial recorded a command-partition repair. This is a different sample, not a substitute for failed public acceptance or evidence that tail latency is fixed. [Issue 38](https://github.com/pearjelly/cliany.site/issues/38#issuecomment-6221970653) retains its timings and limits.

An initial follow-up lost diagnostic stderr to nested `CliRunner`; its three CLI-success observations cannot establish candidate traces. A private-file trace cohort observed three CLI successes. A further predeclared six-observation cohort recorded five CLI successes and one distinct failure at `browser type`, before extraction: the Search textbox was not found and the URL still lacked a query. In three CLI-success observations, the result-list AX candidate was absent at first and present later. Those diagnostics did not independently grade every returned row and do not rescore the original failures or prove their missing failed-turn causes.

## Controlled Native Reproductions

Two native Chromium fixtures generate an adapter from actually observed semantic identity, then replay a changed query. One delays the named Search textbox by four seconds after opening the form; the other delays the named result list by four seconds after submission. The observer uses explicit CDP and the replay page's phase marker, not the launching pipe's page list or an earlier page with the same URL. Generated core hashes remain unchanged.

Both fixtures fail against official PyPI 0.16.389: the first exits at `browser type` with `E_SELECTOR_NOT_FOUND`; the second completes navigation/input/submission but exits at extraction with `extract_target_unresolved`. The later expected field/list is actually present. A first red run failed two tests in 20.51 seconds; after strengthening page selection and retaining full JSON envelopes, a separate red run failed both in 15.18 seconds. Those failures remain local evidence, not corrected scores. These controlled defects have corresponding public error signatures but are not claimed as the original public attempts' exact causes.

Fifteen deterministic controls initially produced ten failures and five passes. They cover delayed semantic identity, bounded/stalled/late probes, shared extraction budget, explicit-ref stability, equal-score refusal, challenge handling and external cancellation. The first correction passed 57 related controls and both native fixtures. Its first complete unversioned regression passed **3,715 tests in 445.29 seconds**; Ruff and Mypy (126 source files) passed. That run predates the additional late-page guard and two boundary tests below, so it is not final-source or release acceptance.

A later boundary test proved a page lookup could return after cancellation and still start a new settle probe. Its companion confirmed an already-late type node cannot dispatch an event. The two-test red run retained the late-page failure separately; the correction checks the deadline before starting that probe. Native replay additionally checks exactly one actual form submission, not just the final field value. Final-source testing and real source workflow evidence remain pending.

## Correction Boundary

- Named `browser type` targets may appear during up to ten seconds of read-only AX/node observation, before any input event is dispatched. Equal highest semantic scores fail without changing either field; observed challenges stop immediately. Explicit refs still use one snapshot and are not retargeted later. Typing/clear/Enter behavior stays outside the observation loop and is not retried.
- List/table and status-text semantic extraction uses one existing ten-second readiness budget for initial semantic identity, settling and recapture. It does not repeatedly reset the budget. Late results cannot become success, permanent missing/ambiguous targets remain errors, and external cancellation propagates. Other text/attribute resolution policy is unchanged.
- These are cooperative observation budgets, not entire CLI/workflow deadlines. CDP acquisition, dispatched action handlers, model calls and the rest of the command are not given a new global deadline. Other interactive atoms and the SDK's separate interactive action resolver are not claimed to share the new named-type waiting policy.
- No guessed CSS fallback, navigation/action/model retry, generated-file rewrite, archive change or case promotion is introduced. Model request limits are unchanged; the list readiness budget remains ten seconds but now covers all preparation phases instead of restarting between them. Semantic identity, unique live DOM region, quality checks and the 100-row cap remain required.
