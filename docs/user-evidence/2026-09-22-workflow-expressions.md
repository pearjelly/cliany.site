# 工作流数组引用与条件失败边界

日期：2026-09-22。状态：Unreleased；公开版本仍为 v0.16.356。

## 复现

新增 11 项回归在旧代码上全部失败。README 的 `$prev.data.results[0].name` 被部分替换成 `"[{'name': 'actual'}][0].name"`，而非实际字段。无法解析或无法转为数字的条件默认执行，缺失字段与 true 比较不等时也会放行动作。

## 修复

- 变量路径支持非负、零起始数组下标、嵌套数组及命名步骤结果；按字典/列表结构访问，不执行表达式代码。
- when 使用单个比较运算符和标量比较值。YAML 校验及直接运行 WorkflowDef 都在派发任何步骤前检查全部条件语法。
- 运行时条件字段缺失、下标越界、路径类型不匹配或无法数值比较时，步骤明确失败、attempts=0，不重试也不执行该步骤。
- 显式 null 和原有合法比较保持可用；普通参数的缺失值仍按兼容规则转换为空字符串。
- 负下标、非数字下标和未闭合下标不会生成部分替换的参数；工作流/批处理会记录失败，不派发该项。

测试覆盖实际工作流中前一步返回对象数组、后一步收到精确字段值，以及语法错误时零调用、运行时条件错误时仅前一步被调用。此处是确定性的编排层测试，不是新增公网或 LLM 成功证据。

最终完整离线测试 2859 项通过（6 项既有警告）；Ruff 与 Mypy（123 个源文件）通过。
